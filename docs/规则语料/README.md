## 1. 为什么是仿真语料

| 原因 | 说明 |
|---|---|
| **真实文档拿不到** | 实测仓库一篇规则文档都没有（P-07）。而文档检索通道、D1 切分、混合检索、Rerank、Golden Set L2 层**全部依赖语料**，无语料则第 2 周无法开工 |
| **口径一致性** | 业务数据本就是仿真的（C-13 时间窗 / C-14 规模）。若语料为真实文件、数据为仿真，则两者在**费率、货类、闸室参数**上必然互相矛盾，评测结论失去意义 |
| **可控的评测区分度** | 可**刻意**放入「已废止版本」「相似但相互冲突的条款」「易混淆专有名词」，构造检索难度梯度。这是真实文档难以提供的 |
| **无版权与保密风险** | 自建内容可公开入库，符合 C-07 的入库边界 |

⚠️ **对外表达限制**：README、简历、演示中**不得**称本语料为"真实法规"或"平陆运河官方规范"。
引用本项目检索指标时，必须同时说明语料为仿真。

### 4.1 ★ 货种归类权威表（**以 `generate_seed_data.py` 的 `CARGO_TYPES` 为准**）

⚠️ **语料与仿真数据必须对同一货种给出同一归类**，否则「文档检索通道」与「结构化查询通道」
会对同一个问题给出不同答案。**权威来源是数据库侧的种子数据**：

依据：`backend/scripts/generate_seed_data.py` 第 **150–170 行**（`CARGO_TYPES`）

| 货类大类 | 种子数据中的货种（逐字） |
|---|---|
| 建材 | 机制砂、碎石、水泥、水泥熟料、混凝土预制件 |
| 能源 | 动力煤、焦炭、成品油 |
| 金属 | 铁矿石、铝土矿、**钢材**、锰矿 |
| 农资 | 化肥、粮食、食糖 |
| 化工 | 烧碱、硫酸、液体化工品 |
| 集装箱 | 集装箱货物 |
| 其他 | 机械设备、日用百货 |

**易错点（已实际踩到并修复）**：

- ⛔ **`钢材` 属 `金属`，不属 `建材`**。2026-09-21 语料初稿曾把「钢材制品」列在 `建材` 举例中，
  与种子数据 `JS03 钢材 → 金属` 冲突，已在 `05` / `12` / `25` 三篇统一更正为 `金属`。
- 粮食 → `农资`；铁矿石/铝土矿/锰矿 → `金属`（不得写作"矿石"大类）。
- 危险货物**不是货类大类**，按物理化学性质归入 7 类之一。

⚠️ **写费率表时的三条铁律**：

1. **不得发明第六个费种**，也不得把「过闸费」写成「船闸费」等变体。
2. **不得发明第八个货类**（如「粮食」「矿石」「危险品」）。粮食类须归入 `农资`，矿石与钢材须归入 `金属`。
3. **吨位区间左闭右开**（`[min_ton, max_ton)`），且**同一费种+货类下区间不得重叠**。

### 4.2 ⚠️ 「水深」与「水位」的区别（常见质疑，**已判定为有意保留**）

复核 `03` 篇时会看到「允许最大吃水 4.20 米」「闸室水位」「富余水深 0.30 米」等表述，
而本项目 `lock` 表**没有水深字段**——两者看似矛盾。**结论：不矛盾，属有意保留。**

| 概念 | 是否存在于本项目数据 | 说明 |
|---|---|---|
| **闸室水深**（结构尺寸） | ⛔ **不存在** | `lock` 表只有闸室长宽与设计吨级，**无水深刻度** |
| **运行水位**（动态条件） | ✅ **合理存在** | 由调度机构**过闸当日核定**，随充泄水与上游来水变化 |
| **允许最大吃水**（运行限值） | ✅ **合理存在** | 依**当日核定水位**确定并可下调，**不是**固定结构尺寸 |
| **富余水深**（操作余量） | ✅ **合理存在** | 船舶吃水与当日可航水深之间的安全余量，属操作要求 |

`03` 篇**第六条**已明确写出：*"闸室水位随充泄水过程与上游来水条件变化，本标准**不规定固定的闸室水深刻度**"*，
并在同条声明水位变化**不影响**闸室有效长宽。因此 `03` 与「无水深数据」是**一致**的。

⚠️ **但不得越界**：语料中**不得出现"闸室水深为 X 米""水深限值 X 米"这类给定结构数值的写法**——
那才会与数据库矛盾。校验脚本 `validate_corpus.py` 已按此边界设规则：
匹配"给定具体水深数值"即报错，「富余水深」等操作余量放行（>1.0 米才告警）。

| 类型 | 具体设计 | 用途 |

| 2 | 费率命中正确性 | 全量 109,418 条费用明细按语料口径重做匹配，断言命中的正是库里那条规则 |

| 4 | 覆盖与未实现清单 | 哪些档位无数据触发（**18 / 71**）、语料中哪些条款不可实现（**6 项**，逐条附原因）|
| 5 | **自证** | `--selftest` 故意改坏一条费率，断言检查**确实报错**后回滚复核 |

**改语料或改生成器后，这两个脚本都要跑**（`validate_corpus.py` + `verify_corpus_db_rates.py`）。

## 6. 维护约定

- 本目录为**语料源**，**只增不删**。已废止版本（如 `06`）**必须保留**，它是评测资产的一部分，不得因"过时"而删除。
- 费率或结构改动**必须同步** `docs/规则语料/README.md` §4 与 `docs/DECISIONS.md`。
- 任何语料改动都会改变检索基线，**须重跑 L2 评测**并在《评测报告》中记录版本变更。
  ⚠️ `chunk_id` 是**位置哈希**（`ChunkStructureSplitter.stableId` 不含内容哈希），
  故改条款**文字**不会让 `goldChunkIds` 失效，但**向量与基线数字要重跑**。
- ★ **本目录的费率表是数据库 `tariff_rule` 的唯一事实来源（决策 C-31，2026-09-22）**：
  改这里的费率表 **= 改库**，必须按顺序做三件事，缺一不可：
  1. `python backend\scripts\generate_seed_data.py`（由语料重新生成种子数据）
  2. 重灌数据库（`setup_local_db.ps1 -Recreate` 或 `psql -f backend\scripts\seed_output\load_seed.sql`）
  3. `python backend\scripts\verify_corpus_db_rates.py --selftest`（逐格复核，必须 PASS）

  > 反向不成立：**不得**为了迁就数据库而改语料费率 —— 数据库是派生数据。
  > 详见 §5.2 与[费率口径跨来源漂移](../工程复盘/数据一致性/费率口径跨来源漂移.md)。
