## 1. 范围：本项交付什么、不交付什么

**交付**：一条**可独立评测**的 BM25 检索通道——中文分词（含自建航运词典）→ 词元落库 →
`rag_bm25_search()` 在库内打分 → 可带过滤条件（文档/类别/块类型/生效时点）取 Top-K。

**不交付（重要，别对外说成"已启用混合检索"）**：

- **本通道目前不在任何链路里**：没有 RRF 融合、没有权重、没有接进问答。
- **"是否并入最终链路"是待决决策 D3**，由**第 4 周消融实验**回答。
  知识库（`RAG 优化` 第 125 行）明写：文档高度结构化、查询不含关键词时混合检索**增益不明显**——
  故增益必须由本项目自己的消融数据回答，**本报告不预设结论**。
- **本报告不是"召回率报告"**：Golden Set 的 L2 层（40 条）尚未建（第 2 周第 7 项），
  所以本报告只提供**通道可用性 + 一致性 + 定性观察**，**没有 Context Recall / Precision 指标**。
  §7 的检索质量观察是**人工判读 + 机制核查**，明确标注为"待 Golden Set 验证的疑点"。

## 2. 口径（写进 SQL 与档案的那一套）

**打分公式**（Lucene 形式，`idf` **恒为正**，不会出现经典 BM25 的负值问题）：

```
idf(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
score  = Σ_t idf(t) · (tf · (k1 + 1)) / (tf + k1 · (1 - b + b · dl / avgdl))
```

- `N` = 语料 chunk 数、`avgdl` = 平均词元数、`dl` = 本块词元数，**均为语料全局量**。
- **唯一实现**在 PostgreSQL 函数 `rag_bm25_search()` 里；`k1`/`b` 从档案表读，不硬编码。
- **检索文本只用 `content`**（与向量通道**同一份输入**），标题/章节路径**不进**检索文本。
  理由：第 4 周做 RRF 消融时，差异只能归因到"通道"，而非"输入不同"。
  ⚠️ 这个选择有代价，§7 现象 C 给出了**它的直接证据**。
- 过滤条件与打分**在同一条 SQL 里**（不存在"先近似取 Top-N 再过滤"的静默少返回问题，
  与向量通道 V3 的坑不同，见 `docs/工程复盘/检索工程/HNSW索引过滤条件静默少返回.md`）。

## 5. 独立复核：Python 重算 BM25 与库内结果逐条比对

**做法**：`backend/scripts/verify_bm25.py` **不调用任何 SQL 打分函数**，
只从 `rag_chunk_term` / `rag_chunk_token_stat` 读出词元与长度，**用 Python 自己算一遍 BM25**，
再与 `rag_bm25_search()` 的输出逐条比对。两套独立实现算出同一个答案，才叫"验证过"。

**结果（6 条探针）**：

| 排名次序不一致 | **0** |

| **分数最大绝对差** | **3.55e-15**（容差 1e-9；差异来自两套实现的累加顺序） |
| 不变式违例 | 0 |

| 结论 | **`[PASS] BM25 通道通过独立复核`**，退出码 0 |

| # | 查询 | 词元数 | 其中 `df = 0` 的词元 | Top-1 分数 |

| 1 | 过闸费的计费单位是什么 | 6 | `什么` | 12.784017 |

## 7. 检索质量观察（⚠️ 人工判读 + 机制核查，**待 L2 Golden Set 验证**）

> **没有 Golden Set，就不能算指标**。下面是把 6 条探针的 Top-5 逐条读出来后的**观察**，
> 每条都附**可复现的机制核查**（SQL 证据），而不是"我觉得排得不对"。
> 这些观察的作用是**给第 4 周定消融假设**，不是结论。

### 现象 A｜精确数值 / 表格类查询：BM25 优势明显（正面证据）

探针 3「船舶总吨位 3000 吨需要几根系泊缆」：

| 排名 | 分数 | 文档 / 条款 | 命中词数 |
|---|---|---|---|
| **1** | **30.037471** | 19-码头靠离泊作业规程 **第十三条【系泊缆配备数量】** | 8 |
| 2 | 18.085068 | 19 第十条【拖轮配备数量】 | 6 |

**Top-1 与 Top-2 相差 66%**，且 Top-1 正是**题面要的那一条**。
机制：查询里的 `3000`、`吨`、`系泊`、`缆` 在目标条款里**字面同时出现**——
这是"精确匹配"型问题，正是 BM25 相对稠密向量的长板。第 4 周消融应把
"数值/表格类问题"单独分层看，**预期 BM25 在此分层贡献最大**。

### 现象 B｜12 个条款分数完全并列，把真正的答案条款挤出 Top-5（**最值得注意的一条**）

探针 1「过闸费的计费单位是什么」的 Top-8：

| 排名 | 分数 | 文档 / 条款 |
|---|---|---|
| 1 | 12.784017 | 06-过闸费费率表（2026版）**第一条【目的与依据】** |
| 2–5 | **12.520430（完全相同）** | 06/07 费率表的**各货类费率条款**（农资/建材/能源/化工/金属…） |
| 6–8 | 12.520430（还是同一个分数） | 同上，继续 |

- **实测：分数 `12.520430` 上并列了 12 个 chunk**（都是"一货类一条"的费率条款，`dl` 全为 47、
  词元构成几乎相同），**谁进 Top-K 完全由 `chunk_id` 的排序决定**——与相关性无关。
- **真正回答这个问题的条款排在很后面**：

| 排名 | 分数 | 条款 | 与并列簇的差距 |
|---|---|---|---|
| 14 | 12.505320 | 25-术语与定义 **第二十七条【计费单位】** | 仅低 **0.12%** |
| 18 | 10.638692 | 06-费率表 **第三条【计费单位与吨位分段】** | 低 15% |

- Top-1 的正文实测是：*"为规范平陆运河船舶过闸费的计收，**明确过闸费的计费单位**、计费吨位与
  各货类、各吨位段的费率标准，制定本费率表。"*——**它只是提到了这个术语，并没有回答它**。
  即：**样板条款（"目的与依据"）靠关键词重复取胜**。

**这段是"为什么必须有 rerank（D4）"最硬的本地证据**：BM25 的分数差小到 0.12% 时，
排序实际上退化成"按 id 排"。第 4 周消融应加一条假设：
**"BM25 召回 + 专用 Reranker"在"术语定义/规则解释类"分层上的增益**，
而不是笼统地说"混合检索更好"。

### 现象 C｜文号检索命中的是"引用者"，不是文档本体（**检索文本选择的直接代价**）

探针 4「PLYH-GZ-2026-001 规定了什么」：Top-5 里出现的都是**别的文档的第一条**。机制核查：

```sql
-- 含该文号的 chunk 只有 4 个，全部是别的文档在"引用"它
SELECT doc_id, article_no, article_title FROM rag_chunk
 WHERE strpos(content, 'PLYH-GZ-2026-001') > 0 ORDER BY doc_id;
-- 02-过闸申报与调度规程   第一条 目的与依据
-- 02-过闸申报与调度规程   第九条 闸次容量与编排
-- 03-船舶尺度与吃水控制标准 第一条 目的与依据
-- 04-重点物资优先过闸规定  第一条 目的与依据
```

而**该文号对应的本体文档（01-船舶过闸管理办法）实测 21 个 chunk 里，
含自己文号的有 0 个**（`含该文号的chunk数 = 0 / 21`）——因为文号只写在**元数据块**里，
而元数据块**不进 `content`**（本报告 §2 的选择）。

**结论**：**文号类查询在"只切 content"的口径下，无论向量还是 BM25 都无法定位文档本体**。
这不是 BM25 的缺陷，是**输入选择**的后果，而且是**可测量的**。
→ 第 4 周消融变量（已在 C-25 ⑤ 登记）：**把标题/文号/章节路径拼进检索文本**，
本条给出的是**先验证据**，不是事后猜测。

### 现象 D｜版本冲突：`as_of` 过滤确实把两版近重复费率表分开了（正面证据）

语料刻意放了"过期条款"与"相似冲突条款"（C-20）。同一查询、三个时点实测：

| `as_of` | 命中的 Top-3 来自 | 命中数 |
|---|---|---|
| 不加 | **06 版与 07 版混在一起**（第 2 名 06版、第 3 名 07版） | — |
| `2026-11-01` | **全部是 06-费率表（2026版）** | 520（541 − 21） |
| `2027-06-01` | **全部是 07-费率表（2027版）** | 517（541 − 24） |

过滤口径是**左闭右开**（`effective_from <= as_of AND effective_to > as_of`）。
对照逐文档生效期：06 版 `2026-09-16 → 2026-12-31`，07 版 `2027-01-01 → 长期`。

⚠️ **一个必须写下来的"看起来像故障、其实正确"的实测**：`as_of = 2026-06-01` 时**命中 0 条**。
原因**不是**过滤器坏了，而是**全部文档的生效日都是 `2026-09-16`（最早）**——
在那个时点这套规则**根本还不存在**，返回空是**如实**的。
**教训**：评测取时点必须取"有意义的时点"，否则会把自己的口径错误当成"检索失败"。

### 现象 E｜靠后的正确答案（待 Golden Set 判定）

- 探针 2「危险货物过闸需要提前多久申报」：Top-1 是 16-运输单证管理规范 **第四条【单证种类】**
  （一张 8 行表格，`dl=100`，`货物` 出现 8 次、`申报` 5 次），而**11-危险货物申报与审核细则
  第四条【申报时限】**（正文实测：*"危险货物运输申报应当在预计过闸时间前四十八小时提交…"*）
  排在第 3。**排序把"词频高的长表格"放在了"真正时效条款"前面。**
- 探针 5「退费的办理时限是几天」：Top-1 是 **24-服务质量考核与赔付办法 第十三条【赔付办理流程与时限】**
  （9.922694），**23-退费与差错更正管理规定 第十条【退费办理流程与时限】**（9.786820）排第 2——
  **两者仅差 1.4%**，且查询里的 `几天` 实测 **df = 0**（帮不上忙）。
- 探针 6「重点保供物资优先过闸的条件是什么」：Top-1 是 **07-费率表 第十一条【重点物资减免】**，

**共同机制**：本次 6 条探针里，"正确答案在 Top-5 内"的情况基本成立，
但 **Top-1 的正确性明显更弱**——凡"条款标题就是答案"（时限、条件、计费单位）的问法，
BM25 都会被**关键词密度更高的其他条款**压过。
→ 这正是"**标题不进检索文本**"叠加"**无 rerank**"的结果，两条都已在第 4 周的消融变量清单里。
