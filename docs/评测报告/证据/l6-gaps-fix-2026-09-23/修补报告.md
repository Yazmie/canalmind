## 2. 六个缺口：现状 → 现在 → 改了哪些文件

### ①-a `limit` 越界（`L6-011` `limit=10000`、`L6-010` 全量下载）

| | |
|---|---|
| 现状 | `DEGRADED(SCHEMA_INVALID)`——越界被当成"模型没说清"，可重试却永远改不对；`L6-010` 端到端实测是模型**根本没调工具**（`TOOL_NONE`） |
| 现在 | **`REJECTED`**，理由点名受限参数与边界（`参数 limit 不得超过上限（must have a maximum value of 50）`），**执行层不被调用** |
| 文件 | `SchemaGate.java`（新增 `Violation` / `violations()` / `validateArgumentsAsViolations()` / `isValueViolation()` / `describeForUser()`）、`ExtractionOutcome.java`（`STATUS_REJECTED` / `rejected()` / `KIND_PARAM_VIOLATION`）、`ToolArgumentExtractor.java`（终局判定分支）、`StructuredQueryService.java`（`outcome.rejected()` 分支 → `ToolResult.rejected` + 轨迹「违规拒绝（参数取值越界/枚举不符，未执行）」） |

**判据**：只有 `enum` / `const` / `maximum` / `minimum` / `exclusiveMaximum` / `exclusiveMinimum`
算「值越界/枚举不符」（`SchemaGate.VALUE_VIOLATION_KEYWORDS`）；
`required` / `additionalProperties` / `pattern` / `type` 一律**不**算 ⇒ **缺参仍走追问、形状错仍是 `DEGRADED`**。
判定用 **any**（出现一条越界即拒绝）：越界这件事**不因同一次输出里还漏了别的字段而变得可满足**。

### ③ 单位错（`L6-006`「机制砂 5000 **米**」）

| | |
|---|---|
| 现状 | 静默按 5000 吨算出 `18250.00 元` |

| 文件 | 新增 `TonnageUnitGuard.java`；`StructuredQueryService.java` 新增 `requireUnitConsistency()`，在 `queryTariff` / `quoteFee` 的**最前**（比量级/窗口/费率查询都早）调用 |

**判定规则（证据驱动，⛔ 不猜）**：命中需同时满足
(a) 问句里有「数字 + 长度单位」（`厘米/毫米/千米/公里/海里/公尺/米`，**长单位优先**，避免「厘米」被截成「米」）；
(b) 该数字与该次 `tonnage` **完全相等**；(c) 问句里**没有**同值的「…吨」表述。
⇒ 单独提到长度（如"吃水 5 米的船装 5000 吨货"）**不会**误判。

## 4. ③ 的诚实说明：问句拿得到吗？残余风险？

**拿得到。** 结构化层收到的就是**用户原话**：

- `QuestionPipeline.doRun` → `structured.ask(question)`（`backend/src/main/java/com/canalmind/eval/pipeline/QuestionPipeline.java` 约 L321/L338 传的是原始问题串）；
- `L4RunCli` 则传拼接后的多轮 prompt。
- 本轮为此**显式改了两个签名**：`queryTariff(call, traces, question)` / `quoteFee(call, traces, question)`，
  并把 `askDetailed` 改成 `run(outcome, question)`——即"问句"是**显式入参**，不是藏在某处的隐式状态。

**方法**：`TonnageUnitGuard.explainIfLengthUnitMistake(question, tonnage)` 纯函数，规则见 §2③，
⛔ 不发明脆弱正则去"理解"中文，只做**同值 + 单位词**两件确定性可核的事。

**残余风险（如实列出）**：

1. **它是"证据驱动"，不是"单位校验器"**：返回 `null` 只意味着"**没有发现单位用错的证据**"，
   **不等于**"单位确认正确"。模型若把 5000 直接猜成吨位、而问句里恰好没有任何长度词，本层**看不出来**。
2. **依赖"同值"**：若模型把「5000 米」换算成别的数（如 5）交给本层，守卫不触发（本轮选择"漏判"而非"误判"）。
3. **依赖调用方传原话**：若未来有调用方传入**改写后**的问句（如 Query Rewrite 之后再进结构化层），
   守卫会**静默失效**——失败方向是"漏判"，⛔ 不会变成误判。这一条**必须**在改调用链时复核。
4. **本轮只覆盖"长度单位"这一类**：其它单位错（如把"立方米/标箱/人次"当吨位）**未覆盖**，
   数据集里也**没有**这类题，故不做无据推测。

## 7. 诚实清单：**没做的 / 未验证的**

1. **⛔ 没有重跑 L6 端到端评测，也没有重新判分**（那需要付费模型调用）。因此：
   - 本报告的全部结论都是**层内确定性证据**（固定 JSON 桩 + 内存假数据层）；
   - `L6-011` / `L6-012` 等在**真实模型**下**是否真的产生"越界值"应答**，本轮**未复核**；
     我只保证"**一旦产生这种应答，行为已符合期望**"。
2. **`L6-010` 的端到端失败原因与守卫层无关**：2026-09-23 实测记录显示该题模型
   **没有调用工具**（`TOOL_NONE`）⇒ 那是**路由/抽取层**的问题，**本轮未修**（也修不动）。
   本轮只保证"若模型把该诉求表达成 `limit` 超上限，则 `REJECTED` 且不触达数据层"——
   探针第 2 格就是这个形态。**⇒ `L6-010` 的端到端状态不能凭本报告声称已修复。**
3. **`L1` 层未重跑**（付费）。⑥ 与 ④ 的改法**触及参数接受口径**，存在如下**未验证残余风险**：

4. **`networknt` 的英文细节文本会出现在拒绝理由里**（如 `must have a maximum value of 50`），
   本轮只是在其前面加了中文说明（`参数 limit 不得超过上限（…）`），**没有**做全量中文化。
5. **`SchemaGate` 的公开 API 有新增**（`Violation` / `violations` / `validateArgumentsAsViolations` /
   `isValueViolation` / `describeForUser`）。已确认 `L1` 依赖的既有入口 `validate(...)` **签名与行为未变**，
