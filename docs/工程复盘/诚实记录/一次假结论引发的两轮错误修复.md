# 一次假结论引发的两轮错误修复

> 类别：[诚实记录](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **我错的判断** | 我认定 Java 源码里的双反斜杠写法是"被误加了一倍"，并据此对 4 个文件做了**全局反斜杠减半**。**这个判断是错的**，依据来自一个不可靠的 Python 探针（原因见[验证工具本身也要被验证](../工程方法/验证工具本身也要被验证/README.md)）。 |
| **造成的实际损坏** | ①减半后多个文件出现**非法转义**，javac 直接拒绝编译（31 处）；②我随即写了"回滚脚本"，而回滚采取的是**全局加一倍**，于是把**本来就正确的换行字符字面量**（如 `'\n'`）也改成了 `'\\n'`，编译再次失败；③最终把**换行分割逻辑**改成匹配"字面反斜杠+n"，造成 CRLF 归一化失效、表格静默消失。 |
| **为什么一开始没发现** | 因为**编译能过**。第一次减半后的错误是"非法转义"（编译期就报错，好发现）；而"写成字面量"这一类**是合法的 Java**，编译通过、测试也可能绿——属于[转义与写入层的静默损坏](../工程方法/转义与写入层的静默损坏.md)记录的那类错误。 |
| **怎么查出来的** | 靠**十六进制断言**：测试打印 chunk 正文前 14 个字符的码点，看到 `005C 006E`（反斜杠 + n），这才确认"字面量"确实落进了正文。**在这之前，我一直在读源码、数反斜杠，全是无效劳动。** |
| **怎么修的** | 放弃"数反斜杠"，改为**用计算字符彻底绕开转义**：`String.valueOf((char) 13)` / `(char) 10`。并把所有编辑类脚本改成**逐处定位 + 逐处断言**，禁止全局替换，最后用"干净重建 + 跑测试"作为唯一 oracle。 |
| **我该更早做的事** | ①**发现"我改坏了"就该先停下**，而不是立刻写第二个脚本去对冲；②编辑类脚本必须**先 dry-run 打印将改动的每一处**；③涉及转义/编码时，"编译器接受"与"行为正确"是**两个**判据，不能只验前一个。 |
| **留下这条记录的原因** | 项目约定：**发现自己的错误结论必须在诚实记录留痕，不得静默改掉**。这轮的教训不是"我不该改代码"，而是**"我不该在探针未经验证时启动破坏性修复"**。 |
| **面试怎么讲** | 主动讲：我因为一个跨语言的假结论，做了全局替换，然后把回滚也做成了全局替换，两轮错误互相抵消，反而引入了静默 bug；最终靠**十六进制断言**定位、靠**计算字符**从源头消除该变量。我会强调**"编辑类操作要逐处、可断言、可回滚"**，并说明我现在会先验证探针再动手。这是"我知道自己会犯什么错"的展示，比"我从不犯错"可信。 |
