## 为什么单独立一类

因为这类内容**最容易被自己删掉**——"我犯过的错"看起来不像成果。
但面试官问"你犯过什么错 / 这项目有什么不足"时，**能具体、已修正、并固化成流程地回答**，
比说"我比较细心"有力得多。

**纪律**：发现自己的错误结论后，**必须在本目录留痕，不得静默改掉**（见 `AGENTS.md` §8.2）。

## 共同教训（含跨类指针）

**诚实不只是「承认错误」，还包括「不把还没做到的说成做到了」。** 越是接近交付的时刻，越容易滑向后者——
因为对外表述一改，KPI 立刻好看。

- ⚠️ **「建了索引」不能说成「用上了索引」**：本项目实测 541 行下规划器选 `Seq Scan`，
  索引**可用但未被选中**，故⛔ 不得宣称「HNSW 已启用 / 线上在用 HNSW」 → 主因在
  [检索工程/建了索引不等于用上了索引](../检索工程/建了索引不等于用上了索引.md)
- ⚠️ **两族指标不得混用、更不得只报好看的那一族**：严格口径（只对 gold 计分）读作**下界**、对外承诺用它；
  可答口径（gold ∪ 等价块）用来判断「是否真取到可答内容」。**必须并列报告并写明口径** → 主因在
  [数据一致性/改评测集后指标怎么变才算健康](../数据一致性/改评测集后指标怎么变才算健康.md)
- ⚠️ **摘要（数据包 / 汇报数字）是缓存，必须带「取自哪个产物、哪个 sha」**：本项目真实发生过
  「数据包手抄值 42、产物真值 41」——数据集重生成后**没有任何机制会报警**。
  推论：**校验脚本全绿 ≠ 我引用的那份摘要是新的**（脚本查的是数据集本身） → 主因在
  [中间产物值被当成最终值沿用](中间产物值被当成最终值沿用.md)
- ⚠️ **「我搜了没找到」不是「不存在」——而依据它去编辑，会把正确内容删掉**：同一会话内
  ① 字面量搜索把**已修**的缺陷误报成「未修」；② 脚本按**不存在的逐题字段名**读数据，
  输出**假的**「变好 0 / 变差 0 / 不变 40」；③ 只搜 `backend\scripts\` 就断言核对脚本不存在，
  **并把产品报告里本来正确的核对命令删掉、改成「手工比对、没有落成脚本」**（该脚本一直在
  `backend\target\eval\check_channel_parity.py`，实跑 40 题逐位一致、`[PASS]`、退出码 0）；
  ④ 查进程得到**「（无 java 进程）」**，而**我自己的付费批次当时正在跑**——真因是
  `Get-CimInstance` 被**拒绝访问**、又被 `-ErrorAction SilentlyContinue` **吞掉**
  （换 `Get-Process` 立刻看到 PID 15760、启动 10:51:10）。
  ⑤ 拿"本地仓库里没有 `ecj`"去**质疑对方的实测**、并准备要求对方删掉那条注释——
  **对方的实测是真的**（`target/surefire-reports/` 里的报告原文一字不差）；
  若真按我的判断改，就**删掉了当时唯一一条真实证据**，真因反而更查不出来。
  ⇒ 同一条纪律的另一面：**质疑别人的实测之前，先去看他说的那份证据**（它就躺在 `target/` 里）。
  ⇒ **「空」有三种成因——真的没有 / 范围不全 / 查询失败被静默——只有第一种能当结论。**
  更正留痕在产品报告 §6.2 那段「草稿期自我更正留痕」里 → **主因（验证方法）在**
  [../工程方法/局部搜索不能支撑否定结论.md](../工程方法/局部搜索不能支撑否定结论/README.md)

## 操作纪律类（非"结论错"，而是"动作错"）

- [把验证与提交串在同一条命令里，于是"验证"变成了走过场](验证与提交串在同一条命令里就不是闸门.md)：
  **改字面量前不查引用 + 跑出红却照常提交** ⇒ 一次真实的**带红提交**（`f33e9ae`）。
  与既有那次带红提交的区别：那次是**跑错了测试**，这次是**测试跑对了但提交不以它为条件**。
  核心一句：**验证必须是闸门，不是步骤**——失败时流程还能往下走，它就不是闸门。
