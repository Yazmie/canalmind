# 我有一段"假 PASS"的经历

> 类别：[诚实记录](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **发生了什么** | 我的语料校验脚本报「错误 1 项」，但列不出任何明细——**因为汇总语句写在了检查之前**，错误被计数却不被打印。也就是说，**那一整段时间我看到的 PASS，是靠错误的输出顺序打印出来的**。 |
| **我是怎么发现的** | 因为我**不信任自己的 PASS**：习惯去核对"数字和明细能否对上"。1 ≠ 0 却列不出明细，这个不对称就是线索。 |
| **讲法** | **测试、校验、监控，它们本身也是代码，也会有 bug。** 对它们保持怀疑，是可靠性的一部分。 |
| **一句可以记住的话** | **"一个从不失败的检查，无法证明它有效。"** |
| **后续怎么加固的** | ①汇总语句移到所有检查之后，并保证**指标与明细可对账**；②每新增一条检查都做"[注入错误](../工程方法/检查有效性必须被验证.md)"测试，确认它真会拦。 |
| **为什么这条比"我没出过错"更有价值** | 因为它证明的不是"我很小心"，而是"**我有一套发现自己在犯错的机制**"。前者靠状态，后者靠方法——**状态会波动，方法能复制。** |
