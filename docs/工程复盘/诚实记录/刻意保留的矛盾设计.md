# 刻意保留的矛盾设计

> 类别：[诚实记录](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **设计** | 费率表 `06`（2026 版，**已废止**）与 `07`（2027 版，**现行**）**故意并存且费率不同**；`02` 与 `04` 都讲"优先放行"但**适用货类范围不同**。 |
| **用意** | 用来测"**能不能检索到正确版本**"，而不仅是"能不能检索到相似文档"。这是检索系统真正的难点。 |
| **讲法** | **评测集的区分度来自"刻意设计的困难"，不是来自"干净的数据"。** 把数据洗得太干净，评测就测不出差别，也就失去了意义。 |
| **配套纪律** | 已在 `docs/规则语料/README.md` §5/§6 登记清单与维护约定：**已废止版本必须保留，不得因"过时"而删除**。 |
| **可能被追问** | "你怎么证明这些'难点'真的有效？"→ 答：这正是第 2 周要建 **Golden Set L2（40 条）+ Context Recall 基线**的原因——**区分度要用数据说明，不能只靠设计意图**。如果某条"难点"在评测里不产生差异，那它就不是难点，应当调整。 |
