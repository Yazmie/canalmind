# 断言某字段「独有」，而其实我只看了样例

> 类别：[我公开更正过自己的错误结论](README.md) ｜ 返回总索引：[../../README.md](../../README.md)

## 我原来下的结论

补 Judge 三层落库时，我核产物 schema，看到 L6 的条目里比 L3 多了三个键
（`ruleExpectedStatus` / `ruleActualStatus` / `rulePass`），于是写下：

> 「**L6** 的条目多 3 个规则键，那是 L6 独有的状态规则校验。」

并把它写进了 `DECISIONS.md` C-52、以及 `ArtifactIngest` 的注释和测试名。
**这句话是错的。**

## 实测把它打掉

落库成 135 条之后，按层数 `scores->>'rulePass'` 的非空条数：

| 层 | 带 `rulePass` 的条数 |
|---|---|
| L3 | **0 / 20** |
| L5 | **17 / 20** ← 我漏掉了这一层 |
| L6 | 15 / 15 |

**L5 也有**，只是**只有部分条目带**。锚点：`docs/评测报告/layer-L5-judged-v1.json`
（其顶层 `ruleChecked` / `rulePassed` 本就是 17，与逐条统计**自洽**）；
复核命令见 `DECISIONS.md` C-52 收口。

## 我为什么会错

因为**我看的是"一个样例"，却下了"独有"这种全称判断**。
L6 的样例里三个键都在，我就把它当成了"L6 才有的东西"——
**没有去数 L5、也没有去数 L3**。而"独有"这个词要求的正是**逐层清点**，
恰恰是我没做的那件事。

⚠️ 更值得记的是：**我写的守卫方向是对的，但它守的不是我错的那一处**。
我当时担心的是「照 L3 的键集一刀切会丢掉 L6」，于是把读取器写成
**"按条目有没有这个键"逐个取**，还在注释里**显式禁止按层名分支**。
真按我错的那句话去实现（"只有 L6 才读 rule\*"），
**L5 那 17 条的规则结果会被静默丢掉**——丢字段不报错、记录条数也仍然对。

⇒ **没出事，一半靠纪律、一半靠运气**：纪律让代码对"存在与否"敏感，
而运气让我虽然把话说错了、却没说成一句会被代码照抄的话。**不能拿这个当成功案例。**

## 现在怎么防

同一处口径**两个独立守护**，而不是只留我的一句注释：

1. 单测 `ArtifactIngestJudgeTest`：条目带 `rule*` 键时必须落进 `scores`，
   **且不含该键时不许凭空补**（补 `rulePass=0` 会把"没做这项检查"误报成"检查没过"）。
2. 落库后**按层数 `scores->>'rulePass'` 非空条数**——这是"产物 → 库"的端到端清点，
   能抓住任何"某层静默少了一部分字段"的情况。

## 教训（可迁移）

- **"独有 / 唯一 / 只有 X 才有"是全称判断，必须逐项清点后才能说**；
  看一条样例只能得出"这条有"，得不出"别的没有"。
- **把结论写进注释、测试名、决策记录之前，先问它是否超出我实际核对过的范围**——
  错话一旦被代码照抄，就会变成丢数据的实现。
- **守卫要守在我错的那一处**。这次我守的是相邻的一处：方向对，靶心偏。
