# 我公开更正过自己的错误结论

> 类别：[诚实记录](../README.md) ｜ 返回总索引：[../../README.md](../../README.md)

本主题子目录按 `AGENTS.md` §8.3 的递归规则，从原条目《我公开更正过自己的错误结论》拆出。
它记的是同一族纪律下的三次更正——**出处不同，纪律相同**——下面每条各记一次。

| 条目 | 它解决什么子问题 |
|---|---|
| [断言知识库无覆盖的更正](断言知识库无覆盖的更正.md) | **我的结论错了**：断言「知识库对某问题没有覆盖」，而复查方式本身有误；留痕怎么留、面试怎么讲 |
| [表格占位标记写法的更正](表格占位标记写法的更正.md) | **我们的文档错了**：`[[TABLE:n]]` 与代码、库里实存的标记不一致；**文档会滞后，数据不会撒谎** |
| [不是结论错了是归因错了](不是结论错了是归因错了.md) | **归因错了**：把 gold 标注错误写成了系统的「已知实现限制」，差点永久保留一个并不存在的缺陷 |
| [断言某字段「独有」，而其实我只看了样例](断言某字段独有而其实只看了样例.md) | **全称判断超出核对范围**：由一条样例断定「该字段独有」，漏掉整整一层；守卫方向对但靶心偏 |
| [把未被作答路径使用的提示词当成 Prompt 基线](把未被作答路径使用的提示词当成Prompt基线.md) | **改的不是被测对象**：冻/改的是 Web 侧提示词，而 L5 作答读的是另一处；`SYSTEM_PROMPT` 命名让人误判调用关系；**付费前实测消费方才挡住** |
| [把未决的决策当成了缺证据](把未决的决策当成了缺证据.md) | **欠报也是失真**：由「**D8**（改写策略）待决」推断「消融**至少一臂缺**」，用户据此裁定"规格书 L653 不勾"；取证发现看板两处明写**消融 6/6 全部有数**、且**明列 `+Query Rewrite` 臂** ⇒ **"上游决策未决"与"这一臂没跑"之间没有逻辑蕴含**。⚠️ 更关键是**先断言后取证**（证据当时就在手里）。⛔ 硬规矩：任何"某臂缺 / 某项未做"的断言，**必须能指出缺在哪一行、哪份产物**——"少勾"会被当成谦虚，于是没人质疑它 |
| [「六层全部在库」这句当时不成立](../../工程方法/汇总句必须由能跑的检查守护.md) | **汇总句没人验证**：「`eval_record` 六层全部在库」实测**只有 5 层**（**L4 一条都没有**），且被**放大进三份文档**（含「第 4 周目标验收通过」）；**同一个错在同一节犯了两次** ⇒ 主篇在 [工程方法/汇总句必须由能跑的检查守护](../../工程方法/汇总句必须由能跑的检查守护.md)（按 §8.2.4，主因归工程方法，此处留指针） |
