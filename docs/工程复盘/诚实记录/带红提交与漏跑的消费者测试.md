## 教训（可迁移）

1. **"改了 A 模块的数据，就要跑消费 A 的模块的测试"**。
   改语料时我只想到"语料校验脚本"，忘了语料**同时是 Java 切分器的输入**——
   而**输入契约由消费者定义**（这里由 `DocumentParser` 定义），不是由我改文件的那一侧定义。
2. **同一份文件被多套检查覆盖时，"跑过检查"不等于"跑过覆盖它的检查"**。
   本仓库里语料同时被 Python 校验器、SQL 探针、**Java 切分器/解析器**消费，
   三者的检查项互不包含。⇒ 交付语料改动的**最低验证集**应是"三个方向各跑一次"。
3. **顺手加的解释性括号，会撞上机器可解析字段**。
   元数据表是**给程序读的**，不是给人读的散文。说明性文字应当**放在正文或相邻字段**
   （本次已把它移到「说明」字段与正文，见修复）。
4. **提交前的那一次"跑测试"不能省**——尤其当改动**跨语言/跨模块**时。
   这次的代价是一次"带红提交"，而我原本可以在提交前 3 分钟内发现它。
