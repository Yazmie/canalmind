# 摘要值是缓存：中间产物值被当成最终值沿用

> 类别：[诚实记录](README.md) ｜ 返回总索引：[../README.md](../README.md)
>
> **一句话**：我在 v2 **数据包**里手抄的「gold 块数（去重）**42**」取自**中间态产物**——当时 `L2-034` 的 gold 还是**两块**；
> 后来该题 gold 改成单块、数据集重生成、`datasetSha256` 也变了，**而那个手抄的数字没有跟着重取**，一路流进了《评测报告》草稿。
> 正确值是 **41**。**摘要（数据包、汇报数字）本质是缓存，而缓存没记「取自哪个 sha」——过期时没有任何机制会报警。**

| 项 | 内容 |
|---|---|
| **现象** | `backend/target/eval/v2_datapack.md` §3 与《评测报告》`docs/评测报告/检索段-纯向量基线.md` 的 §2.2 / §3.1 都曾写「数据集 gold 去重后共 **42** 块」。**正确值是 41**：40 题里 **39 题 m=1、只有 `L2-027` 是 m=2**（41 次提及、去重也是 41，**没有任何块被两题共用**）。 |
| **根因（关键）** | 42 取自**中间态产物**：那一刻 `L2-034` 的 gold 是**两块**（`04d3ea4e3e8f448b` + `039a5c3a38396f46`）。我随后把该题 gold 改成**单块**（旧 gold `039a5c3a38396f46` 不含文号、答不出题干前半句），数据集重生成、`datasetSha256` 由 `4f32a3f0…` 变为 `8a33e64ca8cf598a…`——**但数据包里的那个手抄数字没有跟着重取**。 |
| **为什么这比「抄错一个数」严重** | ① **数据包/摘要本质是缓存**，而缓存里**没有记「取自哪个产物、哪个 sha」** → 它过期时**不报错、不告警**，下游（报告、看板、汇报）会**一路沿用**；<br>② 它与[度量口径没进产物](../检索工程/度量口径没进产物.md)是**同一条教训的两面**：那条讲**产物**缺「用了什么口径」字段 → 两份产物无法区分；这条讲**摘要**缺「取自哪个产物」字段 → 过期值无法被发现；<br>③ 这类错误**不会被任何校验脚本拦住**——`verify_golden_set.py` 查的是**数据集本身**（它的 `goldChunkCount` 一直是对的 **41**），**错的是我手抄在摘要里的那一份**。**校验通过 ≠ 我引用的那份摘要是新的。** |
| **怎么被抓到的（不是我自查出来的）** | 写报告的一线拿数据包里的数去和报告 §5.7 的**题级明细**做**算术交叉核对**时发现算不通：数据包里「`P1` 采纳 **13 题 / 14 块**」与「数据集内合计 **14 题 / 16 块**」并存，而**按 13 题无论怎么加都得不到 16 块**，必须把 `L2-034` 那一题（2 块）算进去才成立（可核对的硬证据：等价块集合里「有 2 块」的题**只有 `L2-022` 与 `L2-034`**）。顺着这条线回头查，才发现 42 是过期值。<br>→ **跨章节的数目必须能互相算得通；算不通，就说明其中有一处过期了。** |
| **同一处的第二条证据：「说不通」是过期信号的指纹** | 我在数据包里给「`BODY 27`」写的因果注是「**因 `L2-034` 从 BODY 换到 BODY**」——**这句话语义上根本不自洽**（BODY 换 BODY 怎么会让计数变化？）。真因是 **`L2-027` 新增的权威块 `89b7f0a4b4cb8615` 是 BODY**（v1 BODY 26 → v2 BODY 27）；`L2-034` 是**换块**（BODY → BODY），**对类型计数没有影响**。<br>→ **当一句话「看起来很正式但说不通」时，它通常是被抄下来的、而不是被推出来的**；这类句子应当**当场复核**——它是数字过期最灵敏的指纹。 |
| **已做的更正（可核对，且留痕）** | ① `backend/target/eval/v2_datapack.md` §3 已把 42 → **41**，并注明「⚠️ **曾误记为 42**——那是『`L2-034` 的 gold 仍为两块』时的中间产物值」；同处 `BODY 27` 的因果注改为「增量**全部来自 `L2-027` 新增的权威块**（BODY）；`L2-034` 的 gold 由 BODY 换成 BODY **不改变类型计数**」。<br>② 《评测报告》§2.2 按同一口径更正并**保留「本节此前写 42 块」的痕迹**、§3.1 表格同时标注「修订包曾记 **42**——中间值」；报告末尾 v2.3 修订说明的第 ①/② 条逐条记下这两处更正。<br>③ **没有静默改掉**：旧值以「⚠️ 曾误记为…」的形式留在原处（`AGENTS.md` §8.2 第 5 条）。<br>④ **该处留痕已于同日补齐**（`backend/target/eval/v2_datapack.md` **§3 中以「⚠️ 上格**曾经的错误因果注**（留痕，勿删）」开头的那一行**，**逐字引用被替换掉的旧句**「BODY 27——**因 `L2-034` 从 BODY 换到 BODY**」，并回指本条记录）——**触发者是本条记录本身的核验**。这一点比只写「打折了」更完整：**打折会被发现，并被补上。**<br>⚠️ **锚点纪律（本条自己也踩过）**：我起初引的是「该文件**第 63 行**」——**它当天就失效了**（该文件开头新增了纪律行，其后整体下移；实测那一刻原「第 63 行」已变成「条数 / 划分」那格——**行号已对不上**）。该文件是**会持续修订的工作文档**，故一律改用**「小节号 + 引文」**；又因为该行**行内带 Markdown 加粗**，**检索时用「留痕，勿删」或「从 BODY 换到 BODY」最稳**（用不带加粗的整串会命中文件开头纪律行里的示例）。**行号锚点失效时不报错——读者只会点到一段无关的文字。**<br>⚠️ **同一会话内已发生两次**：该文件当天先按用户指令替换了两处（原第 80 / 111 行，其后的行号整体 **+4 / +6**），又在**开头插入纪律块**（整体 **+5**）——**行号锚点会在当天失效，且改它的人自己也会记错**：校正这条锚点的人，在刚插完行之后仍按旧认识说「第 63 行仍然对」。**所以结论不是「要更小心地数行号」，而是「会变动的文件根本不该用行号」。** |
| **权威值只看产物（不许看摘要）** | `docs/评测报告/retrieval-baseline-l2.json` 的 `goldChunkTypeCounts` = **BODY 27 / TABLE 14**、`goldSizeValues` = `[1, 2]`；`docs/评测报告/golden-l2-validation.json` 的 `goldChunkCount` = **41**（41 块逐个查库全部命中）。同批产物还有 `backend/target/eval/recall_depth.md`。**摘要是副本，产物才是原件的唯一出处**——要引用数字就现场重跑并引用产物路径。 |
| **教训（本条标题级结论）** | **摘要必须带「取自哪个产物、哪个 sha」**；**数据集一旦重生成，所有手抄数字一律重取，不许沿用。** 这与「评测集要冻结 `datasetSha256`」是同一个道理：**可追溯性不能只钉在被测对象上，还必须钉在「我引用的那份摘要」上。** |
| **可操作做法** | ① **摘要只引用命令输出，不手抄**：本项目已有 `python backend/scripts/verify_golden_set.py --json docs/评测报告/golden-l2-validation.json` 与 `python backend/scripts/eval_retrieval.py --hits … --json docs/评测报告/retrieval-baseline-l2.json`，需要数字时**重跑它们**，并把**命令 + 产物路径**写进摘要（本期起摘要的每一格都带出处）。<br>② 报告里凡是「数据包未给 → 留空」的空缺，正确做法是**改挂产物出处**，而不是继续留空或凭记忆补——《评测报告》v2.3 就是这样收口的（删掉全部「数据包未给」声明，6 处空缺一次改挂 `retrieval-baseline-l2.json`）。<br>③ 收到「看起来正式但说不通」的句子、或发现跨章节数字算不通时，**先按过期处理**，不要先相信它。 |
| **⚠️ 未验证 / 留痕打折的地方（如实记）** | ① **原句的留痕当时是「打折」的，现已补齐**：数量那一格留了痕（⚠️ 曾误记为 42），但 **`BODY 27` 因果注那一格**当时是**静默替换**——报告末尾只有「按数据包更正」的记录、**没有引用旧句**。**这本身就是 `AGENTS.md` §8.2 第 5 条的一次打折执行**（改错了、也记了「改过」，却没留下「错成什么样」）。**同日已补齐**：`v2_datapack.md` §3 中那段留痕（见上格 ④，锚点用「小节号 + 引文」）已逐字引用旧句，故旧句**现在可从产物反查**（补齐之前只能凭本条记录复述）。<br>② 我**没有**回头全量复核数据包里其余手抄数字是否也来自中间态（本轮只更正了被追问的那两处），**不排除还有别的沿用值**。 |
| **可能被追问** | 「为什么不每次都直接查一遍？」→ 因为**摘要存在的意义就是省掉一次查询**。本条的结论不是「不要写摘要」，而是：**摘要必须自带版本戳，且每个数字都要能一条命令重放**——否则省下的那一步，迟早要用一次静默的过期来偿还。 |
