# 把自己的标注错误写成了系统的"已知限制"

> 类别：[诚实记录](README.md) ｜ 返回总索引：[../README.md](../README.md)
>
> **一句话**：一条"检索未命中"的真因是**我的 gold 标错了**（不是系统缺陷），我却把它叙述成系统的
> "已知实现限制"、并当"已登记缺陷"写进数据集与报告——**最后推翻它的，是我专门安排的一次
> "证伪自己产物"的对抗式复核；而它用的证据，是本项目另一条线自己的基线产物。**

| 项 | 内容 |
|---|---|
| **现象** | 纯向量基线 40 条里，唯一一条 30 位内完全召不回的是 `L2-034`「文号 `PLYH-GZ-2026-001` 对应哪一份文件？它主要规定了什么？」。我给它标的 gold 是 `039a5c3a38396f46`（01-船舶过闸管理办法 第二条 适用范围）——锚点：`docs/评测报告/golden-l2-v1.json` 中 `L2-034` 的 `goldRationale` 字段。 |
| **我当时的推理** | "文号属于 01 号文档 → gold 就取该文档的『适用范围』条（回答后半句「规定了什么」）"。**漏掉的正是：这块 chunk 全文不含文号，答不出题干的前半句。** |
| **我把它叙述成了什么（错）** | 「检索文本只用 `content`，而文号只存在于元数据里 → **无论向量还是 BM25 都无法靠文号定位本体**」，并当作**已登记的已知限制项**。该表述曾同时进入四处：数据集 `L2-034` 的 `knownLimitation` 字段（`docs/评测报告/golden-l2-v1.json`）、评测报告 §5.1、进度看板 §3.5、`docs/DECISIONS.md` 的"第 7 项交付"记录行。 |
| **真因（已验证）** | "本文档自己的 chunk 里没有自己的文号"**是真的**（校验快照记 `chunksInOwnDoc: 0`）；但文号出现在**别的文档的 4 个「依据」条**里，且每处都把**文号与文件名绑定**（「……依据《船舶过闸管理办法》（PLYH-GZ-2026-001）制定」）：`fa1bed0064ff3c1f`（02-第一条）、`9c2e4442313c8686`（02-第九条）、`04d3ea4e3e8f448b`（03-第一条）、`47e68f09b312a686`（04-第一条）——即"**检索失败**"不成立，**失败的是我的标注**（对照表见报告 §5.1）。 |
| **推翻它的证据本来就在手边** | ①同一份数据集里 `L2-031` 的 `note` 就写着「本条证明『文号检索并非一律不可答』……与 `L2-034` 形成对照」；②项目自己的 **BM25 探针 4**（`query` = `PLYH-GZ-2026-001 规定了什么`）的 **rank 1–4 正是上面那 4 个块**：`47e68f09b312a686` **16.948** / `fa1bed0064ff3c1f` **15.792** / `04d3ea4e3e8f448b` **15.605** / `9c2e4442313c8686` **11.205**（`docs/评测报告/bm25-baseline.json` 的 **`probes[]` 中 `query` 为「PLYH-GZ-2026-001 规定了什么」的那一条**——当前是 `probes[3]`（共 6 条，**该数组没有 `id` 字段**，故用「**下标 + `query` 字面值**」双锚点）——的 **`topHits` 里 `rank` = 1/2/3/4 的四条 `chunkId`**；该文件由 `backend/scripts/verify_bm25.py` 重生成，**锚点认 `query` 字面值与 `rank`、不认行号**：原写的「第 479–518 行」今天仍对得上，但那是**「还没坏」而不是「不会坏」**）。 |
| **为什么这比"算错一个数"更危险** | 数值错误只影响结论的**大小**；**归因错误掩盖的是原因**——它让人**停止排查**（"这是已登记限制，不是 bug"），于是**永久保留一个并不存在的系统缺陷**，还会污染后续决策：把"把文号拼进检索文本"当成必须做的优化，或对外说"我们的检索器认不了文号"。 |
| **怎么发现的** | 不是我自己回头看出来的：我安排了一次**只读对抗式复核**，**不告知它结论**，目标直接写成"证伪标注"（覆盖 40/40 题的 gold 全文 + 同条兄弟块 + 全库关键词扫描 + 40×541 = 21,640 对最长公共子串）。它给出 **17 条可用 / 23 条需修订**（P0 结论性标注错误 3 条、P1 等价证据块缺失 15 条、P2 分类与题面 5 条），并点名 `L2-034`（出处：进度看板 §3.5「对抗式审计」小节）。**P0 那三条我又自己查库复核了一遍——不采信未经验证的结论。** |
| **自动校验为什么没拦住** | 同一轮我给数据集写了校验脚本 `backend/scripts/verify_golden_set.py`，9 项检查里**第 9 项就是"已知限制项自证"**（`verify_golden_set.py` **docstring「检查项」小节的第 9 项**，实现在分节注释 `# ---------- 8. 已知限制项自证 ----------` 之下、变量 `limitation_checks`；**锚点认小节项名与变量名，不认行号**——原写的「docstring 第 32–33 行、实现第 316–349 行」实测已失效）——但它核的是"**文号是否真的不在本文档自己的 chunk 里**"，**这句话本来就是真的**，于是它给一个错误的叙述**盖了合格章**：PASS 快照 `docs/评测报告/golden-l2-validation.json` 的 **`limitationChecks`** 里还老老实实记着 **`chunksInOwnDoc` = 0、`chunksAnywhere` = 4**（**锚点认字段名**；原写的「第 18–26 行」在 v2 **重新生成产物**后已失效——**产物一重跑，行号必漂**，现行定位只用字段名，不再补新行号）——**"全库 4 处"就写在里面，我当时把它读成"限制成立"，而没有读成"答案在别处、gold 可能标错"**。**自动校验只能查形式（存在性 / 分布 / 照抄），查不出"gold 答不出该题"这种语义充分性**——那必须另设**对抗环节**。 |
| **更正做法** | 按 `AGENTS.md` §8.2 第 5 条**不静默改掉**：在 `L2-034` 的 `goldRationale` 与 `knownLimitation` 两个字段（`docs/评测报告/golden-l2-v1.json`）以及报告 §5.1 就地保留"原表述是错的"、并写明推翻依据（那 4 个块、那个 BM25 探针）。 |
| **⚠️ 当时未修的部分（已于 2026-09-21 修订，留痕不删）** | **当时**这 23 条**一条都还没改**：修 gold 会改变指标本身，属「指标与验收标准」口径调整（`AGENTS.md` §4.2.1 ④），**已提请用户确认，未擅自改标**。<br>**修订（2026-09-21）**：用户选定**全套修订包**（决策 C-29 / D18），23 处**逐条重判后**落改，数据集升 **v2**（`docs/评测报告/golden-l2-v2.json`，v1 原样保留供对照）——本条的 `L2-034` gold 由 `039a5c3a38396f46` 改为 **`04d3ea4e3e8f448b`**（03-第一条，单块答全两问），并新增 2 块可接受等价块。⚠️ **修订后严格族要逐指标看**：`HitRate@5/@10/@20/@30` **一字未变**（0.925 / 0.950 / 0.975 / 0.975），而其余指标**有升有降**——`Precision@k` 略**升**、`Precision@m`/`MRR@30` 略**降**，**四处差值全部逐题归因、没有一处来自检索能力变化**（**升降都要报**，只报未变的那一项就是选择性汇报）——这正是「没有事后挑数据」的可核对证据，见[改评测集后指标怎么变才算健康](../数据一致性/改评测集后指标怎么变才算健康.md)。 |
| **⚠️ 未验证（已于 2026-09-21 部分核实）** | **当时**另两条 P0（`L2-027` 的 gold 自称「以《术语与定义》为准」却多列「感染」；`L2-021` 的 gold 是标题自带「**其他**」的部分集合）引自进度看板 §3.5 与报告 §5.1 的记录，**该会话没有重新查库**。<br>**后续核实**：两条均已在 v2 修订中处理并复核——`L2-027` 的 gold 扩为 `['57a96bb50310e677', '89b7f0a4b4cb8615']`（补入被指定为权威的第二块），`L2-021` 保持 gold 不变、改为**收窄题面**（加限定「除了气象和能见度条件之外」）。理由与证据逐条记在 `docs/评测报告/golden-l2-v2.json` 的 `revision.changes`。 |
| **可复用的一句话** | **要防的不是"犯错"，而是"没有安排会证伪自己的环节"。** 我在同一轮里既写了校验脚本、又写下了错误结论——**形式校验全绿，不等于结论成立。** |
| **可能被追问** | "为什么不重做一次实验？"→ 不必：**"多个通道各自留下可核对的产物"本身就是交叉验证机制**，它比"重新做一次实验"更便宜。BM25 探针产物**早于**数据集落盘（实测文件时间戳：`bm25-baseline.json` 2026-09-20 23:12 ＜ `golden-l2-v1.json` 2026-09-21 00:20）——**证据早就在仓库里，是我没去交叉核对。** |
