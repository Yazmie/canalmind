# 已知薄弱环节

> 类别：[诚实记录](README.md) ｜ 返回总索引：[../README.md](../README.md)
>
> **用途**：面试被问"这项目有什么不足"时，**有准备地承认，比临时找补可信**。

| 薄弱点 | 现状 | 计划 |
|---|---|---|
| **业务数据是仿真的** | 语料与业务数据均为本地生成，**不代表真实费率与政策** | 如实声明（文档已标注）。**这也是本项目定位为"技术验证"而非"业务系统"的原因** |
| **知识库引用无法被外部核对** | 知识库是第三方资料、不入 git（`.gitignore` 第 29 行） | 讲述时**复述结论本身**，不依赖对方看不到的引用（见[../README.md](../README.md)） |
| **混合检索的增益尚未验证** | 语料是高度结构化的规则条文，知识库提示"此类文档 BM25 增益可能不明显" | 正是 **D3（是否启用混合检索）待决**的原因——要用消融实验的数据决定，而不是先上再说 |
| **`iterative_scan` 的代价未量化** | 已知会增加扫描量（`shared hit` 949 → 2478），但**未测延迟影响** | 纳入第 4 周消融对照项，把权衡写成数据而不是印象 |
| **融合与 Rerank 尚未落地**（方案已定、代码未写） | **D2 → C-26**（融合用 **RRF**，`k`=60，融合层接口化）与 **D4 → C-27**（**LLM Rerank**（DeepSeek）+ 可插拔 `Reranker` 接口）**均已确认**（2026-09-21），但**实现属第 2 周第 5 项，尚未开始** | 前置件已就绪（向量通道与 BM25 通道都能独立评测）；届时按 C-28 纪律**只用 `split=dev` 的 32 条调参**，`holdout` 8 条只在阶段结论定稿时跑一次 |
| **前端仍是空壳** | `frontend/` 只有 `.gitkeep` | 非第 2 周范围；实现时须匹配后端 `SseTextCodec` 的解码语义 |
| **数据包/摘要里的数字没有全量复核** | 本轮查出数据包里一处手抄值取自**中间态产物**（`gold` 块数记 42、真值 **41**）并已更正，但**只更正了被算术交叉核对追问出来的那两处**，其余手抄数字**没有全量重取** | 流程收口：**摘要每一格带产物出处，需要数字就重跑** `verify_golden_set.py --json …` / `eval_retrieval.py --json …`，**不再手抄**（详见[中间产物值被当成最终值沿用](中间产物值被当成最终值沿用.md)） |
| **评测指标的绝对水平只有 40 条样本** | 纯向量基线**已产出**（严格口径 `HitRate@30` **0.975** / `@5` **0.925**、Top-1 **0.6625**、`MRR@30` **0.776488**；v1/v2 两份都在 `docs/评测报告/`），但**分辨率只有 2.5 个百分点/条**，**不支持统计结论** | 对外只用《评测报告》里写明的口径与数字；⛔ 不把 40 条的结果说成「线上效果」，也⛔ 不引用没有出处的数字（`AGENTS.md` §6 第 1 条） |
| **评测集自身曾存在已确认的标注缺陷（2026-09-21 已修订为 v2）** | 当时有题目的 gold **答不出该题**（对抗式复核查出、并经独立查库复核确认）；**当时未修**，因为修 gold 会改变指标口径。<br>**现已按 A 类决策修订**（决策 C-29）：23 处逐条重判后落改、数据集升 v2，**严格族的 `HitRate@k` 一字未变**，但 `Precision@k` **略升**、`Precision@m`/`MRR` 略降（**三处去向已逐题归因，没有一处来自检索能力变化**），并新增「可答率」口径 | ⚠️ **仍未闭合的部分**：可答族的分子依赖人工标注（16 块等价块，判据「单独可答」由我判定、**无第三方复核**）；且 **BM25 通道与后续融合/重排尚未按 v2 重跑**。详见[把标注错误写成了系统的已知限制](把标注错误写成了系统的已知限制.md) 与[改评测集后指标怎么变才算健康](../数据一致性/改评测集后指标怎么变才算健康.md) |
| **HNSW 索引在本项目数据量下「不被规划器选中」** | 索引**可用且结果正确**（强制 `enable_seqscan=off` 后命中，Top-20 与精确扫描完全一致），但 **541 行规模下规划器选 `Seq Scan`**（两者都是毫秒级）；实测 **≥1000 行才自发选 HNSW**；且 pgvector 代价模型**显著高估** HNSW（541 行约 5.7 倍） | ⛔ **不得对外宣称「HNSW 已启用 / 线上在用 HNSW」**；已列为第 4 周规模测试复核项（详见[建了索引不等于用上了索引](../检索工程/建了索引不等于用上了索引.md)） |

> **讲法**：这份清单不是"自曝其短"，而是**说明我知道边界在哪**。
> 一个能说清"哪里还没验证、为什么、打算怎么验证"的人，比一个声称"都做好了"的人可信。
