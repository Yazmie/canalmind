# 两种「等价」度量的分数差 1e-7，而产物里没有「用了哪个度量」

> 类别：[检索工程](README.md) ｜ 返回总索引：[../README.md](../README.md)
>
> **一句话**：名次一样、语义一样、**分数不一样**；更要紧的是命中产物里**根本没有度量字段**——
> 下游无法只凭产物判断这批分数是谁算的，混用两份产物做阈值判断就会漂移，而漂移量小到**任何直觉都不会报警**。

| 项 | 内容 |
|---|---|
| **背景** | 向量通道有两条度量：`cosine`（`1 - (embedding <=> q)`，精确扫描）与 `ip`（`-(embedding <#> q)`，与 HNSW 的 `vector_ip_ops` 算子类一致）。因为入库的 `bge-m3` 向量**已 L2 归一化**（实测范数均值 1.000000、最大偏差 0.000001），两者在**语义上是同一个量**——[embedding模型是索引格式的一部分](embedding模型是索引格式的一部分.md) 里「排序完全等价」那句就是这么来的。 |
| **实测事实 ①：名次完全一致** | 40 条题、Top-30：`--metric cosine`（`<=>`）与 `--metric ip`（`<#>`）**40/40 排序完全一致**，同名次分数**最大绝对差 8.28e-07**（《评测报告》§3.3「度量不变性」一行，判定为 float 精度级）。 |
| **实测事实 ②：分数不一致（文件级证据，可自己 diff）** | `backend/target/vector-probe/cmp-cosine.json` 与 `cmp-ip.json` 是**同一次查询、同一 Top-5** 的两份产物：**逐行 diff 只有 5 行 `score` 不同**，名次、`chunkId` 与其余字段全同。例如第 1 名 `0.7562966056223852`（cosine）vs `0.7562965154647827`（ip）→ 差 **9.0e-08**；第 5 名 `0.7507569342401125` vs `0.7507569789886475` → 差 **4.5e-08**，**方向还相反**。 |
| **陷阱（这条真正的代价）** | 命中产物 JSON **不含度量字段**：契约只有 `channel / profileName / topK / queryCount / results`，命中项只有 `rank / chunkId / docId / docTitle / chunkType / articleNo / articleTitle / version / score`（`backend/src/main/java/com/canalmind/rag/vector/VectorResultJson.java`，类注释里那份契约就是全部键）。**故下游无法只从产物判断用了哪个度量**；两份不同度量的产物一旦被混着做阈值判断或分数比较，就会漂移——而漂移只有 **1e-7**，**「差距看起来很小」这种直觉恰好是最不会报警的那一类**。 |
| **当时怎么处理的** | **不改契约**（加键属对既有接口的扩展，留待第 5 项接入融合层时一并处理），改为**把口径写在产物之外**：《评测报告》§3.3 明确声明「§4 全部数字来自 `--metric cosine`（默认，精确扫描）」，并把这件事登记为**溯源缺口**。 |
| **教训** | **「等价」不等于「字节等价」。** 数学上等价的两种实现落到浮点上就会有 1e-7 量级的差。凡是拿分数做阈值、比较、或要求结果可复现的地方，必须三件事同时做：①**固定同一个度量**；②把度量写进**产物之外的元数据**（报告 / 标签 / 文件名）；③条件允许时，**把它变成产物里的一个字段**——契约里没有它，就等于让下游靠猜。 |
| **⚠️ 未验证** | 我核对到的是**两份产物的逐行 diff**（差值的量级与方向）与报告记录的 8.28e-07；**pgvector 内部 `<=>` 具体走哪条浮点路径（按单精度算 `1 − cos`，或另有中间精度）我没有在这一轮读实现确认**——「1e-7 来自浮点精度」是**量级判断**，不是实现级确认。 |
| **可能被追问** | 「既然等价，为什么不干脆只用 `ip`？」→ 答：`ip` 与索引算子类一致 → 可能走 HNSW → **带近似误差**；基线要的是**无近似误差**的精确扫描，所以默认 `cosine`。这个开关的本质不是「换个相似度口径」，而是**「精确扫描的评测基线」与「走索引的线上路径」二选一**（`VectorSearcher` 类注释原话）。 |

> **同一条教训的另一面（摘要侧，指针）**：本条讲的是**产物缺「用了什么口径」字段** → 两份产物无法区分；
> 对称地，**摘要（数据包 / 汇报数字）缺「取自哪个产物、哪个 sha」字段** → 它会过期而**不报警**——
> 本轮真实发生：数据包里手抄的「gold 块数 42」取自 `L2-034` gold 仍为两块时的中间态，数据集重生成后没重取。
