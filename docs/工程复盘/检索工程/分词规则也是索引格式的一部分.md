# 分词规则也是"索引格式"的一部分

> 类别：[检索工程](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **现象（一个隐患）** | 第一轮入库时，档案记录的身份是"**库版本 1.0.2 + 词典 sha256 + 停用词 sha256 + 切分模式 + k1/b**"。随后我**改了本项目的分词规则**（增加"剥离行首列表编号"），而上面这些字段**一个都没变**。 |
| **为什么危险** | 于是"**就地重灌**"会把**两套不同口径的词元混进同一个档案**——分数照样算得出来，只是**不再可比**；而查询侧无法分辨这件事。 |
| **守卫为什么没拦住** | 数据库守卫 `rag_assert_token_profile`（见 `V4__add_bm25_token_index.sql`）比的是**值**，不是**行为**：上述字段都没变，它就认为"口径没变"，**察觉不到**。**"比值的守卫"挡不住"比不出来的变化"。** |
| **修法** | 引入 `RULES_VERSION`（本次为 **`v2`**），并把它**同时**折进两个方面：①档案的 `tokenizer_version` 字段变成 **`1.0.2+rules-v2`**——守卫因为**该字段变化**而拒绝就地重灌；②**档案名**变成 **`jieba:shipping-dict-v1:rules-v2:INDEX`**——让**人**一眼看出"这两个档案为什么不同"，并让 rules-v1 / rules-v2 **共存对照**（本次的量化对比就是这么做的，见 [结构标记不该进倒排表](结构标记不该进倒排表.md)）。**一条信息要同时写给人看和写给机器判。** |
| **诚实记录的薄弱点** | `RULES_VERSION` 是**人工常量**，靠人记得改——**规则是代码，没法像词典那样算文件哈希**。缓解手段：单元测试把**档案名与版本串写死**（`TokenizerProfileTest`、`JiebaShippingTokenizerTest` 的 `profileCarriesIdentity`），**改规则时测试会红**，逼人做决定（要么 bump 版本、要么承认就该复用旧档案），而不是让它悄悄过去。 |
| **一般化结论** | **凡是决定"被索引的表示"的东西，都必须进档案身份**：embedding 模型（同类条目 [embedding模型是索引格式的一部分](embedding模型是索引格式的一部分.md)）、分词器与其版本、词典与停用词的**指纹**、**分词规则版本**、BM25 的 k1/b（本项目 k1/b 存在**档案表**里、不写死在代码里，改它们同样会触发拒绝重灌）。 |
| **业务含义** | 这与 embedding 那条是**同一个道理的另一半**：那条讲"模型换了索引就失效"，这条讲"**同一句话，切法也是索引格式的一部分**"。"索引格式"不是指存储格式（字节怎么排），而是**"同样的输入被表示成什么"**。 |
| **可核对锚点** | • `backend/src/main/java/com/canalmind/rag/tokenize/JiebaShippingTokenizer.java`（`RULES_VERSION` 的 javadoc：为什么单独版本化、已知薄弱点）<br>• `TokenizerProfile.buildProfileName`（档案名由 分词器名 + 词典版本 + 规则版本 + 模式 拼成）<br>• `backend/src/main/java/com/canalmind/rag/tokenize/TokenizerProfileGuard.java`（不一致**拒绝查询**而非降级）<br>• `backend/src/main/resources/db/migration/V4__add_bm25_token_index.sql`（`rag_assert_token_profile` 守卫）<br>• 单元测试：`backend/src/test/java/com/canalmind/rag/tokenize/TokenizerProfileTest.java`、`JiebaShippingTokenizerTest.java`（`profileCarriesIdentity`） |
| **可能被追问** | *"为什么不给规则也算个哈希？"* → 因为规则是**代码**，代码哈希会把注释和格式改动也算进去——那测的是"文件变了"，不是"**行为变了**"。**用一个需要人判断的常量 + 一条会红的测试**，比一个看着自动、其实噪声很大的哈希更可靠。**自动化的价值在于判据有意义，不在于少写一行。** |
| **可能被追问（进阶）** | *"规则改了但不 bump 会怎样？"* → 单元测试会红。这是**刻意留的强制停点**——因为在"要不要重建索引"这件事上，**沉默通过比失败更贵**。 |
