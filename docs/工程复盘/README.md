# 工程复盘与面试素材

> **这是什么**：CanalMind 开发过程中**真实踩到、并想明白了**的问题清单。
> 每条按「**问题 → 怎么发现的 → 怎么解决的 → 业务含义**」组织，也就是面试里可以直接讲的结构。
>
> **⚠️ 项目定性（务必如实说明）**：CanalMind 是**个人技术验证项目**。
> 业务语料（`docs/规则语料/` 的 28 篇规则文档）与业务数据（船舶、航次、运单、费率）
> **均为本地生成的仿真内容，不含任何真实业务数据，也不代表真实费率与政策**。
> 值得讲的**不是"业务体量"，而是工程判断力**：如何在无人告知的情况下**发现**数据不一致、
> 如何验证自己的验证是否可靠、以及如何把一个"看起来只是配置项"的问题追到会影响线上召回率。

## 一条主线（贯穿全部文件）

"一致性"在 RAG 系统里会以**三种完全不同的面目**出现，处理方式要**逐层升级**：

1. **同一份语料内部**的矛盾 —— 靠人眼审查能发现 → [闸室尺度跨文件互斥](数据一致性/闸室尺度跨文件互斥.md)
2. **跨来源**的矛盾（文档 vs 数据库）—— 人眼看不出来，必须靠脚本做跨源比对 → [钢材归类跨来源冲突](数据一致性/钢材归类跨来源冲突.md)
3. **校验脚本本身失效** —— 最危险，因为**它让前两层看起来是绿的** → [校验器输出顺序导致错误被吞](工程方法/校验器输出顺序导致错误被吞.md)

> **讲法**：前两层是"认真"，第三层才是"可靠"。
> 真正的工程成熟度不在于"我写了很多检查"，而在于**我会去验证检查本身是否真的在工作**。

## 第二条主线：**"合法但错"是最难查的一类**

第二轮排查暴露出一类此前没写进本目录的错误形态，值得单独成线：

1. **代码合法、编译通过、测试也绿，但行为是错的** ——
   [转义与写入层的静默损坏](工程方法/转义与写入层的静默损坏.md)：
   同一处换行写成"一个反斜杠"或"两个反斜杠"，运行时分别是 2 字符与 4 字符，
   写错的那个**永远匹配不到**，于是归一化失效、表格整块消失，**一句报错都没有**。
2. **诊断它的工具自己也会错** ——
   [验证工具本身也要被验证](工程方法/验证工具本身也要被验证.md)：
   一个跨语言的假结论让我启动了全局替换，把 4 个文件改坏，回滚又过度纠正。
3. **改坏的经过必须留痕** ——
   [一次假结论引发的两轮错误修复](诚实记录/一次假结论引发的两轮错误修复.md)。

> **讲法**：这类问题的正确应对不是"更仔细地读代码"（读不出来），
> 而是**换判据**：并排 A/B 对照实验、码点/十六进制级断言、`javap -v` 看真实产物、
> 干净重建后跑测试。**"我看过了"不构成证据，"两个独立 oracle 一致"才算。**

4. **平台默认值悄悄污染产物** ——
   [生成物被平台默认值污染](工程方法/生成物被平台默认值污染.md)：
   Jackson 的默认缩进器用 `DefaultIndenter.SYS_LF`，于是"生成清单"这件事在 Windows 上
   产出 CRLF，而仓库声明 LF —— **每跑一次命令，diff 就变一次**。
   ⚠️ 这是我在本次**先猜错、再实测推翻自己**的一条：我原以为是 `Files.writeString` 归一的，
   实测发现它并不归一，真凶在**序列化阶段**。**"我能想到的解释"不等于根因。**

5. **默认值是一个"具体的值"，不是一个"安全的值"** ——
   [结巴用户词典的列数陷阱](检索工程/结巴用户词典的列数陷阱.md)：
   词典照抄标准 jieba 的三列格式，词频**静默退回默认值 3.0**；而该库基础词典
   349045 词、总频次 60101878，于是 `log(3/60101878) = -16.81`——
   **比基础词典里任何词都低**。你以为"给词典加了个词"，
   实际是**把它加成全库最低分**，且一句报错都没有。
   > **追问自己一句**：这个缺省值，相对于我的真实数据，是多大？

6. **默认值选错，会让整批数据"看起来是模型不行"** ——
   [量程不足会把配置掐死记成能力不足](工程方法/量程不足会把配置掐死记成能力不足.md)：
   重排侧额度 `maxTokens=4096` 在 **30 条候选**档下 **3/3 必然降级**（`finish_reason=LENGTH`、
   `completion` **恒等于** 4096——推理 token 与正文共享同一预算），而 `DEFAULT_TIMEOUT` **30 s**
   **正好压在实测均值 29.4 s 上**（有一次**成功**的调用耗时 **29.875 s**）。
   两处都在产物里表现为**「保留融合原序」——与「重排没有效果」完全一样**。
   > **讲法**：`max_tokens` 与 `timeout` 不是"调参"，是"**量程**"。
   > 量程不足时，失败会被记成"能力不足"，而产物只会说"降级了"——
   > 所以**在评估任何"模型能力"之前，先确认仪器的量程够不够**。

## 第三条主线：**"基准"本身也是会被写错的对象**

建第一版 Golden Set L2（40 条评测题）+ 指标脚本这一轮，暴露出第三条独立主线——
**评测资产自己就是一类易错对象，而且它们出错不会报错**：

1. **评测集本身的错误不报错，只会让"指标好看"** ——
   [评测集自身的错误不会报错](数据一致性/评测集自身的错误不会报错.md)：
   gold id 抄错、**分布失衡**、题面照抄条款用词，三类风险**都不会让任何脚本变红**；
   于是给数据集也写了校验脚本（`backend/scripts/verify_golden_set.py`），**首轮就抓出 7 项错误**。
2. **校验规则过严，会把正确的东西判成错的** ——
   [规则过严会把正确的东西判成错的](工程方法/规则过严会把正确的东西判成错的.md)：
   断言范围写成"全库" → 把一条**成立**的已知限制判成不成立；
   反照抄规则过严 → 误伤"必须点出术语"的术语题与"必须写出版本号"的标识符题，
   甚至会**诱导人去改写本来没问题的题面**（只为迎合规则）。
3. **真实数据未到位，就先用合成输入空跑** ——
   [用合成输入先空跑评测链路](工程方法/用合成输入先空跑评测链路.md)：
   两个真 bug，其中一个**静默返回 0 条**（占位标记匹配串要求 id 后紧跟 `]`，
   而真实标记是 `[TABLE:<id> rows=N cols=M]`）。若直接上真实数据，
   它极可能被读成"**这类失败不存在**"。
4. **量尺错在哪里，也可能被我自己说错** ——
   [把标注错误写成了系统的已知限制](诚实记录/把标注错误写成了系统的已知限制.md)：
   一条"30 位内完全召不回"的题，真因是 gold 标了一个**答不出该题**的块，
   我却写成"**无论向量还是 BM25 都无法靠文号定位本体**"的**已知实现限制**，
   并登记进数据集、报告与决策记录；**推翻它的证据来自另一条线自己的基线产物**（BM25 探针 rank 1–4）。
   **自动校验只能查形式，语义充分性必须靠对抗式复核。**
5. **否定结论比肯定结论需要更强的举证，而依据它去编辑最贵** ——
   [局部搜索不能支撑否定结论](工程方法/局部搜索不能支撑否定结论.md)：
   同一会话内连着错**四次**，**全部是我的验证方法**——① **字面量搜索**把**已修**的缺陷误报成「未修」
   （修法是加 `rerankEnabled` 守卫，那个字面量其实还在）；② 脚本按**不存在的逐题字段名**读数据
   （`rankOfFirstGold` 实为顶层直方图 `rankOfFirstGoldHistogram`），每题取到 `None`
   ⇒ 输出**假的**「变好 0 / 变差 0 / 不变 40」（真实是 **变好 8 / 变差 8 / 不变 24**）；
   ③ 只搜 `backend\scripts\` 就断言核对脚本不存在，**并据此删掉了报告里本来正确的命令**；
   ④ 查进程得到**「（无 java 进程）」**，而**我自己的付费批次当时正在跑**——真因是查询被**拒绝访问**
   （`Get-CimInstance`）又被 `-ErrorAction SilentlyContinue` **吞掉**，换 `Get-Process` 立刻看到它。
   > **讲法**：肯定结论**有一个正例就成立**；否定结论要求**搜索范围本身可辩护**——
   > 所以**搜索与脚本必须先自证「我真的扫到了 / 读到了」**（打印文件数 / 命中数 / 题数，
   > 让空结果看起来就是可疑的），而**「我搜了没找到」⛔ 不构成编辑别人正确内容的理由**。
   > ⚠️ 再加一句**「空」有三种成因**：**真的没有 / 范围不全 / 查询失败被静默**——
   > 三者在屏幕上长得一样，故「空 / 无 / 0」在当结论前必须先问「这是哪一种空」。

> **讲法**：前两条主线讲的是"**系统**不一致"，这一条讲的是"**量尺**不一致"。
> 尺子错了不会报错，只会让每次实验都"看起来在进步"——所以**评测集、校验规则、度量脚本
> 必须和被测系统一样被验证**（与[验证工具本身也要被验证](工程方法/验证工具本身也要被验证.md) 同族：
> 那篇讲"诊断工具自己会错"，这轮新增的是它的**度量工具**版本）。
> 而第 4 条再进一步：**连"量尺错在哪"都可能被我归因错**——归因错误会让人**停止排查**，
> 于是一个并不存在的系统缺陷被永久保留。**所以除了验证量尺，还必须安排"会证伪自己"的环节。**

## 第四条主线：**「已经做了」不等于「已经生效」——索引、口径、豁免、审计都一样**

向量通道 + 评测基线 + 数据集修订这一轮暴露出一族**同形状**的问题：
某样东西**明明做了**（建了索引、定了度量、写了豁免、做了审计、抄了摘要），**却没有证据说明它生效了**，
而且失败的样子全都是「**不报错、只是少一行字**」。

| 现象 | 一句话 | 条目 |
|---|---|---|
| **索引建了却没被用上** | 算子类不匹配 → `<=>` 用不上；换成匹配的 `<#>` **在 541 行下仍不被规划器选中** | [检索工程/建了索引不等于用上了索引](检索工程/建了索引不等于用上了索引.md) |
| **度量口径没进产物** | 两种等价度量名次 40/40 一致、分数差 **1e-7**，**产物却没有度量字段** | [检索工程/度量口径没进产物](检索工程/度量口径没进产物.md) |
| **豁免生效时静默不打印** | 读者分不清「没报错」是「确实没重合」还是「被豁免掉了」 | [工程方法/规则过严会把正确的东西判成错的](工程方法/规则过严会把正确的东西判成错的.md) |
| **审计的结论没被核验** | 23 条待修订里**审计自己错了至少 3 处**，照搬会改坏**正确**的 gold | [工程方法/审计结论也要逐条核验](工程方法/审计结论也要逐条核验.md) |
| **改了评测集，指标该怎么变** | **严格族要逐指标看、升降都要逐题归因**：`HitRate@k` 未变、`Precision@k` 略**升**、`Precision@m`/`MRR` 略**降**；「改完普遍变好」才是危险信号 | [数据一致性/改评测集后指标怎么变才算健康](数据一致性/改评测集后指标怎么变才算健康.md) |
| **摘要里的数字过期了不报警** | 数据包手抄「gold 块数 **42**」取自**中间态产物**（真值 **41**）——**校验全绿 ≠ 我引用的那份摘要是新的** | [诚实记录/中间产物值被当成最终值沿用](诚实记录/中间产物值被当成最终值沿用.md) |

> **讲法**：前三条主线讲的是**系统**与**量尺**不一致，这一条讲的是**证据**不足。
> 「我做了 X」是**动作**，「X 生效了」是**事实**，两者的差距只能靠证据补——
> 所以每条都要能回答一句：**「你是从哪个产物看出来它生效的？」** 答不上来，就等于没做。
> ⚠️ 再加一句：**产物里的值才是原件的出处，摘要只是副本**——副本必须自带「取自哪个产物、哪个 sha」。

## ⚠️ 全局约定（新增条目时必读）

### 1. 用**语义化路径**定位，不用编号

条目文件名就是它的标题（如 `HNSW索引过滤条件静默少返回.md`）。
**不要引入编号**——编号会随重组位移，导致所有"见 §2.3"式引用失效；
语义路径在文件移动时只需改链接文本，且**看文件名就知道内容**。

**引用条目一定要写成 Markdown 相对链接**（便于点击跳转、也便于机械校验）：

| 场景 | 写法 |
|---|---|
| 引用**同类**条目 | 反引号包裹：`` `[标题](文件名.md)` `` |
| 引用**跨类**条目 | 反引号包裹：`` `[标题](../其他类/文件名.md)` `` |
| 引用**某类目录** | 直接链到该目录的 `README.md`，如本文件顶部的分类表 |

> ⚠️ **写示例时要把链接用反引号包起来**（如上表），
> 否则**示例本身会被链接校验判为失效链接**——这是个真实会咬人的小事。

### 2. 新增一个"种类"怎么办

**直接新建一个分类目录**，并在其中放一个 `README.md` 作为该类索引。
**不需要改任何既有文件的位置。**

若新种类当前只值一两条，先放进最接近的既有类；
**攒到 3 条以上再独立成目录**（避免空目录）。

### 3. 同一类下的"不同问题"再分层

**递归规则**：某条目内容长到**超过约 40 行**（或明显含多个独立子问题）时，
就地新建**主题子目录**，把它拆成多条：

```
检索工程/
├── README.md
├── 近似索引/                   ← 新增的主题层（示例）
│   ├── HNSW索引过滤条件静默少返回.md
│   └── 迭代扫描的代价.md
└── ...（其余条目）
```

**层数不设上限**——每层都用同一条规则判断"要不要再拆"。
但**不为未来预留空目录**：目录应当在有内容时才出现。

⚠️ **当前这条规则有 6 条未拆的偏离**——已实测登记在文末「⚠️ 已知结构偏离（2026-09-21 实测登记）」一节；
⛔ 那是**专项留待**，不是「不需要拆」。
（登记在文末是为了**不动本小节的编号**——「约定 6」已被其他条目按编号引用。）

### 4. 每条记录必须有的要素

| 要素 | 要求 |
|---|---|
| **可核对锚点** | 文件路径 + 行号 / 实测数据 / 脚本名。⛔ 禁止"我记得当时…" |
| **业务含义** | 一条记录若说不出"这对真实系统意味着什么"，就不算复盘 |
| **可能被追问** | 面试防守用；想不出追问点，说明这条讲不透 |

> 📌 **锚点偏好（实践层）**：本文档目录**优先**用 **小节号 / 字段名 / 逐字引文 / 生成方式（哪个脚本、哪条 SQL）**；
> **行号仅用于已冻结的文件**（Flyway 迁移、只读知识库、`.gitignore`）。
> ⛔ 这不是推翻上一条的「可接受类型」——行号**仍属可接受类型之一**，只是**本文档目录内不优先用它**，

### 6. ⚠️ 批量删除/移动前，先列出**将要被影响的文件**

**真实案例**：我在把本目录从"单文件"重构成"分类目录"时，
用 `Get-ChildItem *.md | Remove-Item` 清理旧文件——
结果把**同一批里刚新建的 `面试速查卡.md` 一起删掉了**（新文件也在顶层、也匹配 `*.md`）。

**发现方式**：不是我看出来的，是**刚写好的 `check_links.py` 当场报**
`✗ 缺少顶层文件：面试速查卡.md`。
**这就是"把约定做成机器检查"的价值——它在新方法第一次使用时就开始兜底了。**

**因此的纪律**：

| 场景 | 要求 |
|---|---|
| **批量删除/移动** | **先打印匹配到的清单并核对总数**，确认无误再执行；⛔ 不要直接 `Remove-Item` 通配符 |
| **重构/改名后** | **必须**跑 `check_links.py`（本目录的结构完整性检查就是为这类事故准备的） |
| **新建 + 清理同批发生** | 格外小心——**新文件往往也匹配"旧文件"的筛选条件** |

> **业务含义**：**通配符删除的危险不在"删错文件"，而在于它删除的是"当时恰好匹配的东西"**，
> 而你对"当时匹配了什么"的认知来自**上一次的目录状态**，不是执行那一刻的真实状态。
> 所以生产环境的 `DELETE` 也应当先 `SELECT COUNT(*)` 核对——**同一个道理，只是规模不同。**
