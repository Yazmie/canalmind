# 危害与做法

> 主题：[UTF8按ANSI读丢换行](README.md) ｜ 类别：[环境坑](../README.md) ｜ 返回总索引：[../../README.md](../../README.md)
> 危害**不是「行数不对」这么轻**——任何按行遍历 / 切分 / 计数都可能静默少处理数据；做法是**显式给编码**加**独立来源交叉确认**。

## 危害（⛔ 不是「行数不对」这么轻）

- 任何**按行遍历 / 切分 / 计数**的处理都可能**静默少处理数据**：只跑了前 22 条查询、只校验了 22 条记录，**没有任何一处会报错**。
- **「行数自检」会给出假的安全感**：两个**都按错误编码读**的脚本会互相印证（22 = 22），看起来完全一致 ✓——**一致的是同一个错误**。
- 同一段代码若换成「按行切分后写回产物」，错的就从**日志**变成**数据**；**危害大小取决于你在哪一步数它**。

## 做法

- **读 UTF-8 文本一律显式给编码**：`Get-Content <文件> -Encoding UTF8`，或改用 `[System.IO.File]::ReadAllLines` / `ReadAllText`（.NET API 默认 UTF-8，行为不随控制台代码页变）。
- ⛔ **不要用不带 `-Encoding` 的 `Get-Content` 去数行数或做行级处理**；⚠️ 也**别以为 `-Raw` 就安全**。
- **行数 / 条数这类「自检」必须由一个独立来源交叉确认**：本例的独立来源是**产物里的 `queryCount=32`** 与 **`[System.IO.File]` 的读法**——两个读法**互不依赖**才叫交叉确认；两个都按错编码读，只能互相印证同一个错误。
