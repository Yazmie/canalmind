# PowerShell 脚本的反引号陷阱（付费脚本的失败点落在最后一步）

> 类别：[环境坑](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **现象** | 脚本**正常退出、表格正常打印**，但输出文案里的文件名 `v2-rrf-rerank.json` 显示成 `2-rrf-rerank.json`、`rerankDegraded` 显示成 `erankDegraded`——**每处都少了恰好一个字符，且不报错**。 |
| **根因** | PowerShell 的**双引号** here-string `@"..."@` 里，反引号 `` ` `` 是**转义符**。我为做 Markdown 行内代码写的那对反引号里，`` `v `` 被当成转义序列吃掉、只剩 `v`。`AGENTS.md` §7.2 记过同一条陷阱（"反引号在双引号串里是转义符"），上次宿主是**命令行参数**，这次是 **here-string**——**同一个原因换了个外壳就认不出来了**。 |
| **⚠️ 为什么这条比普通错别字严重** | 被改写的**恰好是文档要引用的证据文件名**。`v2-rrf-rerank.json` 是本节唯一"改前语料旧产物、不可与新版并列"的那个标记物；文件名少一个字符 ⇒ **读者会去找一个不存在的文件**，或把警告误读成笔误。**损坏落在证据上**，比落在装饰文字上危险得多。 |
| **权威实测** | 把 `@"` / `"@` 换成**单引号**版 `@'` / `'@`（单引号 here-string **不解析任何转义、不插值**），重跑后文案逐字正确；并与 `-SkipPaidRun` 先空跑一遍核对输出。 |
| **最终写法** | ①**对外输出文案一律用单引号 here-string** `@'...'@`；只有**确需变量插值**时才用双引号版，且**里面不写反引号**。②需要行内代码感时，改用「」或直接裸写文件名，⛔ 不要为了排版方便引入反引号。 |
| **⚠️⚠️ 更贵的那个教训：付费脚本的失败点不许留在最后一步** | 同一次任务里我还踩到第二个"只在最后一步失败"：脚本末尾调 `compare_runs.py --run` 时**误传了 hits 产物而非 metrics 产物**，报「缺少键 label」——**而前面 40 次付费 LLM 调用已经发完了**。两个坑合起来说明一条规律：**付费脚本里，"花钱的调用"必须排在"所有零成本校验"之后**。 |
| **最终修法（可复用）** | ①给付费脚本加 **`-SkipPaidRun`** 开关：免费分支（指标重算、多臂对照、文案输出）可**反复空跑**，⛔ 不必为了让一处文案正确再花 40 次调用。②把**参数/产物路径/解析**三类校验**前置**到发起请求之前。③**先空跑、再付费**：`-SkipPaidRun` 已能跑通全链路，才允许去掉开关真跑。 |
| **可能被追问** | "你怎么保证脚本改完是对的？"→ 答：**静态层**用 PowerShell 自带 AST 解析器（`Parser::ParseFile`，零成本、能抓编码与转义）；**动态层**用 `-SkipPaidRun` 只跑免费分支。⛔ **不拿"执行一次没报错"当判据**——本次坑 2 恰恰是"执行成功但内容被改写"，而坑 1 是"包装器退出 0 但脚本根本没跑"（见[脚本文件BOM](脚本文件BOM.md)）。 |
