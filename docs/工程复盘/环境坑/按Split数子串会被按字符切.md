# 按 Split 数子串会被按字符切

> **一句话**：想数「某个子串在文本里出现几次」时写 `$t.Split($old)`——
> PowerShell 会把**一个字符串**隐式转成 `char[]`，落到 `Split(char[])` 重载上 ⇒ **按每个字符切**。
> 实测 `$old` 只是 10 个汉字，`$n` 却算出 **21272**（真实次数是 **1**）。

## 现场（2026-09-22，给 `docs/进度看板.md` 打补丁时）

```powershell
$old = '六项进度：**①⑥ 已完成**'
$n = ($t.Split($old).Count - 1)      # ⛔ 期望 1，实测 21272
```

`String.Split` **没有** `Split(string)` 这个重载；PowerShell 的类型转换把字符串当 `char[]`，
于是"分隔符"变成了「`六`、`项`、`进`、`度`、`：`、`*`…」这一串**单字符**，
整篇 1878 行的文档被切成一万多个片段。

**做法**：数出现次数用正则，别用 `Split`：

```powershell
$n = ([regex]::Matches($t, [regex]::Escape($old))).Count
```

## 真正值钱的部分：**这次没写坏文件，是因为写入前有断言**

同一轮里我踩了三个"脚本自己出错"的坑（本条 + 相对路径 + 回读判据），
但**没有一个文件被改坏**——因为我给每个补丁脚本都钉了同一条规矩：

> **逐处精确匹配 → 断言「恰好出现 1 次」 → 不满足就 `ABORT`，⛔ 一个文件都不写。**

实测两次触发 `ABORT`，两次都复核过**文件分毫未动**（`BOM`/`CR` 与残留计数都没变）。
⇒ **"断言 + 不满足就不写"比"小心地写"可靠**：它把"我以为"变成"机器验过"。
