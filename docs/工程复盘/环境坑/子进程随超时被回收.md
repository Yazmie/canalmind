# 子进程会随"超时被杀"的父命令一起被回收

> 类别：[环境坑](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **坑** | 我让临时 PG 集群挂在一条普通命令下启动。它**已正常运行 9 分钟**（日志显示 autovacuum 正常告警），但**那条命令超时被杀时，postgres 被连带杀死**——日志在 15:25 之后直接断掉。 |
| **为什么会连带** | 它是那条命令的**子进程**；父命令被终止时，**整棵进程树被一起回收**。 |
| **解法** | 用**独立的后台作业**持有长驻进程，不要挂在会被超时回收的命令下；验证脚本改为**只连不启动**（`-ConnectOnly`），服务器生命周期由外部作业管理。 |
| **实证** | 改成后台作业后，postgres 稳定存活，验证脚本一次跑通（索引命中、过滤场景对照全部拿到结果）。 |
| **业务含义** | **长驻进程的生命周期必须显式管理。** 把"服务"和"一次性任务"混在同一条命令的生命周期里，就会出现"任务结束、服务也没了"这种**看起来像服务崩溃、其实是进程树被回收**的假故障。 |
| **可能被追问** | "生产上也有这个问题吗？"→ 答：容器里同样有——**如果服务是 shell 的子进程而没有正确转发信号/用 `exec`，主进程退出会带走服务**。这与本机遇到的是同一类问题的不同规模。 |
