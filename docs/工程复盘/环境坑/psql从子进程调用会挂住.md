# psql 从子进程调用会挂住（它在等一个永远不会有人输入的口令）

> 类别：[环境坑](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **现象** | Python 脚本用 `subprocess.run([...psql...], capture_output=True)` 调 psql，**永久挂住**——harness 侧 **600 秒**超时、脚本内 **300 秒**超时都触发了。而且因为 Python 的 stdout 被**管道缓冲**，日志一片空白，看起来像"**什么都没做**"。**"挂起 + 无输出"是最难查的一种失败形态**：既没有现场，也没有错误。 |
| **第一步排查（走错了一条路）** | 本项目记录过"受限环境里用管道捕获另一个程序的输出会失败"的同类现象（Node.js `child_process` 用 `stdio: 'pipe'` 报 EPERM），于是**先怀疑"管道捕获受限"**，改成把 stdout/stderr **重定向到文件**——**仍然挂住**。**这一步排除了管道这条线**（但"写文件而不是走管道"这个写法保留了，理由见下）。 |
| **真正原因** | 子进程**没有被传入准备好的环境变量**（漏了 `env=`）。于是 psql 拿不到 `PGPASSWORD`，转去**弹口令提示**；而 **psql 的提示读的是控制台，不是 stdin**——所以 `stdin=subprocess.DEVNULL` **挡不住它**，命令就一直等一个**永远不会有人输入的密码**。 |
| **为什么难发现** | 因为"等口令"**不是错误、不是异常、也不是日志**，它只是**安静地等**。所有"看起来该有输出的地方"都是空的，于是注意力会被吸到"为什么没有输出"，而不是"**它在等什么**"。 |
| **修法** | ①**传给子进程 `env=`**（真因）；②给 psql 加 **`-w`**（never prompt）——口令缺失时**立刻报错**而不是挂起，把"**永久等待**"变成"**一条清楚的错误**"。 |
| **为什么"写文件"这个写法留着** | 即使它**不是**本次挂起的原因，它仍值得保留：`psql` 的输出写到 `backend/target/bm25-verify/*.out.csv` / `*.err.txt`，再由 Python 读回来——**进程结束之后现场还在**（管道里的内容会随进程消失），并且 `subprocess.run` 一律带 `timeout=300` 兜底。 |
| **配套的既有约定** | SQL **一律走 `psql -f <UTF-8 无 BOM 文件>`**，不用 `psql -c`：`-c` 传中文会被**控制台代码页**改坏，然后以"**查不到行**"的形式**静默失败**——又是一个"合法但错"。 |
| **可迁移的教训** | **"挂起 + 无输出"要优先怀疑子进程在等交互输入**，而不是网络 / SQL / 死锁。`stdin=DEVNULL` **不是万能挡板**——交互式程序可以绕过它去读控制台。让子进程"**宁失败不等待**"（互斥式开关，如 psql 的 `-w`）+ **显式超时**，比事后一步步 build 排查便宜得多。 |
| **⚠️ 这条记录当场抓出一条过时注释（已修）** | 写这条记录时发现：`verify_bm25.py` 类 `Db` 的 docstring **仍把根因写成"管道捕获受限"**，而真因只写在 `-w` 那处注释里——**代码是对的，类注释的理由是过时的**。**已随后改掉**：docstring 现在明确列三条——①真因是漏传 `env=`；②"写文件不走管道"是**另一个**理由、**不是**本次挂起的原因；③`-w` + `timeout` 让失败表现为清楚报错。**顺序值得记下来：先有代码，再有复盘，复盘反过来纠正了代码的注释。** 这与 [../诚实记录/公开更正自己的错误结论.md](../诚实记录/公开更正自己的错误结论/README.md) 是同一类要求：**理由被推翻后，注释也必须跟着改。** |
| **可核对锚点** | `backend/scripts/verify_bm25.py`：类 `Db` 的 docstring、`psql_env()`（把 `PGPASSWORD` 放进 `env`、不进命令行）、`Db.__init__` 里的 `-w`、`Db.rows()`（`stdout=out` / `stderr=errh` / `env=self.env` / `stdin=subprocess.DEVNULL` / `timeout=300`，SQL 先 `write_bytes` 成 UTF-8 无 BOM 再 `-f`）。 |
