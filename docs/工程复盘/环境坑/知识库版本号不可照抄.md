# 文档里的版本号不可照抄

> 类别：[环境坑](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **坑** | 知识库 `AI 可观测性与 Trace` 第 420 行以 **"Spring AI 2.0.0 + Spring Boot 4.x"** 为例；实测本机 Maven 仓库**只有 1.0.0 / 1.1.0 / 1.1.2，不存在 2.x**。 |
| **查证方式** | 遍历 `D:\MavenRepo\maven-3.9.12\org\springframework\ai` 全量目录，并读 `spring-ai-starter-model-deepseek-1.1.2.pom` 确认它依赖 Spring Boot 3.5.8 / Spring Framework 6.2.14。 |
| **结论** | 项目实际选定 **Spring Boot 3.5.9 + Spring AI 1.1.2**（决策 C-16），并写入 `AGENTS.md` §7 版本记录。 |
| **为什么值得记** | 知识库**明确提醒过**"不同版本的依赖和属性可能有调整，升级时以对应版本官方文档为准"——**但提醒本身也是文字，很容易被跳过**。 |
| **业务含义** | **技术文档里的版本号是"写作时的快照"，不是可用性证明。** 引入任何依赖前要以**官方仓库 / 本地仓库的实测**为准。这条对"照教程搭环境"的新人尤其致命——教程过期会让你把时间花在排查"为什么属性不生效"上。 |
| **可能被追问** | "怎么系统性避免？"→ 答：**把版本查证当成一个显式步骤并留档**（本项目的 `AGENTS.md` §7 版本记录表就是干这个的），而不是"用的时候再说"。 |
