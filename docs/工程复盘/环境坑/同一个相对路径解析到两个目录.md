# 同一个相对路径，在 PowerShell 与 .NET 里指向两个目录

> 类别：[环境坑](README.md) ｜ 返回总索引：[../README.md](../README.md)

**一句话**：`Set-Location` 只改 **PowerShell** 的当前位置；`[System.IO.File]::ReadAllBytes` 这类 .NET 静态方法用的是**进程当前目录**。
两者可以**不一样**，于是同一个相对路径会解析到**两个不同的目录**。

## 最小复现（本机 PowerShell 5.1 实测）

```powershell
Set-Location 'D:\Project_AI\canalmind'
(Get-Location).Path                           # D:\Project_AI\canalmind
[System.IO.Directory]::GetCurrentDirectory()   # D:\Project_AI      ← 不一样
```

## 现场症状（一次真实的假失败）

我用 `[System.IO.File]::ReadAllBytes` 自查两个刚写好的文件，
结果报 `DirectoryNotFoundException: Could not find a part of the path 'D:\Project_AI\docs\…'`。
⚠️ 它**看起来像「文件不存在」**，实际是**目录解析错了**——真文件在 `canalmind\docs\…` 下，一直都在。
同一次调用里 Python 段用的是绝对路径 ⇒ `exit=0` **全绿**；PowerShell 段用相对路径 ⇒ **全红** ⇒ 一半成功一半失败。

## 判据

| # | 判据 |
|---|---|
| ① | 脚本里凡用 `[System.IO.*]::` 读写文件，**一律传绝对路径**（别依赖 `Set-Location`） |
| ② | 遇到「找不到文件」先同时打印 `(Get-Location).Path` 与 `[System.IO.Directory]::GetCurrentDirectory()`，两者不一致就是它 |
| ③ | ⛔ 不要用 `[System.IO.Directory]::SetCurrentDirectory()` 去绕——它改的是**进程级**状态，会影响同进程里其它代码 |
