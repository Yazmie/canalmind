# "知识库没有覆盖" —— 我凭印象下了一个错的结论

> 类别：[工程方法](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **问题** | 我在提「Embedding 用本地模型还是 API」这个决策时，声称"**知识库对此没有覆盖**"。 |
| **实际情况** | **完全错了。** 知识库有直接覆盖：`RAG 基础概念：检索、生成与工程取舍.md` 第 95–103、111 行，以及 `RAG 知识库文档如何更新…….md` 第 27–45、302 行。 |
| **怎么发现的** | 写决策记录、需要给出"文件名 + 行号"作为依据时，我去做了一次**全库关键词检索**——才发现覆盖得很完整。 |
| **怎么解决的** | ①在 `docs/DECISIONS.md` 里**公开更正自己的结论**（见[诚实记录/公开更正自己的错误结论](../诚实记录/公开更正自己的错误结论/README.md)）；②把教训固化成流程（已写入 `AGENTS.md` §4.1）：**下"无覆盖"结论之前，必须先做一次全文关键词搜索**。 |
| **业务含义** | 这条对**新人/新领域**尤其普适：**"我没找到"和"它不存在"是两个完全不同的判断。** 前者是检索行为，后者是事实断言——**事实断言需要证据，而检索行为需要方法。** |
| **可能被追问** | "你会怎么避免？"→ 答：把"无覆盖"当成**需要举证的主张**（要说明搜了哪些词、哪几个文件），而不是凭记忆的即时判断。 |
| **⚠️ 对外讲述注意** | 这里引用的知识库**不入 git**、外部无法核对。讲的时候要**复述结论本身**，别只给一个对方看不到的引用——见[../README.md](../README.md) 的可核查性说明。 |
