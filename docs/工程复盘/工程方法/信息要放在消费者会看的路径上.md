# 信息要放在"消费者会去看"的路径上

> 类别：[工程方法](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **问题** | 语料 `03` 里有「闸室水位」「允许最大吃水 4.20 米」「富余水深 0.30 米」等表述，而本项目数据库**没有水深字段**。**两个不同的子代理、先后各提了一次**这个"矛盾"。 |
| **我最初的判断** | 我认为这不是矛盾（水深是**结构尺寸**、水位是**动态运行条件**、吃水是**运行限值**，`03` 第六条本就写明"不规定固定的闸室水深刻度"），并且**已经记进了 `docs/DECISIONS.md`**。 |
| **我判断错的地方** | 我的**结论**没错，但**位置**错了：复核语料的人**不会去翻决策日志**。所以同一个疑问被反复提出——**这不是噪音，这是信号**。 |
| **怎么解决的** | 在 `docs/规则语料/README.md` 新增 **§4.2**，用一张表把「闸室水深（⛔ 不存在）」与「运行水位 / 允许最大吃水 / 富余水深（✅ 合理存在）」分清，并写明**越界条件**（不得出现"闸室水深为 X 米"这类给定结构数值的写法）；同时在**校验脚本的规则注释里**写清为什么这三处放行、哪里才报错。 |
| **业务含义** | **信息要放在"会消费它的人"所在的路径上。** 写在决策日志里只对"做决策的人"有效；要阻止复核者重复提问，信息必须放在**他们实际会打开的那个文件**里。 |
| **可能被追问** | "同一个问题被问两次说明什么？"→ 答：说明**我的沟通方式有缺陷，而不是对方理解力有问题**。重复出现的问题要当作**文档放置位置的缺陷**来修，而不是重复解释。 |
| **更广的推论** | 同一个道理也适用于本目录：`面试速查卡.md` 之所以要**独立可读**（不依赖其它条目），就是因为**面试前我只会打开它**。 |
