# 验证动作自己出错的三次实测（例 ⑪）

> 类别：[工程方法](../README.md) ｜ 主题：[验证工具本身也要被验证](README.md)
> 上下文：**C-58**「模型调用的限流 / 退避重试 / 降级」最小可验证版（2026-09-22）

**这一条记的不是"结论错了"，而是"取证动作本身错了"** —— 三次都发生在同一个下午，方向还各不相同：
两次**假成功**（工具说改了、调用说成功了，其实都没有），一次**假失败**（断言说属性不在，其实在）。
判据：**凡"验证"这一步，都要能被另一条独立证据复核**；⛔ 自己那句 print 不算证据。

## ① 凭印象写框架接口签名 ⇒ 编译当场不认（`javap` 才是权威）

要给 `ResponseErrorHandler` 覆写错误处理方法，我"照着印象"写了
`handleError(ClientHttpRequest, ClientHttpResponse)` 并加 `@Override` ⇒ 编译报
**「方法不会覆盖或实现超类型的方法」**。`javap` 实测 spring-web **6.2.15** 的接口上只有三个方法：
`hasError(ClientHttpResponse)`、`handleError(URI, HttpMethod, ClientHttpResponse)`（`default`）、
`handleError(ClientHttpResponse)`（`default`）——**我写的那个签名根本不存在**。

⇒ 用框架接口前先 `javap` 看一眼，比记忆便宜；与例 ⑩（取错 jar 版本）同属"**输入源不可靠**"。

## ② 覆写错了重载 ⇒ 429 被静默伪装成"模型答了个空"（假成功，且是最危险的方向）

只覆写**三参数**那个 `default` 重载时，实测（JDK `HttpServer` 桩 + 真 `DeepSeekApi`）：
429 **不抛异常**，调用方拿到一个**空的 `ChatResponse`**（`generations` 为空）——
"被限流"被伪装成了"成功返回"。
只覆写**单参数**那个（实测才是 RestClient 真正走的那条）⇒ 异常**原样穿透**，能读到
`429 TOO_MANY_REQUESTS` 与 `retry-after=1`。

⚠️ 这与 [空作答被当成成功作答](空作答被当成成功作答.md) 是**同一个形状**：系统没报错，
只是把"没办成"说成了"办成了"。
⇒ 守住它的不是注释，而是一条断言：`LlmCallGuardTest` 用桩回放 429，断言**必须**抛
`LlmHttpFailure(429)` 且 `Retry-After` 读得到（哪天框架改了调用路径，这条会红，而不是悄悄退回空应答）。

## ③ 断言读法与改文件脚本：一个假失败、一个假成功

- **假失败（读法）**：读 Span 属性时用了 `ctx.getLowCardinalityKeyValue("键")` ⇒ 对**观察启动之后才写入**的键
  返回 `null`，用例以 NPE 红掉；而同一个 context 的聚合视图 `getLowCardinalityKeyValues()` 里明明有它。
  ⇒ 本项目既有测试（`AiObservabilityTest` / `AiSpanTreeTest` / `LlmRerankerTest`）读的都是聚合视图，**随大流即可**。
- **假成功（改法）**：用 PowerShell 调 `.NET` 的 `[System.IO.File]::ReadAllText('src\main\...')` 改文件——
  它按**进程工作目录**（不是 `Set-Location` 之后的位置）解析相对路径，两个文件操作都抛异常；
  而我脚本里的 `if ($t -notmatch ...)` 对 `$null` 求值为真，**照样打印了「已插入 import」**。
  ⇒ 改用 `git status --short` 复核，文件根本一个字没变。
- **假成功（改法之二：追加写成了替换）**：用"锚定整行 + 替换"的方式**追加**表格行时，我把**旧行整段**
  填进了 `old_string` ⇒ 新行**覆盖**旧行，**静默删掉了既有内容**（本轮在 import 行与 `面试速查卡`
  的表格行上各犯一次，两次都是靠**独立的复核动作**——`git status` / 重新读那一行——才发现）。
  ⇒ 追加类改动的正确形状是 `new_string = 旧内容 + 换行 + 新内容`，且**改完必须重新读那个位置**。

**共同点**：三次都不是"知识不够"，而是**把一次动作的输出当成了动作本身的结果**——
编译器的报错、桩返回的空对象、自己脚本的 print，三者都可能与事实相反。
