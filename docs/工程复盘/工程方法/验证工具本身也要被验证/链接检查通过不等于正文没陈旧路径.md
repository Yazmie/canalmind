# 「链接检查通过」不等于「正文没有陈旧路径」

> 类别：[工程方法](../README.md) ｜ 主题索引：[README.md](README.md) ｜ 总索引：[../../README.md](../../README.md)

**一句话**：改名/拆分后**链接**被自检兜住了，但**正文里当文字写的老路径**它看不见（本轮真漏 2 处）；更要紧的是——**这个自检器当时报出的行号也是错的**。

## 实测①：45 处链接全修好、自检 PASS，正文仍留着 2 处旧路径

拆分后我按「解析后的真实路径」重写链接：45 处 ✓，`check_links.py` 报 **问题 0 项 / `[PASS]`**。
但再用 grep 找「6 个旧条目名 + `.md`」，**命中 15 处**：

| 类型 | 处数 | 判定 |
|---|---|---|
| `[旧名](../新目录/README.md)` —— 链接**文字**保留旧名、**目标**指向新目录 | 13 | ✅ 合格（文字是标题，不必等于文件名） |
| **正文里的裸路径**（无链接语法） | **2** | ⛔ 陈旧 → 已修 |

漏掉的原因值得记：我的重写只按 **`docs/` 开头的全路径**匹配，而这 2 处写成「相对 `docs/`」的形式（如 `工程复盘/诚实记录/公开更正自己的错误结论.md`）⇒ **规则覆盖不到**。

⇒ 改名/移动之后要查**两样**：**链接**（自检器管）+ **文字**（grep 旧名管）。只查一样就会漏。

## 实测②：自检器报出的**行号**当时是错的（已修）

`check_links.py` 里 `INLINE_CODE = re.compile(r"`[^`]*`")`——字符类**不排除换行**，
而 Markdown 的行内代码**不跨行**，于是它会一路吞到**下一个**反引号（可能在几十行之后），
把中间的 `\n` 一起换成空格 ⇒ **行数变少 ⇒ 报出的行号整体前移**。（它的 docstring 当时还写着「保持行数不变以便行号仍然准确」——**注释说了，代码没做到**。）

**对照实验（不是只跑一遍看它对）**：把目录拷到临时区，在**真实第 59 行**注入一条坏链：

| 版本 | 报出的行号 | 是否仍检出 |
|---|---|---|
| 旧写法 `[^`]*` | **52** ⛔（差 7 行） | 检出 ✓ |
| 修后 `[^`\n]*` | **59** ✓ | 检出 ✓（1 项，未削弱） |

⇒ 判据：**校验器报出的行号也要抽查**。否则按它给的行号去改，改的是**别的位置**。
