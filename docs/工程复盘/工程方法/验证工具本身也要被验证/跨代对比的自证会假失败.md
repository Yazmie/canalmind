# 跨代对比的自证会「假失败」

> 类别：[工程方法](../README.md) ｜ 主题索引：[README.md](README.md) ｜ 总索引：[../../README.md](../../README.md)

**一句话**：一条**量化自证**（"A − B 应等于 C"）成立的前提是**A 与 B 吃同一份输入**；
输入换了而检查没跟着换，它会**报出一个看起来像被测对象坏了**的 FAIL。

## 实测（2026-09-21，语料修改后重灌 BM25）

`verify_bm25.py` 检查项 6 的等式是：**「rules-v1 词元数 − rules-v2 词元数 == 本份语料的列表编号数」**，
用来证明"剥离列表编号"这条规则**只剥了该剥的**（不多不少）。改语料后重灌，它报：

```
错误 1 项，警告 1 项
[FAIL] BM25 通道未通过独立复核
  ✗ 词元减少量 1102 ≠ 语料里实测的列表编号数 1171
```

**但通道没坏**——把四个数摆开就看出是**世代错配**：

| 量 | 值 | 来源世代 |
|---|---|---|
| `rules-v1` 词元总数 | 35764 | **改前**语料（档案建于 09-20 22:18） |
| `rules-v2` 词元总数（改前） | 34594 | 改前 ⇒ 改前等式 **35764 − 34594 = 1170 = 改前编号 1170 处 ✓ 成立** |
| `rules-v2` 词元总数（改后） | 34662 | **改后**语料（本次重灌） |
| 脚本拿它去比的「编号数」 | 1171 | **改后**语料（=`rag_chunk` 当前内容） |

于是 **1102 = 1170 − 68**：差额 68 就是语料改动带进来的词元增量。
**等式没错，是两端各自属于不同世代**。

## 修法：把「凭什么成立」写成可判定的条件

改为**先判世代再决定比不比**，判据用**库内可观测的时间戳**（不需要人工开关、也不需要改表结构）：

```sql
(SELECT max(updated_at) FROM rag_chunk) > (SELECT created_at FROM rag_token_profile WHERE profile_name='…rules-v1…')
```

为真就**如实跳过并打印四个数字 + 两个时间**，而不是给出一个假的 FAIL。

⚠️ **这里有个必须守住的边界**：不能因为"报错很烦"就**悄悄降级成 warning**——
那是本主题最忌讳的"靠放宽检查换绿"。所以跳过时**必须把数字全部打出来**，
让读者能自己复算"差额 = 语料改动量"，而不是只看到一句"已跳过"。

## 同一脚本的第二处：在**结论之前**崩掉的打印

同一轮还踩到：脚本末尾用 `args.json.relative_to(ROOT)` 打印产物路径，
调用方传**相对路径**时抛 `ValueError`——而且它发生在**所有比对都做完、结论即将打印时**：

```
打分复核：6 条探针 ｜ 排名不一致 0 ｜ 分数最大绝对差 3.553e-15   ← 全部通过
ValueError: '…' is not in the subpath of '…'                    ← 然后崩，退出码 1
```

**表现与"复核失败"完全一样**。已改成 `_shown()`（解析后取相对路径，失败就原样打印）。

## 可复用的三条判据

| # | 判据 | 本次怎么用 |
|---|---|---|
| ① | **"跨 X 的对比"必须显式写出 X 的身份** | 等式两端分属两次入库 ⇒ 先比世代；同理"跨版本/跨机器/跨运行"的对照都适用 |
| ② | **别让打印语句有失败路径** | 收尾的 `relative_to` / 取字段 / 格式化都可能抛；**它一抛，前面全绿也会变成失败** |
| ③ | **假 FAIL 与假 PASS 是一对，都要防** | 假 PASS 让人漏掉真问题，假 FAIL 让人去改本来正确的东西（本项目 [规则过严会把正确的东西判成错的](../规则过严会把正确的东西判成错的.md) 是同一族） |
