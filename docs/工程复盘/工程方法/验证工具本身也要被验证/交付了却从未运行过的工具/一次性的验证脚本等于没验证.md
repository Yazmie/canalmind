# 一次性的验证脚本等于没验证

> [交付了却从未运行过的工具](README.md) ｜ [验证工具本身也要被验证](../README.md) ｜ [工程方法](../../README.md) ｜ [返回总索引](../../../README.md)
> 上一个条目讲**"交付了却从没跑过"**；这一条讲它的孪生形态：**跑过、也真拿到了数，然后脚本被删了。**

## 实测（2026-09-23，交付 `frontend/index.html`）

| 项 | 内容 |
|---|---|
| **当时怎么做的** | 页面交付前我写了三个**临时脚本**：SSE 解码往返、假 DOM 空跑渲染函数、真 Chrome 量几何。**都跑过、都通过、数字也写进了看板**（"10 组往返 / 11 份渲染产物 / 侧边栏 240 / 溢出 0"）。因为判定它们是"一次性验证"，**跑完就把临时目录删掉了**。 |
| **后果 ①：结论不可复查** | "前端现在是对的"这句话**再也不能被独立复核**——别人跑不了，我下个会话也得重写一遍。⚠️ **写进文档的数字是真数字，但没有能再产出这些数字的工具**。 |
| **后果 ②：改坏不会变红** | 这批断言**不构成回归护栏**。同一份看板里别的模块都有能跑的命令（`mvn test`、`verify_golden_set.py`），前端这一块**只有一段描述**。 |
| **后果 ③（最贵的一条）：同一批坑被重踩一遍** | 下一轮我要改会话隔离，需要重新量几何 ⇒ 临时脚本已经没了，只能**从零重写**。重写时我：①先用了 `window.resizeTo()`（headless 下**无效**，实测两次视口完全一样，差点把重复测量当独立测量）；②再次被"**受限沙箱下脚本输出会丢**"困住（连跑多次都无输出，⚠️ 该现象的**机制我至今没隔离**）。⚠️ **这两个坑的结论当时就写在 [看不见图时怎么验界面](../../看不见图时怎么验界面.md) 里**（该文实测表里明写用 `Emulation.setDeviceMetricsOverride`）——**我读过那段文档，还是重踩了**。⇒ **文字结论挡不住重踩，能跑的脚本才挡得住。** |
| **修法（已做）** | 把断言**搬进仓库**并接进日常链路：`frontend/test/check_frontend.js`（零依赖 Node，**208 条断言**）＋ `frontend/test/check_geometry.js`（真 Chrome，**50 条断言**）；前者**接进 `backend/scripts/demo.ps1`**（本机没装 node 时 `[警告]` 明说跳过，⛔ 不静默跳过）。详细实测见 `docs/进度看板.md` §0.4.13b。 |
| **可复用的判据** | **"一次性验证"与"没验证"的差别只维持到下一个会话。** 判断要不要入库，问三句：①**下次改坏了，它会变红吗？**②**别人能跑吗？**③**我能不重写就再跑一次吗？**——三句里有一句是"不能"，它就该进仓库（哪怕只是个零依赖脚本）。 |
| **⚠️ 反过来也要说清（别把它读成"什么都得入库"）** | ⛔ **不是所有验证都必须入库**：需要**付费调用**、或需要特定人肉环境（如本机 Chrome + 更宽权限）的验证，可以留在文档里**当一次性证据**——但那时必须**把"这是一次性证据、⛔ 没有回归护栏"写清楚**，不能让人误以为随时可复跑。本条的价值是：**别把"跑过一次"升级成"有护栏"。** |
