# 看不见图时怎么验界面

> 类别：[工程方法](README.md) ｜ 返回总索引：[../README.md](../README.md)

**一句话**：这次交付"**看**一眼页面"才算完成，而我**读不了图**（模型不带视觉）、视觉桥又 **429**、
`--dump-dom` 还**返回空**——最后是把"看"换成**用 CDP 把几何量当文本取回来**，才拿到可断言的证据。

## 实测（2026-09-23，交付 `frontend/index.html`）

四条路，前三死一活，报错都照抄：

| 尝试 | 结果 |
|---|---|
| `read_image` 读自己刚截的 PNG | `model "…" does not declare image input` —— **能力边界**，不是环境故障 |
| `modlens_read_image`（视觉桥） | `429 该模型当前访问量过大` |
| `chrome --headless=new --dump-dom` | **stdout 0 字节**（同一个构建里 `--screenshot` 出图正常） |
| `chrome --screenshot` | 拿到了 106 KB 的 PNG，**但我读不了** ⇒ **有产物 ≠ 有证据** |
| **`--remote-debugging-port` + Node 内置 `fetch`/`WebSocket` 走 CDP `Runtime.evaluate`** | ✅ 让页面**自己把 `getBoundingClientRect()` 报回来**；一次跑两个视口宽（`Emulation.setDeviceMetricsOverride`） |

拿回来的数（1440 与 1200 两档都测）：

- 侧边栏 `w=240`、顶栏 `h=52`、主区起点 `x=240`
- 输入区 `bottom=900` **= 视口高**（贴底且完全在视口内）、对话区 `bottom ≤ 输入区顶`
- `doc.scrollWidth == clientWidth`（两档都相等）⇒ **无横向滚动条**；`body *` 里**右侧溢出元素 0 个**
- 金额元素 `fontSize=22px` / `fontWeight=700` / `color=rgb(183,121,31)` / `fontFamily` 命中 mono

## 可复用的四条判据

| # | 判据 | 本次怎么用 |
|---|---|---|
| ① | **先定"能自动断言的性质"，再谈"看起来对不对"** | 溢出元素数 `=0`、`scrollWidth==clientWidth`、`bottom==视口高`、颜色/字号**精确值**——全是布尔量，不靠眼睛 |
| ② | **把"渲染链路能跑"与"布局对不对"拆成两次验证** | 先用 Node 假 DOM 空跑页面的渲染函数（**不需要浏览器、不需要视觉**）；再用真浏览器量几何 |
| ③ | **断言里必须带"反例"项** | `不得出现 undefined`、`不得出现 NaN`、`不得出现 **`（强调标记漏到页面）——这三条各抓到真缺陷；只断言"含有期望值"会全绿 |
| ④ | **每个死路都留原始报错** | ⛔ 别把"我读不到"讲成"页面没问题"；同时说清哪一条是**能力边界**（读不了图）、哪一条是工具故障（`--dump-dom` 空） |

## 代价

若停在"截图成功、106 KB"就收工，我对"**最小宽度 1200px 不许挤**"这条明确验收点
**一个字的证据都没有**——而它恰恰是用户提的要求。
⇒ ⚠️ **"有产物"不等于"有证据"**：把产物换成**可断言的性质**，才算验证。
