# 验证工具本身也要被验证

> 类别：[工程方法](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **核心** | 用来诊断问题的**探针、脚本、正则、审计器**，本身就是会出错的一环。**探针给出"结论"之前，必须先证明探针自己是对的。** 否则你不是在测量系统，而是在测量自己的工具。 |
| **实测例子 ①** | 我用 Python 复核 Java 正则 `^###\s+(第…条)\s*$`，对 `"### 第一条 目的"` 得到 **不匹配**，据此断言"Java 里的双反斜杠是 bug"。真相是 **Python 的 `$` 语义**：`re.match` 的 `$` 只在绝对末尾（或末尾换行前）成立，测试串不满足，于是**探针错了，系统没错**。<br>教训：**跨语言复核正则时，`$`/`\Z`/`matches` 的语义差异足以制造假结论**；Python 探针测 Java 正则，本身就是不可靠的。 |
| **实测例子 ②** | 我写了一个独立探针来验证超长条的再拆分，探针里把条标题写成了 **ASCII**（形如 `### 第四条 LONG`）。切分器当然不认，于是"切出 0 块"。我据此**误判为产品 bug**，其实**是探针的输入不合规**。<br>教训：探针的输入必须与**真实数据同构**（真实中文、真实元数据块）；否则它测的不是产品。 |
| **实测例子 ③** | 我一度写了一个"非法转义审计器"，它的判定模型只看**最后一个反斜杠的后继字符**，于是把"被误改成双反斜杠的换行"判为合法，打印出**"非法转义总数: 0"** 这个假 PASS。<br>教训：见[检查有效性必须被验证](检查有效性必须被验证.md)——**审计器也要先被审计**。 |
| **代价** | 例子 ① 的假结论让我跑了一个**全局反斜杠替换脚本**，直接造成了[转义与写入层的静默损坏](转义与写入层的静默损坏.md)：4 个文件、31 处被改坏，随后又一次"回滚"**过度纠正**，把真正的换行字符字面量也改坏。**一次假结论 → 两轮互相抵消的错误修复 → 数小时排查。** |
| **正确姿势** | ①**优先用被测语言自己写探针**，别用另一种语言模拟它的语义；②探针的输入要**并排打印出来核对**（我后面改用"码点/十六进制 dump"，立刻定位到 `005C 006E`）；③**结论要有可复现的对照实验**（`EscCompare.java` 那种 A/B 两个常量并排比较），而不是单次观察；④**编辑类脚本一律禁止全局替换**，改为逐处定位 + 逐处断言，最后用"编译 + 跑测试"作为最终 oracle。 |
| **业务含义** | 生产排障时，"我的诊断脚本说是 X"与"系统实际是 X"是两件事。**先花五分钟验证探针，能省掉几小时的错误修复**——尤其当修复手段本身是破坏性的时候。 |
| **可能被追问** | "你怎么判断该信探针还是信系统？"→ 答：**找两个独立的 oracle**。例如本轮的最终判据不是任何脚本的输出，而是：①`javap -v` 看常量池原始字节；②干净重建后**跑测试**看绿不绿；③并排 A/B 对照实验。三者一致才下结论。 |

## 实测例子 ④（Golden Set L2 这一轮）：给**指标脚本**加 `--selftest`

> 上面三个例子是"探针查**别人**的错"；这一条是**度量工具自证**——它算错了同样不报错，只会让"增益"看起来合理。

| 项 | 内容 |
|---|---|
| **做法** | `backend/scripts/eval_retrieval.py` 里加了 `--selftest`（实现为函数 `selftest()`，⛔ **锚点认函数名不认行号**——该脚本仍在增长）：构造 **4 条题**（gold 均为单个 chunk，命中名次分别为 **1 / 5 / 30 / 未命中**），**手算**每一档指标的期望值，再断言指标实现算出的数与之一致。 |
| **实测结果** | `python backend/scripts/eval_retrieval.py --selftest` **退出码 0**，逐项：`HitRate@1=0.25`、`HitRate@5=0.5`、`HitRate@30=0.75`、`Precision@5=0.1`、`Precision@30=0.025`、`MRR@30=0.308333`、`Precision@m=0.25`、`allGoldRecalledAtTopK=0.75`——与手算期望完全一致。 |
| **为什么值得** | 指标算错**不报错**：`Recall@k` 换了分母、`MRR` 忘了"未命中记 0"，都只会让数字"看起来合理"。而本项目后续所有增益结论（RRF 融合 / Rerank / 三档 Top-K）**都以这些数字为准**。 |
| **与探针的区别** | 探针的判据常来自"另一个实现"，而 `--selftest` 的判据来自**手算的期望值**——**独立于实现**，所以它证明的是"实现符合定义"，不是"两个实现彼此一致"。 |
| **相关** | [用合成输入先空跑评测链路](用合成输入先空跑评测链路.md)（同一轮的另一半：空跑管 I/O 路径，自检管指标口径）｜[审计结论也要逐条核验](审计结论也要逐条核验.md)（同一族的下一步：**一个会写自然语言的复核者也是「工具」**——它的 23 条结论里至少 3 条是错的，照搬就会把审计的错改成我的错） |

## 实测例子 ⑤（2026-09-21）：查重探针是**子串**匹配，于是误报一个「重复编号」

> 前四条错在探针的**语义**、**输入**与**范围**；这一条错在探针的**匹配方式**——它连「一个编号有没有重复」这种看起来最客观的查重都答错了。

**当时的探针（⛔ 子串匹配，错就错在这里；`D` 是读入数据包全文后的字符串）**：

```python
D.find("## 8.8")     # 子串查找：`### 8.8` 这个字符串自己也含这个子串 ⇒ 命中
```

| 项 | 内容 |
|---|---|
| **当时我做了什么** | 数据包 `backend/target/eval/v2_datapack.md` 里**本来就有**一节编号为 `### 8.8`（重排偶发降级的诊断配方）。我新增的那一节**也想编成 8.8**，为了「查重」我用了上面这个**子串查找**。 |
| **工具给了我什么** | 一次**命中**（`find` 返回一个合法位置）——因为 `### 8.8` **自己就包含** `## 8.8` 这个子串。输出看起来完全像「确实重号了」。 |
| **我据此发出了什么结论** | 「**差点出现两个 8.8**」——一个**关于数据包存在编号冲突**的缺陷结论，方向指向**数据包**。 |
| **真相是什么** | **编号从未重复**：一个是 `### 8.8`，我新增的那一节实际写成了 `## 8.9`。真正的问题只有一件——**我那一节的层级高了一级**（`##` 应为 `###`，否则会截断 `##` 那一节），已改。<br>⚠️ 更值得记的是**误报把真问题换掉了**：探针把「**我自己层级写错**」渲染成了「**数据包编号冲突**」——**是我自己的错，却被记到了数据包头上**。 |
| **留痕位置（可核对）** | 数据包 `backend/target/eval/v2_datapack.md` 的 **§8.9 小节开头**那条以「留痕」开头的说明里，逐字留着这次的探针写法、错误结论与更正后的判据。⚠️ 该文件是**生成产物、不入 git**，故它只能作**本机证据**，⛔ 不能当长期锚点。 |
| **可复用的纪律** | **查重 / 查存在必须锚定「行首 + 层级」，⛔ 不用子串**——该写的是 `(?m)^### 8\.`（`^` 锚行首、层级写全、`\.` 转义点号），而不是上面那种 `D.find` 子串写法；**子串查找既会误报**（`### 8.8` 被算成 `## 8.8` 的命中），**也会漏报**（层级、空格、点号写法一变就找不到——而「层级」恰恰是本次真正的缺陷）。 |
| **同族与相关** | [局部搜索不能支撑否定结论](局部搜索不能支撑否定结论.md)：那篇讲「**没搜到**不能当事实」（漏报 + 范围不全），这条讲「**搜到了**也不能当事实」（误报）——**命中同样是工具的输出，不是事实**｜[检查有效性必须被验证](检查有效性必须被验证.md)：**探针也要做「注入」测试**——在「真的重号」上必须报出来，在「仅子串相同」上必须不报。 |

## 实测例子 ⑥（同一会话）：我自己写的核对脚本，是一个**假 PASS**

> 上一条是探针**误报**；这一条更贵——检查器**谎报通过**。误报会让人去查一个不存在的问题，**假 PASS 会让人以为问题已经查完了**。

| 项 | 内容 |
|---|---|
| **当时我做了什么** | 为核对数据包里那张**三臂对照表**（`ctx10-norank` / `ctx10-rerank` / `ctx30-rerank`，含 `HitRate@3` 等指标行）的数字与产物是否一致，我当场写了一个 **Python 一次性核对脚本**。⚠️ 这里用**表里的臂名**做锚点而不是小节号——因为本轮恰好出过「小节号差点被我编重」的事（见上一条⑤），**小节号是这里最不稳的锚点**。 |
| **工具给了我什么** | 两样**互相打脸**的东西：① 正文里打印出**一堆「不符」**；② **最后一行**打印 `核了 66 格，不符 0 格`。 |
| **我据此发出了什么结论** | 先被那堆「不符」引向「**有一批数字对不上**」；再看末行，又会被引向「**都对上了**」。⚠️ **同一份输出同时支持两个相反的结论**——这本身就说明它不是一把尺子。 |
| **真相是什么** | 脚本有两个缺陷：<br>① **没有限定范围**——它把文档里**别的小节**（四路对照表）的表行也拉进来比对，于是那堆「不符」**全是误报**；<br>② **更严重：最后一行是无条件打印**——`0` 是**写死在打印语句里的字面量**，**不管前面有没有不符，它永远说「不符 0 格」**。<br>⇒ 这个脚本**既会误报、也会谎报通过**。⚠️ 发现②的方式是**我自己读输出**：前面明明打印了 ⛔ 行，末行却说 0 不符——**如果我只扫末行，它会一直绿下去**。 |
| **修法（已落地；逐字片段见下方代码块）** | ① **先断言定位到了正确对象**；② **限定到目标小节**（只比目标表格，不碰别的小节）；③ **真实计数**：比对不符时 `mism += 1`，末行由 `mism` 渲染；④ 加**自证断言**：核到的格数太少，就判「**检查器失效**」，而不是判「都对了」。 |

**修好之后的四行关键改动（逐字片段，非整脚本）**：

```python
assert "ctx10-norank" in sec                   # ① 先证明我定位到了正确对象
mism += 1                                      # ③ 真实计数（不再写死 0）
print(f"核了 {checked} 格，不符 {mism} 格")      # 末行由 mism 生成
assert checked >= 20                           # ④ 自证：核到的格数太少 ⇒ 判「检查器失效」
```

| 项 | 内容 |
|---|---|
| **⭐ 修好检查器之后，它立刻抓到了我自己的一个真错** | 变成**真检查器**之后，**同一批数据**当场查出：我在数据包里把 `ctx10-norank` 这一臂的 `HitRate@3` 写成了 **0.8125**，而产物里是 **0.8438**（`backend/target/eval/metrics-item6-ctx10-norank.json` 的原始值 `0.84375`）⇒ **已改**。<br>**这就是「假 PASS 被修掉之后立刻产生价值」的直接证据**：**同一个脚本、同一批数据**——修之前它说「不符 0 格」（把真错藏在绿里），修之后它**当场把真错指出来**。⇒ 反过来说：**那一天里这个脚本本该抓到的错，只能靠我自己用眼睛读出来**。 |
| **可复用的纪律** | ① **检查器必须先自证**：断言「我定位到了正确对象」「我核到的格数够多」，并让**汇总数字来自计数变量**；② ⛔ **绝不无条件打印「0 项不符」**——**汇总行必须由 `mism` 生成**，因为「指标与明细能否对账」正是发现假 PASS 的唯一线索；③ **读输出要读到明细**：前面有 ⛔ 行、末行却说 0，这个**不对称**就是假 PASS 的指纹。 |
| **同族与相关** | [局部搜索不能支撑否定结论](局部搜索不能支撑否定结论.md) 的实测②（同一个动作：**加断言自证「数据真的读到了」**）｜[检查有效性必须被验证](检查有效性必须被验证.md)（**一个从不失败的检查，无法证明它有效**）｜[../诚实记录/已知假PASS的经历.md](../诚实记录/已知假PASS的经历.md)（本目录既有的假 PASS 留痕：**指标与明细必须能对账**） |

## 实测例子 ⑦（2026-09-21 晚）：一个**交付了、却从未运行过**的功能，第一次运行就推翻了我的结论

> 前几条错在探针的**语义 / 输入 / 匹配方式**；这一条错得更靠前——**那个诊断工具我根本没跑过**，
> 却已经把它写进文档，并按「它应该会给我什么」写下了结论。

| 项 | 内容 |
|---|---|
| **当时我做了什么** | `--dump-rerank` 这个开关**当天早些时候就已完成，并被写进文档**：声称会写出**提示词全文、原始响应全文**、`finishReason`、`promptTokens` / `completionTokens` / `reasoningTokens`，并声明「语法非法 ⇒ 退出码 2」「写不进去 ⇒ 退出码 1，且发生在**建连之前**」。⚠️ **但在今晚之前，从没有人见过它产出的文件——我也没验证过。** |

| **⭐ 它当场推翻了我一条已写进文档的结论** | 我曾在**数据包与看板**里写：「`rerankTopN` 取 10 比取 30 **更便宜更快**（提示词更短）」。而 dump 里逐字写着「**候选（共 10 条）**」，**我传的 `rerankTopN` 是 5** ⇒ **`rerankTopN` 根本不缩小送进提示词的候选**，它只决定**保留几条 / 输出几个重排分**；**真正决定提示词规模与成本的是 `fusionTopK`**。而三臂批次里 `fusionTopK` **都是 30** ⇒ 提示词一样大、成本一样、延迟相近（≈ 25 s/题）⇒ **我那句「更省」完全站不住** ✗。 |
| **修法（已做，含本机复核）** | 全文搜那句原话：搜 `更便宜更快` ⇒ **共 3 处**，其中**一处竟然还是「活主张」**（看板「下一步」第 6 条），另两处已是留痕 ⇒ **三处一起**改成「**选 10 的唯一理由是没有可分辨的质量损失**，⛔ 不得写成『更省』」。⚠️ **写本条时本机复核**：全仓 `*.md`（含被忽略的 `backend/target/`）搜 `更便宜更快` 现存 **3 处**，**都已是更正 / 留痕的表述**，已无一处当主张 ✓；`没有可分辨的质量损失` 也已落在数据包与看板 ✓。 |
| **可复用的纪律 ①** | **「已实现」不等于「已验证」**——一个开关被写进文档、被别的会话确认「代码里有」，**都不算跑过**；**没产物就没证据**，且**未跑过的功能最可能藏着我自己的错误结论**（本例正是它第一次运行就推翻了结论）。 |
| **可复用的纪律 ②** | **改一处错话，必须全文搜那句原话**——同一句错话常被写在多处（本例写了两处，我第一轮只改了一处，另一处仍是活主张 ✗）。 |
| **可复用的纪律 ③** | **量纲要问清再写**：写「更便宜 / 更快」之前，先问**到底是哪个旋钮在决定这个量**（本例：不是 `rerankTopN`，是 `fusionTopK`）——**没确认旋钮就先别写取舍结论**。 |
