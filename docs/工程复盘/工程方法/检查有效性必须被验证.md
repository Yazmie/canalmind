# 检查有效性必须被验证（"注入错误"测试）

> 类别：[工程方法](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **做法** | 每新增一条校验（如"钢材必须属金属"、[运河节点港名单一致](../数据一致性/运河节点港名单耦合.md)、[费率表列头统一](../数据一致性/费率表列头统一.md)），就**故意把违规内容写回文件**，确认脚本真的会报错、退出码变 1，**然后恢复**，再跑一次确认回到 PASS。 |
| **为什么必须做** | 校验规则写错的典型形态不是"不该报却报了"，而是"**该报却不报**"——正则没匹配上、字段名写错、循环根本没进。**这种情况脚本依然打印 PASS，看不出任何异常。** |
| **实测例子** | ①把 `25-术语与定义.md` 的「钢材」放回 `建材` 行 → 校验报错、退出码 1；恢复后 PASS。②把 `01` 的「钦州港」错标为"否" → 报 `种子数据 is_canal_node=True（应为 是）`，退出码 1；恢复后 PASS。 |
| **业务含义** | 这就是**变异测试（mutation testing）的思路**：**一个从不失败的检查，无法证明它有效。** 只有让它失败过，才知道它真的在守门。 |
| **可能被追问** | "生产上会不会太耗时？"→ 答：这是**写检查时做一次**的开发期动作（通常几秒），不是每次 CI 都跑。收益是"这条规则真的有效"有了证据。 |
| **实测例子（2026-09-23，前端自检 12 个变异体）** | 交付 `frontend/index.html` 后我写了 `frontend/test/check_frontend.js` + `check_geometry.js`，并按本条纪律对它们做注入错误测试：**12 个变异体全部被抓**——共用 `sessionId`、强调标记失效、样式里加 `animation`、`structured` 帧被误反转义、单价改错、规则码档位改错、"计算过程"文字改错、档位区间改错、金额元素去强调、无数据卡片改文案、船期编造、能力边界不显示。 |
| **⚠️ 但第一轮有 1 个逃逸，而它抓出的是"我自己的假检查"** | 把页面里的单价 `3.30` 改成 `3.35`（金额本该从 `10560.00` 变 `10720.00`）⇒ **检查照样全绿、退出码 0**。原因：那条"算术自洽"断言写成了 `(3200 * 3.30).toFixed(2) === "10560.00"` —— **两个数都是脚本里写死的常量，根本没读页面**，它证明的是"我会算乘法"，⛔ 不是"页面算对了"。⇒ 已改为**从页面自己声明的帧数据取值再算**（读 `frameQuoteFee().tool` 的 `计费吨位` × `单价` 与 `金额(元)` 比对，并交叉校验规则码档位、facts 里的档位区间、"计算过程"文字），改后同一条变异体**当场变红**（`算得 10720.00，页面写 10560.00`）。 |
| **⭐ 由此得到的判据（比"注入错误"更狠的一条）** | **注入错误测试不只验证"检查会拦"，它还能抓出"检查是假的"。** 假检查的典型特征是：**断言的输入不来自被测物**（拿自己的常量、缓存值、上一轮产物自证）。⇒ 写每条断言时自问一句：**这个期望值是从被测物里读出来的，还是我写死的？** 若两边都能自证，它就永远是绿的。 |
| **顺手记一条边界：变异体"没生效"也必须被发现** | 我第一次的 `m9`（去掉金额强调）因**替换锚点没匹配上**而"变异未生效"——脚本若不查这一步，就会把**什么都没改**当成"检查通过了这条变异"。⇒ 变异测试脚本必须**断言"源文件真的被改动了"**（本轮实现：`if ($t -eq $src) { 记为逃逸 }`）。 |
