# 举证标准与四例的共同结构

> 类别：[工程方法](../../README.md) ｜ 子主题索引：[README.md](README.md) ｜ 上级主题：[局部搜索不能支撑否定结论](../README.md) ｜ 返回总索引：[../../../README.md](../../../README.md)
> 来源：原条目《否定结论的举证标准与检查清单》总表里的「一句话 / 四例的共同结构 / 纪律 / 相关」四行（原文第 12–14、16 行，逐字搬移）。

| 项 | 内容 |
|---|---|
| **一句话** | **否定结论（「没有 / 不存在 / 未修 / 0 处差异」）比肯定结论需要更强的举证**：肯定结论**有一个正例就成立**，否定结论则要求**搜索范围本身可辩护**。而最容易出事的一步是：把否定结论**当成事实**去**编辑别人的正确内容**。 |
| **四例的共同结构** | 四例都是「**工具给了一个看起来正常的输出**」（命中 / 0 差异 / 无结果 / 一个干净的「无」），而**我把它当成了事实**。与此前两条主线的区别在于：那两条错在**工具本身**（探针语义、跨语言正则），这四例错在**我给工具划的搜索范围、我对输出的读法、以及我允许工具隐瞒自己的失败**——**范围错了不报错，字段名错了不报错，查询被拒绝也不报错**。 |
| **纪律** | ① **否定结论先当「待确认」**，⛔ 不据此做编辑类动作；② 结论里必须**写清搜索范围**（哪些目录、含不含被忽略/构建目录、用什么工具）；③ **让搜索与脚本自证「我真的扫到了 / 读到了」**——打印文件数、命中数、题数，让**空结果看起来就是可疑的**；④ 换一个**独立 oracle** 再否一次，不靠同一工具的第二次搜索；⑤ ⛔ **用来支撑结论的查询不得吞异常**（`-ErrorAction SilentlyContinue` 一类写法会把**失败**与**没有**渲染成同一个输出），至少让失败**可见**；⑥ 见到「空 / 无 / 0」，**先区分三种成因**（真的没有 / 范围不全 / 查询失败被静默），再决定它能不能当结论。 |
