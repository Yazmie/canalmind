## 否定结论的检查清单

1. **先说范围，再说结论**：把「搜了哪些目录 / 含不含被忽略与构建目录 / **用的哪个 cmdlet 与哪个参数**」写进结论本身。
   引用命令时**把 cmdlet 与参数当成一个整体去核**（⛔ 别只核「我加了某个开关」——`-Force` 属于 `Get-ChildItem`，不属于 `Select-String`）。
2. **先问「这是哪一种空」**：① 真的没有 ② 范围不全 ③ 查询失败被静默——**三者在屏幕上长得一样**，
   只有第①种能支撑否定结论。
3. ⛔ **结论性查询不得吞异常**：`-ErrorAction SilentlyContinue` 这类写法会把**失败**渲染成**没有**
   （实测：`Get-CimInstance Win32_Process` 被拒绝访问时输出「（无 java 进程）」）；
   至少 `-ErrorAction Stop` + `try/catch` 把失败打印出来。
4. **证明范围非空**：打印**文件数 / 命中数 / 题数**——让**空结果看起来就是可疑的**，而不是「干净」。
5. **脚本要自证读到了数据**：读取后先断言规模（本项目用 `assert 命中题数 > 30`），再输出结论；⛔ 不靠「没报错」。
6. **换独立 oracle 再否一次**：源码类结论用**行为**证（真机产物 + 会变红的回归测试）；数据类结论用**另一份独立产物**重算；
   进程/环境类结论换一条**不同实现**的命令（本例 `Get-Process` vs `Get-CimInstance`）。
7. **⛔ 不基于否定结论做编辑类动作**：把「我没搜到」当成**待确认**，先问一句、先扩大范围，再动文档——
   **编辑是不可逆的，而多说一句话的成本接近零。**
8. **当锚点前先看文件在不在库里**：被 `.gitignore` 排除、或会被 `mvn clean` / 构建清空的文件，只能作**本机证据**，⛔ 不能当长期依据。
