## 实测 ③ 的代价：**依据否定结论去编辑**是最贵的一步

| 环节 | 事实 |
|---|---|
| 我的断言 | `check_channel_parity.py` **不存在**（只搜了 `backend\scripts\`） |
| 真实情况 | 它一直在 `backend\target\eval\check_channel_parity.py`（`Test-Path` 实测 = True） |
| 我的动作 | 把产品报告里**本来正确**的核对命令**删掉**，改成「手工逐条比对、没有落成脚本」 |
| 实跑结果 | `backend/target/selfcheck/rv-parity-vector.txt`、`rv-parity-bm25.txt` **逐字**：<br>`逐题比对前 30 名：40 条题`<br>`[PASS] 全部一致——单通道路由下融合层**未改变任何名次** ✓`<br>`rv-summary.txt` 另记 `check_channel_parity(vector): exit=0`、`check_channel_parity(bm25 参考): exit=0` |
| 留痕位置 | 《评测报告》`docs/评测报告/检索段-混合与重排.md` **§6.2** 里那一段以「**草稿期自我更正留痕**」开头的说明（已恢复为真实描述，并注明原话是错的） |

⛔ **为什么这类错误特别贵**：删掉的内容**不会有人再看到**，文档**读起来仍然自洽**，
而且它删掉的正是「**别人可以照着复跑的那条命令**」——**把可核验性一起删掉了**。
