## 实测 ② 的根因：字段名错了，脚本会安静地给出一份「像结论的输出」

- 度量产物里与「每题首个 gold 的名次」最接近的键是**顶层直方图** `rankOfFirstGoldHistogram`
  （实测 `backend/target/eval/item5/metrics-v2-rrf.json` 里为
  `{'1': 22, '12': 1, '2': 9, '3': 3, '4': 3, '6': 1, '8': 1}`），
  **并没有**逐题的 `rankOfFirstGold`；该文件的 `results` 只有 5 个聚合块
  （`all` / `byQuestionType` / `bySplit` / `byTopicClass` / `exclKnownLimitation`）加 1 个说明字符串 `exclFlaggedNote`。
- 于是「按逐题键读」**每题都取到 `None`**，而 `None == None` 会被算成「**不变**」——
  40 题全部落进同一格，输出「变好 0 / 变差 0 / 不变 40」。**这不是崩溃，是一份格式完好、数字自洽的假结论。**
- **修法（可复用）**：读完数据先**自证**——`assert 命中题数 > 30`。
  修后实测 **39/40（向量）、40/40（RRF）**，真实结果 **变好 8 / 变差 8 / 不变 24**。

> 本条写作时按同一口径**独立重算**以确认这组数字（口径写全，便于别人复算）：
> 数据源 `docs/评测报告/golden-l2-v2.json` 的每题 `goldChunkIds`，
> 对比产物 `backend/target/eval/item5/v2-vec.json` 与 `v2-rrf.json`；
> 「名次」＝ `hits` 中**第一条 `chunkId` 属于 gold 的记录的 `rank`**（前 30 名内找不到即记为未命中）；
> 比较两路名次，小者为「变好」。按此复算得 **39/40、40/40、变好 8 / 变差 8 / 不变 24**，与上表一致 ✓。
