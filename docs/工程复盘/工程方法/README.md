# 工程方法

> **本类收录**：**"我怎么确认自己做对了"**这一类问题——自我验证、结论举证、
> 信息放置位置、追加型内容的编辑纪律。体现的是**做事可靠度**，比技术点更难在面试里讲好。

## 本类共同教训

**对"自己产出的结论"保持怀疑，是可靠性的一部分。**

- 检查结果（PASS）不是无需验证的前提——**校验器本身也是代码，也会有 bug**。
- "我没找到"是检索行为，"它不存在"是事实断言——**后者需要举证**。
- 信息写在哪个文件，决定了它**会不会被需要它的人看到**。
- **合法 ≠ 正确**：转义写错、"替换没匹配上"、"分割切不开"，都能编译、能跑、能绿。
  这类错误只能靠**对照实验 + 十六进制/码点级断言**抓出来，读源码是抓不到的。
- ⚠️ **"产物齐全"不等于"结构正确"**：观测埋点里 Span 父指针**只在 `openScope()` 之后才存在**，
  于是手工 `start()`/`stop()` 得到的是一棵**父全为 null 的平树**——Span 一条不少、名字全对、
  **不报错**，只是调用链的边全断。⇒ 凡"能被看见的产物"，都要另断言**它们之间的关系**
  （父子边、引用完整性、覆盖关系），**不能只数"有没有"**。
  见 [观测埋点的父指针会静默丢失](观测埋点的父指针会静默丢失.md)。
- 用来诊断的工具（探针、脚本、正则）**必须先被诊断**。跨语言复核正则尤其危险。
- ⚠️ **检查的"过严"与"过松"要各防一次**：过松只是漏报，**过严会把成立的事实判成不成立**，
  而且会**诱导人去改坏本来正确的做法**（只为迎合规则）。断言要精确到"**在哪个范围内成立**"，
  豁免必须**可见且有理由**，不能悄悄放宽。
- ⚠️ **真实数据到位前，先用合成输入把整条链路空跑一遍**：它能把"**脚本错了**"与
  "**被测对象真的不行**"分成两个变量。**"能跑通"和"跑对了"是两件事**——
  合成空跑抓到的 bug 里，有一个**不报错、只是静默返回空**。
- ⚠️ **结论随测量方式变化时，先怀疑测量方式**：连续三次错法的共同点是
  **"我在改测量手段，而不是在改被测对象"**。三类新失手模式：**环境准备不全**（漏 `ANALYZE`）、
  **用代理指标替换真实条件**（伪造统计代替真造数据，而代理与被测代价模型耦合）、
  **结果解析截断**（判据恒假却"看起来稳定"）。**只有 "EXPLAIN 计划文本" 不算证据**——
  规划器类问题必须同时给出真实数据计划 + 实际耗时 + 至少一种交叉验证。
- **"可复现"包括字节可复现**：换行、编码、locale、时区这些"平台默认值"必须在产物里钉死，
  否则"这次差异"到底来自代码还是来自环境，永远说不清。
- ⚠️ **别人（或另一个 AI）的结论也只是「另一个工具的输出」**：一次只读对抗式审计给出 23 条待修订，
  我逐条核验后发现**它自己至少错了 3 处**——其中一处会把一个**正确**的 gold 改坏。
  审计是**线索不是结论**；采纳前必须用**独立手段**（直接查库读全文、自己重算）逐条复核，
  否则就是把「审计的错」当成「我的错」改进系统里，**而且不报错**。
  → [审计结论也要逐条核验](审计结论也要逐条核验.md)
- ⚠️ **在评估任何「模型能力」之前，先确认「仪器的量程」够不够**：`max_tokens` 与 `timeout` 都是**量程**——
  量程不足时失败会被记成「能力不足」，而**产物只会说「降级了」**。本项目实测：重排侧额度 4096 在
  30 条候选档下 **3/3 必然降级**（`finish_reason=LENGTH`、`completion` **恒等于** 4096，推理 token 与正文共享预算），
  而 30 s 的超时线**正好压在实测均值 29.4 s 上**（最小 21.6 / 最大 43.5 s；有一次**成功**的调用耗时 **29.875 s**，
  离上限只差 0.1 秒）。⇒ **量程类失败与能力类失败必须能在产物里分开**
  （`finish_reason` / token 用量 / **失败档位 `degradeKind`** / 生效的 `maxTokens`·`timeout` 都要进产物或 banner），
  **默认值也是结论的一部分**。
  → [量程不足会把配置掐死记成能力不足](量程不足会把配置掐死记成能力不足/README.md)
- ⚠️ **否定结论（「没有 / 不存在 / 未修 / 0 处差异」）比肯定结论需要更强的举证**：肯定结论一个正例就成立，
  而否定结论要求**搜索范围本身可辩护**。本项目**同一会话内连着错了四次**：
  ① **字面量搜索**把**已修**的缺陷误报成「未修」（修法是**加 `rerankEnabled` 守卫**，字面量其实还在）；
  ② 脚本按**不存在的逐题字段名**读数据（`rankOfFirstGold` 实为顶层直方图 `rankOfFirstGoldHistogram`），
  每题取到 `None` ⇒ 输出假的「变好 0 / 变差 0 / 不变 40」，**与真结论长得一模一样**；
  ③ 只搜 `backend\scripts\` 就断言核对脚本不存在，**并据此删掉了产品报告里本来正确的命令**
  （它一直在 `backend\target\eval\` 下）——**基于否定结论的编辑是最贵的一步**；
  ④ 查进程得到**「（无 java 进程）」**，而**我自己的付费批次当时正在跑**——真因是 `Get-CimInstance`
  被**拒绝访问**、又被 `-ErrorAction SilentlyContinue` **吞掉**（换 `Get-Process` 立刻看到 PID 15760）。
  ⇒ ⚠️ **「空」有三种成因，只有一种能当结论**：**① 真的没有；② 范围不全**（只搜一个目录 / 被 `.gitignore` 排除）；
  **③ 查询本身失败而被静默**——三者的输出在屏幕上**完全一样**，故见到「空 / 无 / 0」先问「**这是哪一种空**」。
  ⇒ **让搜索与脚本自证「我真的扫到了 / 读到了」**（打印文件数 / 命中数 / 题数，让空结果看起来可疑）、
  ⛔ **结论性查询不得吞异常**，并**换独立 oracle** 再否一次（源码类结论用行为产物 + 会变红的回归测试；
  进程 / 环境类结论换另一条**不同实现**的命令）。
  → [局部搜索不能支撑否定结论](局部搜索不能支撑否定结论/README.md)
- ⚠️ **"汇总句"是最容易腐烂的一类文档**：它**看起来像结论**（"六层全部在库""共 135 条"），
  却**没有任何东西会自动验证它**，而且**它会被别的文档引用、放大**——
  于是"一句话没核对"变成"**三份文档一起错**"。本项目实测：①《评测报告》§2 标题写"取自库内 `eval_record`"
  时库里只有 L1/L2 共 80 条；②补上 Judge 三层后又写成"**六层全部在库**"，而**实测只有 5 层**
  （**L4 一条都没有**），这句还被抄进 `DECISIONS.md` 三处、**含"第 4 周目标验收通过"那一条**。
  ⇒ **两条硬规定**：①凡"有几层 / 多少条 / 覆盖什么"这类话，**必须能由一条能跑的命令当场证伪**
  （本项目用 `HarnessCli --report --run-id <id>`）；②**并列数值必须带限定域**
  （"（`w4-2026-09-22-all6-artifacts-v2` run 下）135 条"，⛔ 不许只说"135 条"）——
  **一个无法被证伪的汇总句，等于一句没人验证过的话。**
  → [汇总句必须由能跑的检查守护](汇总句必须由能跑的检查守护.md)
