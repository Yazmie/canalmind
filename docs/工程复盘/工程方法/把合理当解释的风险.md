# 把"看起来合理"当解释的风险

> 类别：[工程方法](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **问题** | 看到 `03` 的「单船船宽 ≤ 16 米」时，我第一反应是"**16 米可能是安全余量**"，差点接受它。 |
| **为什么这个解释站不住** | 闸室宽 34 米、单船限宽 16 米，意味着**一半闸室宽度永远用不上**——作为"余量"大得不合逻辑（余量通常是个位数百分比）。真正的余量体现在"单船 ≤ 32.5 米"（约为闸宽的 95%，这个比例才像工程余量）。 |
| **教训** | **"能给一个解释"不等于"这个解释成立"。** 判断数值合理性时，要**算一下比例**、看它是否符合该领域的常规量级，而不是满足于"听起来有道理"。 |
| **业务含义** | 在真实项目里，这个习惯对应**领域量纲/量级校核**：费率、时限、容量这类数值，**都可以用"比例是否合理"快速筛掉一批明显错误**，不需要等到业务方指出。 |
| **可能被追问** | "怎么把这种判断变成可复用的？"→ 答：我在校验脚本里把它变成了**跨文件一致性检查**（见[数据一致性/闸室尺度跨文件互斥](../数据一致性/闸室尺度跨文件互斥.md)）——**把"我觉得不对劲"变成"机器会拦住"**，这样就不依赖每次的直觉。 |
