# 观测埋点的父指针会静默丢失：只 start() 不建立调用链

> **一句话**：Micrometer 的 Span 父指针**只在打开 scope 之后才存在**，而父指针是**子 Span 启动时**
> 从"当前观测"取的。所以**手工 `start()` / `stop()` 埋出来的是一棵"所有父都是 null"的平树**——
> ⛔ **不报错、Span 一条不少、名字全对**，只是调用链的边全断了。

## 1. 实测（2026-09-22，`ObservationRegistry.create()` + 捕获型 `ObservationHandler`）

| 变体 | 写法 | 子 Span 的父指针 |
|---|---|---|
| A | 外层只 `start()` / `stop()` | ⛔ **`null`** |
| B | 外层 `start()` + **`openScope()`** | ✅ `ai.agent.run` |
| C | 把 `registry` 自己注册成 handler 试试 | ⛔ `ClassCastException`——`SimpleObservationRegistry` **不实现** `ObservationHandler` |
| D | 先建子、后 `start()` 根 | ⛔ `null` ⇒ 父是**子启动时**取的，**不是创建时** |
| E | 三层都用 **`observe(...)`** | ✅ 孙的父 = 中间那层 |
| F | 外层 `observe(...)` + 内层手工 scope | ✅ |
| G | `observe(...)` 体内取"当前观测" | ✅ `ai.agent.run` ⇒ **`observe()` 会自动开 scope** |
| H | `observeChecked(...)` 嵌套 | ✅ |

⇒ 结论：**一律用 `observe(...)` / `observeChecked(...)`**（知识库第 448 行的示例正是这个惯用法），
⛔ **不要手工 `start()` / `stop()`**。

## 2. 为什么它属于"静默失效"这一类（这才是重点）

它满足本项目反复记录的那三个特征：**合法、编译通过、不抛异常**，只是行为悄悄错。
更麻烦的是它**看起来完全正常**——导出后 Span 一条不少、名字全对、耗时也都有，**只有父子边是断的**。
于是"检索慢导致作答慢"这类因果**永远推不出来**（所有 Span 平级），
而排查的人反而**不会怀疑埋点**（"Span 都出来了，埋点肯定没问题"）。
⇒ 与 [转义与写入层的静默损坏](转义与写入层的静默损坏.md) 同一族：
**看不见的错必须靠断言抓，不能靠观察产物。**

## 3. 怎么防（已落到代码，不靠记忆）

1. **埋点一律 `AiObservation.start(...).observe(...)`**，工具类 javadoc 写明这条与原因。
2. **用 `ObservationHandler` 断言父指针**，而不是"看导出的 Trace"：`AiObservabilityTest` 的
   `Capturing` 在 `onStart` 记下 `getParentObservation().getContextView().getName()`，断言
   第二层挂根、第三层挂第二层。⚠️ 父名只能从 **`getContextView()`** 取——`ObservationView`
   本身**没有** `getName()`（实测）。
3. **把"手工 start/stop 不嵌套"本身写成一条断言**（`bareStartDoesNotNest`）：将来 Micrometer
   若改了语义，这条会红，提醒复核全部埋点与本文。
