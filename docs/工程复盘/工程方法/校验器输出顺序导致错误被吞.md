# 校验器输出顺序缺陷：错误被计数，却不被打印

> 类别：[工程方法](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **问题** | 校验脚本 `backend/scripts/validate_corpus.py` 报「**错误 1 项**」，但翻遍输出**找不到是哪一条错**。 |
| **根因** | 我把「`错误 N 项` 汇总语句」**写在了跨文件检查和表头检查之前**。于是这些检查发现的错误**被计入总数、却永远不会被打印**。 |
| **危险性（这是重点）** | 这比"没写校验"更糟：**没写校验，我知道自己没查；写错了校验，我以为自己查过了。** 那一整段时间里，我的"PASS"结论都建立在错误的输出顺序上。 |
| **怎么发现的** | 因为我**不信任自己的 PASS**——我习惯去核对"数字和明细能否对上"。错误数是 1、明细却列不出来，这个不对称就是线索。 |
| **怎么解决的** | 把汇总语句移到**所有检查执行完之后**；并顺带把文件数检查一起前移；同时把每个检查的结论都打印出来（含 OK 的情况），保证**指标与明细可对账**。 |
| **业务含义** | 这就是"**可观测性必须自洽**"：**指标（错误数）与明细（错误列表）必须能对账**。一个只给总数、给不出明细的监控，比没有监控更危险。 |
| **可能被追问** | "你怎么保证现在不是又有别的检查空跑？"→ 答：**我对每个新增检查都做了"注入错误"测试**（见[检查有效性必须被验证](检查有效性必须被验证.md)）——故意把错误重新放进文件，确认脚本会报错、退出码变 1，再恢复。**验证"验证器本身"是一个独立步骤，不能省。** |
