## 实测 ② 的根因：字段名错了，脚本会安静地给出一份「像结论的输出」

- 度量产物里与「每题首个 gold 的名次」最接近的键是**顶层直方图** `rankOfFirstGoldHistogram`
  （实测 `backend/target/eval/item5/metrics-v2-rrf.json` 里为
  `{'1': 22, '12': 1, '2': 9, '3': 3, '4': 3, '6': 1, '8': 1}`），
  **并没有**逐题的 `rankOfFirstGold`；该文件的 `results` 只有 5 个聚合块
  （`all` / `byQuestionType` / `bySplit` / `byTopicClass` / `exclKnownLimitation`）加 1 个说明字符串 `exclFlaggedNote`。
- 于是「按逐题键读」**每题都取到 `None`**，而 `None == None` 会被算成「**不变**」——
  40 题全部落进同一格，输出「变好 0 / 变差 0 / 不变 40」。**这不是崩溃，是一份格式完好、数字自洽的假结论。**
- **修法（可复用）**：读完数据先**自证**——`assert 命中题数 > 30`。
  修后实测 **39/40（向量）、40/40（RRF）**，真实结果 **变好 8 / 变差 8 / 不变 24**。

> 本条写作时按同一口径**独立重算**以确认这组数字（口径写全，便于别人复算）：
> 数据源 `docs/评测报告/golden-l2-v2.json` 的每题 `goldChunkIds`，
> 对比产物 `backend/target/eval/item5/v2-vec.json` 与 `v2-rrf.json`；
> 「名次」＝ `hits` 中**第一条 `chunkId` 属于 gold 的记录的 `rank`**（前 30 名内找不到即记为未命中）；
> 比较两路名次，小者为「变好」。按此复算得 **39/40、40/40、变好 8 / 变差 8 / 不变 24**，与上表一致 ✓。

### ⚠️ 同一个坑的第二层：**「全仓搜索」这句话本身也可能是假的**

本条的写作过程里复现了这条：用**默认的 ripgrep 语义**搜 `16384`，命中 24 处，
**全部落在 `docs/` 与 `backend/src/` 这些非忽略路径下**；而**同样含该串的** `backend/target/eval/v2_datapack.md`
（被 `.gitignore` 排除）**根本不在结果里**。
⇒ **若你的搜索工具默认跳过 `.gitignore`，那么「我全仓搜过了」就是一句假话，而它读起来像真的。**
所以「搜索范围」必须**逐字写进结论**：搜了哪些目录、含不含被忽略与构建目录、**用的哪个 cmdlet 与哪个参数**。

**覆盖被忽略路径的正确写法（逐个 cmdlet 核过，本机实测）**：⚠️ **开关不一样，别混用**——

| 写法 | 能不能覆盖被忽略路径 | 实测 |
|---|---|---|
| `Get-ChildItem -Recurse` **`-Force`** | ✅ 它**有** `-Force`（用来列出隐藏 / 被忽略的**文件**） | `Get-ChildItem <…>\backend\target\eval -Recurse -Force -File -Filter *.md` → 列出 `v2_datapack.md` 等 **4 个**文件 |
| `Select-String -Path <具体路径> -Pattern <串>` | ✅ **直接给路径就能读到**被忽略的文件；⛔ **它没有、也不能加 `-Force`** | `Select-String -Path <…>\v2_datapack.md -Pattern 16384` → 命中 **4 行**（首行号 298）；加 `-Force` 则报 `A parameter cannot be found that matches parameter name 'Force'.` |
| Python `pathlib.Path(...).read_text(...)` | ✅ 不看 `.gitignore` | 读到 **23863 字符**、含 `16384` ✓ |

⚠️ **勘误留痕（同一个坑的第三层，不许静默改掉）**：本节初稿写的是「换成含 `-Force` 的 `Select-String` 才把它找出来」——
**这句话是假的**：`Select-String` **没有** `-Force` 参数（本机实测报
`A parameter cannot be found that matches parameter name 'Force'.`）。
真因是我把 **`Get-ChildItem -Force`** 与 **`Select-String`** **混为一谈**：`-Force` 属于前者，**不属于后者**。
⇒ 教训：**引用命令时必须把「cmdlet ＋ 参数」当成一个整体去核，⛔ 不能只核「我加了某个开关」**——
这正是「**结论的锚点必须能被别人逐字复跑**」的具体形态：**开关名对了、却挂错了命令，命令照样跑不起来。**

## 实测 ④：空结果可能是「查询被拒绝」，不是「没有」

我为确认「**是否还有并发付费长跑在抢资源**」而查进程——当时的写法（注意 `-ErrorAction SilentlyContinue`）：

```powershell
$js = Get-CimInstance Win32_Process -Filter "Name='java.exe'" -ErrorAction SilentlyContinue
if ($js) { … } else { "（无 java 进程）" }
```

输出：**「（无 java 进程）」** ⛔ —— 而**我自己**的付费批次**当时正在跑**。

去掉静默之后，同一个查询的真实结果：

```powershell
try { Get-CimInstance Win32_Process -Filter "Name='java.exe'" -ErrorAction Stop }
catch { $_.Exception.Message }
# → 拒绝访问
```

⇒ **`Get-CimInstance` 在受限环境被拒绝访问**；`-ErrorAction SilentlyContinue` 把异常**吞掉**，
于是**「查询本身失败」变成了一个看起来干净的「空结果」**，而我又把空结果读成了**否定结论** ✗。
**这两种输出长得一模一样**：代码走的是同一个 `else` 分支，读的人看到的都是那句「（无 …）」。

**换一条独立路径确认**（CIM 与 .NET 进程 API 是两套不同实现）：

```powershell
Get-Process java
# → PID 15760 启动 10:51:10，CPU ≈ 10.8 s / 工作集 ≈ 346 MB（正是我的批次）
```

> ⚠️ **两条命令给出相反的答案，而只有一条是真的**：一条说「没有」，一条说「有一个约 346 MB 的 JVM 正在跑」。
> **工具说「没有」时，先怀疑工具**——这与本目录既有的 [验证工具本身也要被验证](验证工具本身也要被验证.md)
> 是同一条：**「没有」是一个结论，不是一个观测。**

### ⚠️ 顺带一条可复用的环境事实（本机实测）

- **受限环境下 `Get-CimInstance Win32_Process` 会被拒绝访问**（异常消息就是「拒绝访问」），
  而这个失败**默认可被 `-ErrorAction SilentlyContinue` 静默成空结果**；
- 查进程请用 **`Get-Process`**（实测可用，能给出 PID / 启动时间 / CPU / 工作集）；
- 且**不要**用 `SilentlyContinue` 掩盖它的失败——要么 `-ErrorAction Stop` + `try/catch` 打印，
  要么就让错误冒出来。

### 「空结果」的三种成因（本条四例的归纳）

| 成因 | 本条目里的实例 | 怎么区分它 |
|---|---|---|
| ① **真的不存在** | ——（**只有这一种**能支撑否定结论） | 范围可辩护 + **第二条独立路径**给出同一答案 |
| ② **范围不全** | 实测③：只搜 `backend\scripts\`，漏掉 `backend\target\eval\`；同族还有「默认 ripgrep 跳过 `.gitignore` 排除的路径」 | 打印**搜索范围与扫描文件数**，并显式声明含不含被忽略 / 构建目录 |
| ③ **查询本身失败而被静默** | 实测④：`-ErrorAction SilentlyContinue` 把「拒绝访问」渲染成「（无 java 进程）」 | ⛔ **不许吞异常**；`-ErrorAction Stop` + `try/catch` 让失败可见 |

> **这三者的输出在屏幕上完全一样**——所以「空 / 无 / 0」在当结论之前必须先回答一句：
> **这是哪一种空？** 答不上来，它就只是「我没看到」。

## 否定结论的检查清单

1. **先说范围，再说结论**：把「搜了哪些目录 / 含不含被忽略与构建目录 / **用的哪个 cmdlet 与哪个参数**」写进结论本身。
   引用命令时**把 cmdlet 与参数当成一个整体去核**（⛔ 别只核「我加了某个开关」——`-Force` 属于 `Get-ChildItem`，不属于 `Select-String`）。
2. **先问「这是哪一种空」**：① 真的没有 ② 范围不全 ③ 查询失败被静默——**三者在屏幕上长得一样**，
   只有第①种能支撑否定结论。
3. ⛔ **结论性查询不得吞异常**：`-ErrorAction SilentlyContinue` 这类写法会把**失败**渲染成**没有**
   （实测：`Get-CimInstance Win32_Process` 被拒绝访问时输出「（无 java 进程）」）；
   至少 `-ErrorAction Stop` + `try/catch` 把失败打印出来。
4. **证明范围非空**：打印**文件数 / 命中数 / 题数**——让**空结果看起来就是可疑的**，而不是「干净」。
5. **脚本要自证读到了数据**：读取后先断言规模（本项目用 `assert 命中题数 > 30`），再输出结论；⛔ 不靠「没报错」。
6. **换独立 oracle 再否一次**：源码类结论用**行为**证（真机产物 + 会变红的回归测试）；数据类结论用**另一份独立产物**重算；
   进程/环境类结论换一条**不同实现**的命令（本例 `Get-Process` vs `Get-CimInstance`）。
7. **⛔ 不基于否定结论做编辑类动作**：把「我没搜到」当成**待确认**，先问一句、先扩大范围，再动文档——
   **编辑是不可逆的，而多说一句话的成本接近零。**
8. **当锚点前先看文件在不在库里**：被 `.gitignore` 排除、或会被 `mvn clean` / 构建清空的文件，只能作**本机证据**，⛔ 不能当长期依据。
