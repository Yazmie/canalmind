# 规则过严会把正确的东西判成错的

> 类别：[工程方法](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **核心** | 检查失效有**两个方向**：[检查有效性必须被验证](检查有效性必须被验证.md) 讲的是**太松 → 漏报**；本条讲**太严 → 把成立的事实判成不成立**。后者更危险：它不但产生假警报，还会**诱导人去改坏本来正确的做法**（只为迎合规则）。**在本轮 Golden Set 校验脚本里，这个形态一次咬了两次。** |
| **实测例子 ①（断言范围写错）** | "已知限制项自证"我最初写成断言「**该文号在全库任何 chunk 正文里都不出现**」。实测直接失败：`PLYH-GZ-2026-001` **全库出现 4 次**（SQL 实测分布：`02-过闸申报与调度规程` 2 处、`03-船舶尺度与吃水控制标准` 1 处、`04-重点物资优先过闸规定` 1 处），而**该文档（`01-船舶过闸管理办法`）自己的 21 个 chunk 里 0 次**——那 4 次是**别的文档在引用它**。真实声明应是「**本文档自己的 chunk 不含自己的文号**」。改法：同时输出两个口径（own-doc 计数 + 全库计数），并把这条推理写进脚本注释（`verify_golden_set.py` 中**以「⚠️ 断言必须精确」开头的那段注释**——位于分节注释 `# ---------- 8. 已知限制项自证 ----------` 之下，实现变量名 `limitation_checks`；**锚点认分节名 / 注释引文 / 变量名，不认行号**：本条原先写的「第 316–321 行、断言第 331–349 行」实测已失效，该脚本已从 ~350 行涨到 **502 行**）。**教训：断言要精确到"究竟在哪个范围内成立"，而不是"看起来越严格越好"。** |
| **实测例子 ②（规则过严误伤）** | 反照抄规则第一版只有**一条判据**：「题面与条款标题字符重合率 ≥0.9（标题 ≥6 字）即失败」。把它改成"分档"的过程中实测发现，**两类实质正确的题会被判失败**：①**术语题必须点出被定义的术语**——标题「计费单位」，问法里必然出现「计费单位」，否则无法问"X 是什么意思"；标题「重点保供物资」更是**术语本身即标题**；②**标识符无法回避**——标题「与 V1.0 的衔接」，问"上一版何时废止"必须写 V1.0；标题「与 2026 版的关系」同理。 |
| **误伤幅度（本轮复测，逐条归因）** | 用脚本自己的函数量过（都按最终三档规则、**不加豁免**）：`L2-023`「重点保供物资」与题面**连续重合 6 字**（标题 6 字）→ 被"连续 ≥5 字"那档硬判失败；`L2-022`「计费单位」（标题 4 字）与 `L2-027`「危险货物」（标题 6 字）连续片段为 0、但**字符重合率均 1.00** → 只落到"≥0.8"警告档；`L2-032`（标题 10 字）与 `L2-036`（标题 11 字）**连续重合均为 5 字** → 也被"连续 ≥5 字"那档硬判失败。**注意归因**：后两条的重合率分别只有 **0.67 / 0.78**，单看第一版的"≥0.9"**本来不会报**——是**为了抓 5 字照抄而新加的那一档**把它们打成失败。**即：没有豁免机制，会有 3 条硬失败，全是"正确的题"；而最需要豁免的恰是新加的那一档。** |
| **改法（分档 + 声明式豁免）** | 规则改三档（`verify_golden_set.py` 中**以「反照抄：题面 vs gold 条款标题」开头的那段注释**所列的三档阈值，其实现分支是 `len(title_eff) >= 8 and ratio >= 0.95` / `elif ratio >= 0.8`；**锚点不认行号**，原写的「第 256–305 行」已失效）：**硬失败①**题面与标题有**连续 ≥5 字**重合（5 字已足够构成检索捷径）；**硬失败②**标题 **≥8 字**且字符集重合率 **≥0.95**（近乎逐字照抄）；**警告③**重合率 **≥0.8**（4~6 字领域术语如「申请条件」无法回避，只警告）。另加**两类声明式豁免**：**术语豁免**（T4 定义题的标题去掉「定义 / 术语 / 口径 / 含义 / 规则」后即被定义对象时，该术语*必须*出现在题面，豁免**仅限该术语**、模板措辞不在其列）；**标识符豁免**（数据集逐条声明 `allowedTitleOverlap` + `allowedTitleOverlapReason`；当前 `docs/评测报告/golden-l2-v2.json` 共 **2 条**：`L2-032` 的 `V1.0`、`L2-036` 的 `2026 版`——**锚点认字段名不认行号**，数据集升 v2 后行号已整体位移）。⚠️ 实现上有个**次序陷阱**：术语豁免必须在**连续片段检查之前**判定（脚本中**以「⚠️ 术语豁免要在**连续片段检查之前**判定」开头的那段注释**，实现上是 `is_term_exempt` + `continue` 前置；原写的「脚本注释第 282–284 行」实测已失效——那里现在是变量声明）——否则检查先命中并 `continue`，豁免**永远得不到执行**（第一版就是这么写的，实测 `L2-023` 被误判）。⚠️ **曾经有过一处文档漂移（已于 2026-09-21 修好，留痕不删）**：脚本 docstring 当时写的是旧阈值（「标题 ≥6 且重合率 ≥0.9」），与实现（**≥8 且 ≥0.95**）已经不一致——**改了规则没有回头改 docstring**。<br>**修订（2026-09-21）**：docstring 已**按实现为准**同步（`verify_golden_set.py` **docstring「检查项」小节的第 8 项「反照抄」**及其后的 ⚠️ 阈值同步说明；**认小节名与项名，不认行号**——原写的「docstring 第 28–35 行」虽仍侥幸对得上，但同属会漂移的写法），并在 docstring 里写明「阈值曾与实现漂移……在此写明以免再漂」。**「我已同步」这句话本身也是会过期的**，所以修法不是把这句话删掉，而是**把漂移史留在原地**。 |
| **40 条实测结果（当前 v2）** | **硬失败 0、反照抄警告 8**；三类豁免各有计数：**术语豁免 3**（`L2-022`「计费单位」/ `L2-023`「重点保供物资」/ `L2-027`「危险货物」）、**标识符豁免 2**（`L2-032`「V1.0」/ `L2-036`「2026 版」）、**跨主题类 gold 豁免 1**（`L2-027`），另有 `gold 跨文档` 警告 1（`L2-027`）→ 机读产物 `warnings` 合计 **9 条**（`docs/评测报告/golden-l2-validation.json`）。⚠️ **锚点认字段名（`warnings` / `termExemptions` / `identifierExemptions` / `crossClassGoldExemptions`），不认行号**——数据集升 v2 后行号会整体位移。 |
| **⚠️ 曾经没做到的一个地方（2026-09-21 修好，留痕不删）** | 我原本要求「**所有豁免都在输出里可见**」，但**第一版只有术语豁免有打印路径**；`allowedTitleOverlap`（标识符豁免）**生效时不打印**，只在「声明的串其实没出现在题面或标题里」时打警告——所以**当时的实测输出里看不到那 2 条标识符豁免**，我是另行用脚本函数量出 `raw_seg=5`（上表「误伤幅度」）才确认它们确实在起作用。**「实测确认过」不等于「输出可见」。**<br>**修订（2026-09-21）**：**三类豁免全部逐条打印**——`verify_golden_set.py` 里术语 / 标识符 / 跨主题类 gold **各一个打印循环**（统一走 `[豁免] …`），并**写进机读产物** `docs/评测报告/golden-l2-validation.json` 的 `termExemptions` / `identifierExemptions` / `crossClassGoldExemptions` 三个字段；同一轮还修掉一个同源缺陷：`gold 跨文档` 警告原先**只打印、不进机读产物**（collector 与 printer 不一致，打印了但没落盘），现已一并收集。记录见 `docs/DECISIONS.md`「修正两处产出质量缺口」。 |
| **业务含义** | 规则过严的真实代价有两条：①正确的东西被判错 → **假警报消耗对工具的信任**（下次真报警时人会先怀疑工具）；②**题面为了过规则被改写成不像人话** → 规则从"守护质量"变成"造假指南"，指标反而更不可信。**豁免必须可见且有理由，不能悄悄放宽。** |
| **可能被追问** | "0.8 / 0.95 / 5 字这些阈值怎么来的？"→ 诚实答：**不是从原理推出来的，是按误伤实测在 40 条上校准的**；语料规模或领域变化后必须复核，不能当成通用常数。"为什么不用 LLM 判是否照抄？"→ 该层刻意用**纯规则口径**（决策 C-28）：可复现、无模型漂移、可逐条解释。 |
| **⚠️ 锚点：这个脚本还在长大，行号必漂（实测证据）** | 本条原先引的四处行号（`verify_golden_set.py` 的「第 316–321 行」「第 331–349 行」「第 256–305 行」「脚本注释第 282–284 行」）**今天已全部对不上**——**该脚本已从约 350 行涨到 502 行**，而它只会继续变长：**行号锚点的失效不是「可能」，是「必然」**。现行定位方式＝**三重锚定**（分节名 / 注释引文 / 变量名，见上表两处括号里的写法）：分节注释 `# ---------- 8. 已知限制项自证 ----------`、变量 `limitation_checks`、实现分支 `len(title_eff) >= 8 and ratio >= 0.95` / `elif ratio >= 0.8`，以及注释引文「反照抄：题面 vs gold 条款标题」「⚠️ 术语豁免要在」。<br>**同族证据**：[把标注错误写成了系统的已知限制](../诚实记录/把标注错误写成了系统的已知限制.md) 引的 `golden-l2-validation.json` 行号，在数据集升 v2 **重新生成**后同样失效。**「脚本会长大、产物会重生成」就是行号锚点必然漂移的两个来源**——这也是本目录 [../README.md](../README.md) 全局约定 4 的「锚点偏好」所依据的实测。 |
