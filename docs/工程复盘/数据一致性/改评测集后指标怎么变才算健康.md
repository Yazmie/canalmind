# 改评测集之后，指标**怎么变**才算健康

> 类别：[数据一致性](README.md) ｜ 返回总索引：[../README.md](../README.md)
>
> **一句话**：本轮改了 Golden Set L2 的 **23 处标注**、数据集升 v2 之后，**严格族必须逐指标看、升降都要报**：
> `HitRate@k` 四个 k **一字未变**、`Precision@k` 四个 k **反而略升**、`Precision@m` 与 `MRR@30` **略降**——
> **三处去向全部逐题归因，没有一处来自检索能力变化**，这才是「没有事后挑数据」的可核对证据；
> ⛔ 两次危险信号：**改完普遍变好**，以及**变好了却说不清为什么**（只报降不报升就是选择性汇报）。

### 严格族逐指标对照（锚点：两份基线的 `results.all`）

| 指标 | v1 → v2 | 差值 | 归因 |
|---|---|---|---|
| `HitRate@5/@10/@20/@30` | 0.925 / 0.950 / 0.975 / 0.975 → 同 | **0** | — |
| `Precision@5` | 0.185 → **0.190** | **+0.005 = 0.2/40** | `L2-027` 变 m=2（`1/k → 2/k`） |
| `Precision@10` | 0.095 → **0.0975** | **+0.0025 = 0.1/40** | 同上 |
| `Precision@20` | 0.04875 → **0.05** | **+0.00125 = 0.05/40** | 同上 |
| `Precision@30` | 0.0325 → **0.033333** | **+0.000833 = (1/30)/40** | 同上 |
| `Precision@m` | 0.675 → **0.6625** | **−0.0125 = −0.5/40** | `L2-027` 变 m=2（R-Precision 只命中一块 → 1/2） |
| `MRR@30` | 0.778571 → **0.776488** | **−0.002083 = −(1/3 − 1/4)/40** | `L2-014` rank 3 → 4（题面被修订） |

<sub>来源：`docs/评测报告/retrieval-baseline-l2-v1.json` 与 `docs/评测报告/retrieval-baseline-l2.json` 的 `results.all`；同一对照也写在《评测报告》§4.1 的「v1 ↔ v2 对照」小节。</sub>

| 项 | 内容 |
|---|---|
| **背景** | 对抗式复核查出 23 处待修订，用户选定**全套修订包**（决策 **C-29** / D18）：P0 改 gold 2 条 + 收窄题面 1 条；P1 **采纳 13 题 / 14 块**等价块（另一题 `L2-034` 的 2 块随 P0 登记 → 数据集内合计 **14 题 / 16 块**）、**否决 2 题 5 块**；P2 修 5 处。数据集由 v1 升为 **v2**（`docs/评测报告/golden-l2-v2.json`，v1 原样保留供对照）。 |
| **严格族实测对比（逐指标含差值）** | **见上方七行表**。⚠️ **这七行必须整表一起看**——同一批修订既让 `Precision@k` 略**升**、又让 `Precision@m`/`MRR` 略**降**；**只报 `HitRate@k`「一字未变」就是选择性汇报**，因为它掩盖了其余四行的去向。 |
| **上表每一行的归因（我自己逐题算过，不是猜）** | 用两份命中产物（`backend/target/eval/vector-l2-hits.json` 与 `vector-l2-v2-hits.json`）逐题对齐后：<br>· `Precision@m` 的降幅**恰好**是 `-0.5 / 40`——来自 `L2-027` 由 **m=1 变 m=2**，而它的两块 gold 在 v2 里分别排 **rank 1** 与 **rank 3**，`\|R_2 ∩ G\| = 1` → 该题得 **0.5**；<br>· `MRR@30` 的降幅**恰好**是 `1/3 − 1/4 = 0.083333`——来自 `L2-014` 的首个 gold 名次由 **3 掉到 4**，而这道题的**题面被修订过**（改为「走普通的投诉升级处理，多久必须办结？」）→ **测量输入变了，不是检索变差了**；<br>· `Precision@k` 的上升**完全**来自 `L2-027` 的 m=2：该题贡献由 `1/k` 变成 `2/k`（两块 gold 都在 top-5 内），四项差值依次为 **+0.005 / +0.0025 / +0.00125 / +0.000833**（见上表），**与「检索变好」无关**。 |
| **为什么「变好」是危险信号** | 评测集**不是训练集**：改 gold 的目的是让 gold **答得出题**（硬错），**不是为了让分数好看**。如果一次「修硬错」之后指标普遍上扬，最可能的解释是**我在事后挑选对自己有利的标注**——那正是知识库《AI 应用评测体系》第 88 行「保留集/评测集不参与调参」要防的事。**健康的修订长相是**：硬错修掉后，**严格族每一项变化（升的也要报）都能逐题归因**——归到标注口径改了、题面改了、还是检索真变了，**不能只用一句「略有提升」或「整体没变好」**。 |
| **真正的增益要靠新增口径说，而不是靠抬高旧口径** | v2 新增三族指标（**既有定义一字未改**，写在数据集 `design.metricNote` 与指标脚本里）：<br>· `answerableRate@5/@10/@20/@30` = **0.975 / 1.000 / 1.000 / 1.000**，而严格口径 @30 = **0.975** → **差值就是「跨文档复述」造成的低估幅度**；<br>· `answerableTop1` = **0.700** vs 严格 Top-1 **0.6625**；<br>· `siblingExemptPrecision@5` = **0.310** vs 严格 `Precision@5` = **0.190**（同 `doc_id` + 同 `article_no` 的兄弟块属**切分产物**，不再算假正例）<br>口径定义见 `docs/评测报告/golden-l2-v2.json` 的 `design.metricNote`。 |
| **对外表达纪律（这条是硬规定）** | **严格族（`HitRate`/`Recall`/`Precision@k`/`Precision@m`/`MRR`，只对 `goldChunkIds` 计分）读作真实可答率的【下界】，对外承诺用它；可答族（`answerableRate`/`answerableTop1`，对 gold ∪ 等价块计分）用于判断「**是否真的取到了可答内容**」。⛔ 两族必须并列报告、写明口径，不得混用，⛔ 更不得只报可答率；**严格族内部同样不得只挑一项报**（例如只报 `HitRate@k` 未变、隐去 `Precision@k` 略升）。**「严格未命中但可答率为 1」的实例**：`L2-034` 的 gold 落在 top-30 之外，而同等正确的等价块排 **rank 3**——所以那一格正确的说法是「严格口径未命中」，**不是「检索能力不足」**。三族口径的权威定义见《评测报告》§2.3（该处明写「不得混用」）。 |
| **教训** | **修评测集不等于提分。** 判断一次修订健不健康，看三件事：①硬错是否真的被修（gold 能否单独答出题）；②**严格族的每一项变化（升的也要报）是否都能逐题归因**——若普遍变好又说不清为什么，先按「事后挑数据」处理；③归因要落到**标注口径变了 / 查询文本变了 / 检索真变了**这三者之一，不能只写「略有升降」。三者缺一，指标就失去可比性。 |
| **⚠️ 未验证** | ① 可答族的分子依赖 `acceptableChunkIds` 这批**人工标注**（实测 16 块：跨文档 14 / 同文档 2），判据「单独可答」由我逐条判定，**没有第三方复核**；② 本轮只重跑了**纯向量基线**——BM25 通道与后续融合/重排的基线**尚未按 v2 重跑**，故两族的差值只在本条通道上实测过；③ 「修订题面会改变查询文本，从而改变排序指标」这一点由 `L2-014` 一例支撑，**样本只有 1 条**。 |
| **可能被追问** | 「为什么不让指标变好？」→ 见上「为什么『变好』是危险信号」；补一句：**如果某次修订后指标普遍变好，我会先怀疑自己的标注，而不是先庆祝。** |
