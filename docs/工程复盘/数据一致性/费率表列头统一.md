# 提取表格前，先统一列头

> 类别：[数据一致性](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **问题** | `docs/规则语料/07-过闸费费率表（2027版）.md` 的 7 张费率表列头写成 `费率（元/吨）`，而 `06`/`08`/`09`/`20` 一律是 `费率` + 独立的 `计费单位` 列。 |
| **为什么是问题** | 规格书第 627 行要求做「**表格结构化抽取**」。同一语料内列头不同名，抽取器要么写两套分支、要么**静默取错值**（把带单位的字段当纯数值用）。 |
| **怎么解决的** | 把 `07` 统一为 `费率` + `计费单位`；并新增校验 `check_rate_table_headers()`：按「费种 + 费率 + 吨位下限」特征识别费率表、比对列头签名，**多于一种写法即报错**。 |
| **业务含义** | **结构化抽取的输入必须先满足"结构一致"**。这类问题在解析前很容易被忽略，因为表**看起来都对**——只是列名不同。**"语义相同、写法不同"是数据管道最隐蔽的一类缺陷。** |
| **可能被追问** | "列名不同为什么不能各写一个分支？"→ 答：可以，但**分支数会随文档来源增长**（今天是 2 种，接第 3 方文档后可能变成 5 种）。把"结构"作为**入库前置条件**来约束，比在抽取器里堆分支更可控——**而且约束是有校验守护的，分支只能靠人记得加**。 |
