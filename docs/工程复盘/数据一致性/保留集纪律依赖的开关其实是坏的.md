# 保留集纪律依赖的开关，其实是坏的

## 事实

`backend/scripts/compare_runs.py` 的参数面**宣称**支持按分片出对照表：

```
--split {all, exclKnownLimitation, dev, holdout}   ← 默认 all
```

2026-09-21 第 2 周第 6 项调参时，我按纪律用它出"只看 dev"的表：

```
python backend\scripts\compare_runs.py --run ... --ks 1,3,5,10,20,30 --split dev
```

**结果：KeyError 崩溃。** 原因在取数路径写错了 —— 代码一律去取 `results[split]`，
而产物里 `results` 只有
`all / byQuestionType / bySplit / byTopicClass / exclFlaggedNote / exclKnownLimitation`，
**dev 与 holdout 在 `results["bySplit"]["dev"]`**。
即：**帮助里列出的四个选项，有两个根本取不到数。**

修复：抽出 `split_metrics(doc, split)` 把名字解析到正确的块（dev/holdout → `bySplit`），
并在缺失时**显式报错说清可选值**，不做静默回退。修后四种 split 全部实测 exit 0：

| `--split` | 退出码 | `HitRate@1`（向量 / RRF） |
|---|---|---|
| `dev` | 0 | 0.6562 / 0.5938 |
| `holdout` | 0 | 0.7500 / 0.3750 |
| `all` | 0 | 0.6750 / 0.5500 |
| `exclKnownLimitation` | 0 | 0.6923 / 0.5641 |

## 为什么这条比"普通 bug"严重

**`--split dev` 就是"保留集不参与调参"这条纪律的执行机构**（`AGENTS.md` §6 第 4 条）。
它不可用时，最小阻力的选择是照默认值看 `--split all` 的那张表——**而那张表包含 8 条保留集**。

于是纪律会这样失效：**没有人违反任何规定，大家依然认为自己在守纪律，**
只是那个"守纪律的开关"从没被按下去过。**这类失效不会留下任何痕迹。**

## 可复用的判据

1. **写进 `--help` 的选项不等于可用。** 选项面（`choices=[...]`）只证明有人写了名字，
   不证明每个名字都被端到端跑通过。**凡是"纪律靠它执行"的开关，必须逐个值实跑一遍并断言退出码**——
   本次就是四个值里两个从没跑过。
2. **⛔ 宁可崩，不可静默回退。** 若当初写成
   `except KeyError: return results["all"]`，那么每次"按 dev 看"都会**看到含保留集的数字**，
   而且**没有任何提示**。本次是崩掉——崩掉反而是好的：它当场暴露了自己不可用。
   **"看起来正常工作"是比"报错"危险得多的状态。**
3. **错误信息要给出可选值。** 修后的报错会打印 `results` 里真实存在的键，
   下一个人才不用重读源码。

## 锚点

- 代码：`backend/scripts/compare_runs.py` → `split_metrics()`（本次新增），
  `render()` 内 5 处 + `main()` 的 `--json` 写出 1 处，共 6 处取数全部改走它。
- ⚠️ **同一处 bug 实际有三个变体，是分三次才清干净的**（这段比结论更值得记）：
  1. 第一遍搜 `["results"][split]`，替换 4 处，**自查报"残留 1 处"** → 补掉；
  2. 再跑，**仍崩**：`--json` 写出路径写的是 `["results"][args.split]` —— **变量名不同，我的字面量搜索漏了它**；
  3. 于是改用**正则搜"所有下标取 results"的写法**，才把三处全看清（剩 3 处是
     `["results"][0]` 与 `["results"]["topK"]`，属合法用法）。

  **教训（比 bug 本身更重要）：自查的字面量只覆盖一种写法时，"0 处残留"是假信号。**
  报"已改完/无残留"之前，先问一句：**我搜的这个字面量，是不是这个模式的全部写法？**
  凡是"同一模式可能有多种拼写"的批量修改，**自查必须用正则或结构化的方式**，不能按记忆拼字符串。
  与 [规则过严会把正确的东西判成错的](../工程方法/规则过严会把正确的东西判成错的.md) 同源：
  **检查手段本身的覆盖范围，决定了"通过"这个结论的价值。**
