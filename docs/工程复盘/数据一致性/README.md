# 数据一致性

> **本类收录**：语料 ↔ 数据库 / 多文件之间的口径冲突、隐式数据契约、评测资产治理。
> 这是最能体现**业务理解**的一类：问题本身不难，难在**发现**它。
>

## 本类共同教训

**一致性是有"作用域"的。** 单文件校验只能发现"文件内部错"；
跨文件错误必须用跨文件规则；跨来源（文档 ↔ 数据库）错误必须做跨源比对。
设计校验体系时，先问"**这个不变量横跨多大范围**"，再决定检查放在哪一层。

**并且：连"文档之间"也有不变量，而它最容易没人守。** 同一事实写在两处
（两张同名决策表、看板与决策记录、README 与规格书勾选）时，
**任何代码检查都不会去读它** ⇒ 它只能靠**定期对账**发现。
⚠️ 对账本身还有两个陷阱：①**判据要取那一列本身**，`grep` 整行会被
"解释性引文"骗（更正说明里写到的旧值会被再报一次）；②**字面不一致 ≠ 矛盾**，
先去读正文——本次差点把 `D10 → C-38`（原裁定）与 `D10 → C-53`（收口）
这条**正确**记录"改正"成错的。
→ [两张同名表各自更新导致七处状态矛盾](两张同名表各自更新导致七处状态矛盾.md)

**而且：陈旧值最危险的形态不是"没人管"，而是"被补了一个解释"。** 沉默至少还会让人去数一遍；
一个**听起来合理**的解释会**终止怀疑**——它若是错的，还顺带误导下一个人。
更麻烦的是**同一个陈旧值会长出多个互相矛盾的解释**，因为它们各自被独立"合理化"，
**没有一处会去读另一处**（本项目实测：语料实际 26 篇，而 3 份文档都写 28，且各配了一个互相矛盾的解释）。
⇒ 判据只有一条：**这个数字被哪个机器检查守着？** 没有闸门保护的数字，一律回源头数一遍。
→ [陈旧篇数长出三个互相矛盾的解释](陈旧篇数长出三个互相矛盾的解释.md)

**并且：能被自动化验证的一方，才是权威源——⚠️ 但这条启发式在 2026-09-22 被收窄了。**
两条通道冲突时，通常以有 `CHECK` 约束、被测试守护的一方为准，反向修正描述性文档。
但决策 **C-31** 走的是**反方向**（以语料为准、改库）：权威源应当是**"规则的作者"**，
而不是**"有约束的那一方"**——约束只保证**一致性**，不保证**正确性**。
只有当冲突双方**都被设计为同一事实的权威载体**时，"有约束的一方优先"才成立。
→ [费率口径跨来源漂移](费率口径跨来源漂移.md) 的「与本类既有结论的关系」一节

**再并且：写在文档里的"必须"不是检查。** 跨来源不变量必须由**跨来源的脚本**守住；
判断标准是一句话——*如果它现在不一致，哪个脚本会红？*
→ [费率口径跨来源漂移](费率口径跨来源漂移.md)

**评测集本身也是"数据"，也要被校验。** 它的错误不报错，只表现为"**指标好看但与事实不符**"——
**分布失衡尤其如此**（不触发任何断言，只是某一类能力从未被考到）。
→ [评测集自身的错误不会报错](评测集自身的错误不会报错.md)
（同理，"校验规则写得太严"是另一个方向的风险，见[工程方法](../工程方法/规则过严会把正确的东西判成错的.md)）

**并且：修评测集不等于提分。** 修掉「gold 答不出题」这类硬错之后，
**严格口径应当原样不变或变差，而不是变好**；每一处变化都要能**逐题归因**
（是标注口径变了、查询文本变了、还是检索真变了）。真正的增益要用**新增口径**说明。
→ [改评测集后指标怎么变才算健康](改评测集后指标怎么变才算健康.md)

**跨类指针（一条同时属两类时，主因在别类的那一条）**：

- **口径没写进产物 = 隐式数据契约**：向量通道两种等价度量的分数差 1e-7，
  而命中产物**不含度量字段**，下游无法只凭产物判断口径 → 主因在
  [检索工程/度量口径没进产物](../检索工程/度量口径没进产物.md)
- **豁免生效却静默不打印**：校验脚本的豁免必须逐条可见并落进机读产物，
  否则「没报错」分不清是「确实没重合」还是「被豁免掉了」 → 主因在
  [工程方法/规则过严会把正确的东西判成错的](../工程方法/规则过严会把正确的东西判成错的.md)
- **审计结论必须逐条核验**：23 条待修订里审计自己错了至少 3 处，
  整批照搬会把**正确**的 gold 改坏（评测资产被污染且不报错） → 主因在
  [工程方法/审计结论也要逐条核验](../工程方法/审计结论也要逐条核验.md)
