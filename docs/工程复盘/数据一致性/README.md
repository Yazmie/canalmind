> 这是最能体现**业务理解**的一类：问题本身不难，难在**发现**它。

## 本类共同教训

**一致性是有"作用域"的。** 单文件校验只能发现"文件内部错"；
跨文件错误必须用跨文件规则；跨来源（文档 ↔ 数据库）错误必须做跨源比对。
设计校验体系时，先问"**这个不变量横跨多大范围**"，再决定检查放在哪一层。

**并且：能被自动化验证的一方，才是权威源。** 两条通道冲突时，
以有 `CHECK` 约束、被测试守护的一方为准，反向修正描述性文档。

**评测集本身也是"数据"，也要被校验。** 它的错误不报错，只表现为"**指标好看但与事实不符**"——
**分布失衡尤其如此**（不触发任何断言，只是某一类能力从未被考到）。
→ [评测集自身的错误不会报错](评测集自身的错误不会报错.md)
（同理，"校验规则写得太严"是另一个方向的风险，见[工程方法](../工程方法/规则过严会把正确的东西判成错的.md)）

**并且：修评测集不等于提分。** 修掉「gold 答不出题」这类硬错之后，
**严格口径应当原样不变或变差，而不是变好**；每一处变化都要能**逐题归因**
（是标注口径变了、查询文本变了、还是检索真变了）。真正的增益要用**新增口径**说明。
→ [改评测集后指标怎么变才算健康](改评测集后指标怎么变才算健康.md)

**跨类指针（一条同时属两类时，主因在别类的那一条）**：

- **口径没写进产物 = 隐式数据契约**：向量通道两种等价度量的分数差 1e-7，
  而命中产物**不含度量字段**，下游无法只凭产物判断口径 → 主因在
  [检索工程/度量口径没进产物](../检索工程/度量口径没进产物.md)
- **豁免生效却静默不打印**：校验脚本的豁免必须逐条可见并落进机读产物，
  否则「没报错」分不清是「确实没重合」还是「被豁免掉了」 → 主因在
  [工程方法/规则过严会把正确的东西判成错的](../工程方法/规则过严会把正确的东西判成错的.md)
- **审计结论必须逐条核验**：23 条待修订里审计自己错了至少 3 处，
  整批照搬会把**正确**的 gold 改坏（评测资产被污染且不报错） → 主因在
  [工程方法/审计结论也要逐条核验](../工程方法/审计结论也要逐条核验.md)
