# 分片开关宣称支持却取不到数

> 主题：[保留集纪律依赖的开关，其实是坏的](README.md) ｜ 分类：[数据一致性](../README.md)
> 来源：原条目「事实」一节（逐字搬移）。

## 事实

`backend/scripts/compare_runs.py` 的参数面**宣称**支持按分片出对照表：

```
--split {all, exclKnownLimitation, dev, holdout}   ← 默认 all
```

2026-09-21 第 2 周第 6 项调参时，我按纪律用它出"只看 dev"的表：

```
python backend\scripts\compare_runs.py --run ... --ks 1,3,5,10,20,30 --split dev
```

**结果：KeyError 崩溃。** 原因在取数路径写错了 —— 代码一律去取 `results[split]`，
而产物里 `results` 只有
`all / byQuestionType / bySplit / byTopicClass / exclFlaggedNote / exclKnownLimitation`，
**dev 与 holdout 在 `results["bySplit"]["dev"]`**。
即：**帮助里列出的四个选项，有两个根本取不到数。**

修复：抽出 `split_metrics(doc, split)` 把名字解析到正确的块（dev/holdout → `bySplit`），
并在缺失时**显式报错说清可选值**，不做静默回退。修后四种 split 全部实测 exit 0：

| `--split` | 退出码 | `HitRate@1`（向量 / RRF） |
|---|---|---|
| `dev` | 0 | 0.6562 / 0.5938 |
| `holdout` | 0 | 0.7500 / 0.3750 |
| `all` | 0 | 0.6750 / 0.5500 |
| `exclKnownLimitation` | 0 | 0.6923 / 0.5641 |
