# 保留集纪律依赖的开关，其实是坏的

> 主题索引 ｜ 分类：[数据一致性](../README.md) ｜ 总索引：[../../README.md](../../README.md)

`--split dev` 就是「保留集不参与调参」这条纪律的执行机构（`AGENTS.md` §6 第 4 条），
而它宣称支持的四个取值里**有两个根本取不到数**——纪律因此可以在**没有任何人违规**的情况下静默失效。
本主题收录现场事实、这类失效为何比普通 bug 严重、可复用的判据，以及代码锚点与变体经过。

| 条目 | 一句话说明 |
|---|---|
| [分片开关宣称支持却取不到数](分片开关宣称支持却取不到数.md) | 事实：`--split dev` 实测 `KeyError` 崩溃、真因在取数路径；修后四种 split 全部 `exit 0`，附 `HitRate@1` 对照表 |
| [纪律为什么会在无人违规时失效](纪律为什么会在无人违规时失效.md) | 为什么这比「普通 bug」严重：最小阻力是照默认值看含 8 条保留集的 `all` 表，且**这类失效不会留下任何痕迹** |
| [写进帮助的选项不等于可用](写进帮助的选项不等于可用.md) | 三条可复用判据：选项面只证明有人写了名字；⛔ 宁可崩不可静默回退；错误信息要给出可选值 |
| [锚点与三种写法变体](锚点与三种写法变体.md) | 代码锚点（`split_metrics()` 与 6 处取数）＋ 同一处 bug 分三次才清干净的经过与「自查字面量只覆盖一种写法」的教训 |
