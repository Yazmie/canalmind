# 34 米宽的闸室，为什么能通过 16 米宽的船？

> 类别：[数据一致性](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **问题** | `docs/规则语料/03-船舶尺度与吃水控制标准.md` 声明单船**总长 ≤ 135.0 米、船宽 ≤ 16.0 米**；而 `12`/`14`/`18`/`25` 四篇一致声明闸室**长 300 米、宽 34 米**。 |
| **为什么是真矛盾** | 闸室宽 34 米却限制船宽 16 米，意味着**闸室一半宽度永远用不上**——这不是保守，是**自相矛盾**。（顺带一提，子代理后来把它改成 280/32.5 米；而我最初也差点以为"16 米是安全余量"。） |
| **怎么发现的** | 我给语料写校验脚本时，本能地只做"单文件检查"（条号连续、表头规范…）。是**加入跨文件比对段**之后才暴露出来的。 |
| **怎么解决的** | 统一为：闸室 **300 × 34 米**，单船 **≤ 280 米 / ≤ 32.5 米**（超限上限 300 / 34 米）。并在校验脚本里加**跨文件一致性检查**：把所有"闸室长度/宽度"声明收集起来两两比对，且**穷举审计**所有疑似尺度数值（含表格分行写法）。 |
| **业务含义** | **一致性是有"作用域"的**。单文件校验只能发现"文件内部错"，跨文件矛盾必须用跨文件规则才能发现。设计校验体系时，要先问"**这个不变量横跨多大范围**"，再决定检查放在哪一层。 |
| **顺手修的一个"假警报"** | 我的初版规则把 `03` 的「本标准**不规定**固定的闸室水深刻度」判成错误——**这句话恰是否认存在固定水深，方向是对的**。规则写得太宽会把"正确的否认"当成"违规的断言"。**教训：写正则校验时，要区分"断言某值"和"否认某值"。** |
| **可能被追问** | "为什么不直接删掉冲突的那份文档？"→ 答：语料是**评测资产**，刻意保留了"已废止版本"（如 `06` vs `07` 费率表）作为**版本冲突检索难点**。所以正确做法是**修数据错误、留设计难点**——这两者必须分清（见[检索难点与缺陷的区分](检索难点与缺陷的区分.md)）。 |
