# 把"刻意设计的矛盾"和"真实缺陷"分开管理

> 类别：[数据一致性](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **问题** | 语料里我**故意**埋了检索难点：`06`（2026 版费率，已废止）vs `07`（2027 版，现行）同名费种但费率不同；`02` 与 `04` 都讲"优先放行"但**适用货类范围不同**。这些看起来"矛盾"的地方**必须保留**。 |
| **风险** | 校验脚本如果不加区分，会把这些**评测资产**当成错误报出来，于是要么被误删、要么规则被迫放宽到失去作用。 |
| **怎么解决的** | 在 `docs/规则语料/README.md` §5 明确登记"刻意埋设的检索难点"清单，并在 §6 写明**维护约定：已废止版本必须保留，不得因"过时"而删除**。 |
| **业务含义** | 这对应**测试数据治理**：**"已知且有意为之的异常"和"意外缺陷"必须显式区分并分别管理**。否则团队会在"修复"评测资产的过程中把区分度修没。 |
| **为什么`06`必须留着** | 它测的是"**能不能检索到正确版本**"，而不仅是"能不能检索到相似文档"——这是检索系统真正的难点。删掉它，评测就退化成"找相似"。 |
| **可能被追问** | "怎么保证别人不会把这些当 bug 删掉？"→ 答：**写进仓库文档**，而且要写在**复核者会去看的地方**（这点我踩过坑，见[信息要放在消费者会看的路径上](../工程方法/信息要放在消费者会看的路径上.md)）。 |
| **相关** | [闸室尺度跨文件互斥](闸室尺度跨文件互斥.md)（"修数据错误、留设计难点"的判断在那里也出现过） |
