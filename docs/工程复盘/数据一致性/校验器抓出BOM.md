# 校验器抓出我自己写的 BOM

> 类别：[数据一致性](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **问题** | 我用 PowerShell 的 `Set-Content -Encoding UTF8` 改 `07` 的列头，结果**文件被写入了 UTF-8 BOM**，而项目要求 `.md` 无 BOM。 |
| **怎么发现的** | **我自家的语料校验器当场报错**：`✗ 存在 UTF-8 BOM，建议去除`。 |
| **业务含义** | 这是**"把检查做进工具链"的回报**：同类错误如果只靠人复查，会在很多轮之后才被发现，而且往往是在别的环节（比如 diff 里突然多出一行改动）。**写检查的成本是一次性的，收益是每次操作都自动兜底。** |
| **反复踩的讽刺之处** | 同一个编码问题在两个方向上各咬了我一次：**PS 5.1 的 `UTF8` 会写 BOM**（`UTF8NoBOM` 在 5.1 不存在），而**读无 BOM 的 `.ps1` 又会按 GBK 解析**。详见[环境坑/脚本文件BOM](../环境坑/脚本文件BOM.md)。 |
| **怎么解决的** | 用 `[System.IO.File]::WriteAllText($f,$t,(New-Object System.Text.UTF8Encoding($false)))` 写无 BOM 文件；并把 BOM 检查留在校验器里，长期守护。 |
