# 展示层的业务码必须回到生成它的代码

> 类别：[数据一致性](README.md) ｜ 返回总索引：[../README.md](../README.md)

**一句话**：演示页里我把过闸费**规则码凭印象**写成了 `PLYH-FL-2026-006-第四条`，
而真实格式是**语料派生**的 `CT-过闸费-建材-2000-20260916`——**看着像，就是编的**。

## 实测（2026-09-23）

- 我以为规则码是"**文号 + 条款号**"，于是照《过闸费费率表（2026版）》的文号 `PLYH-FL-2026-006` 拼了一条。
- 回查生成它的脚本 `backend/scripts/corpus_tariff.py` **第 359–372 行** `_with_rule_codes`：
  形如 `CT-{费种}-{货类}-{档位下限}-{生效起始日}`；注释写明前缀 `CT` = Corpus Tariff
  （"表明由语料派生"），且**⛔ 不含随机数/序号**（同输入同输出、重跑可复现）。
- 两者是**同名不同物**的标识：**文号**来自语料页面（`PLYH-FL-2026-006`），
  **规则码**由脚本生成（`CT-过闸费-建材-2000-20260916`）。
  混用**不报错**、不影响渲染，只会让页面**看起来更权威**。

⚠️ 同一页顺带自查了其它值：档位 `[2000,5000)`、单价 `3.30 元/吨`、`3200 × 3.30 = 10560.00 元`
——这几项与语料逐格对得上，**只有规则码那一处是我编的**（即"不是整页不可信，是某一格不可信"，
这种**局部编造**最难发现）。

## 判据

| # | 判据 | 本次怎么用 |
|---|---|---|
| ① | **凡出现在界面上的"业务码 / 单号 / 文号 / 金额"，必须能指到生成它的函数或语料行** | 规则码 → `corpus_tariff.py:359`；费率与档位 → `docs/规则语料/06-过闸费费率表（2026版）.md` |
| ② | **先问"这个值是谁产生的"，再区分同名不同物** | 文号 ≠ 规则码 ≠ 条款号；拼之前先确认格式由谁定义 |
| ③ | **演示数据同样要能被逐格核对** | 演示模式不接后端，更要靠"源可指"担保；⛔ 不能因为"反正是 demo"就放松 |

## 代价

业务页上**编造的码**比**留空**更坏：留空看得出是缺失，
**编的看起来像已经核对过**——它与"正确的演示数据"**长得一模一样**，
唯一抓法就是"**回到生成它的代码**"。
