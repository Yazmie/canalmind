# 钢铁归类冲突：文档说"建材"，数据库说"金属"

> 类别：[数据一致性](README.md) ｜ 返回总索引：[../README.md](../README.md)

| 项 | 内容 |
|---|---|
| **问题** | 文档语料 `docs/规则语料/05-计费总则.md` 把「钢材制品」列在货类 **`建材`** 举例中；而仿真数据 `backend/scripts/generate_seed_data.py` 的 `CARGO_TYPES`（第 150–170 行）把 `JS03 钢材` 归为 **`金属`**。 |
| **怎么发现的** | 不是我看出来的——是一个**并行工作的子代理**在复核自己那 4 篇时顺带实测出来的，它把这条作为"遗留提示"报给了我。我随后用脚本反查 `CARGO_TYPES` 独立确认。 |
| **为什么危险（关键）** | 本项目有**两条并行的答题通道**：<br>· **文档检索通道**（RAG，查规则文档）<br>· **结构化查询通道**（查数据库算费用）<br>同一个问题「钢材的过闸费怎么算」，两条通道会给出**不同答案**。而且它污染的是**两个不同阶段的评测**：第 2 周的检索评测、第 3 周的 Execution Accuracy 评测。 |
| **怎么解决的** | ①**明确权威来源**：以数据库种子数据为唯一权威（因为它是可执行、可被测试守护的一方），把语料 `05`/`12`/`25` 三篇统一改为 `金属`；②在 `docs/规则语料/README.md` 新增 **§4.1「货种归类权威表」**，把 7 个货类下的全部货种逐字列出；③把这条**变成机器检查**——`validate_corpus.py` 的 `check_cargo_examples()` 直接读 `generate_seed_data.py` 的 `CARGO_TYPES` 反查。 |
| **业务含义** | 在真实系统里，这对应「**规则文档与业务系统主数据不一致**」——在航运、保险、税务这类强规则行业是**高频事故源**，且往往在客户投诉时才暴露。正确做法不是"改文档了事"，而是**指定单一权威源 + 把一致性做成可执行的校验**。 |
| **可能被追问** | "你怎么知道是文档错而不是数据库错？"→ 答：数据库的枚举有 `CHECK` 约束且被测试守护，是可执行的单一事实源；文档是描述性的。**当两者冲突，永远以能被自动化验证的一方为准**，然后反向修正描述方。 |
