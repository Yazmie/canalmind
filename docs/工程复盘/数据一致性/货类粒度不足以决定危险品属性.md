# 货类粒度不足以决定危险品属性

## 问题

第 3 周的费用测算要算"危险货物加收 30%"。用户原话常常只说到**货类**：

> 1500 吨化工品的港杂费多少？

而加收与否取决于**是否危险货物**。于是出现一个必须回答的设计问题：
**货类能不能推出危险品属性？**

起初的实现是"必须给货种（21 种）"：货种表里每个货种都带 `category` 与 `is_dangerous`，
由货种推货类 + 属性，逻辑干净。但这样一来，评测集里我自己写的题
（`quote_fee` 传 `cargo_category`）**直接被契约校验拦下**：

```
[FAIL] L1-013：quote_fee 不支持参数 ['cargo_category']
```

这个"红"其实暴露的是**能力缺口**：用户说"建材/化工品"是**自然说法**，
如果工具只接受"机制砂/烧碱"，那模型必须先替用户猜一个货种——**而它不该猜**。

## 查数据后才知道的结论

不是"能不能推"的哲学问题，而是**查库就能得到的事实**：

| 货类 | 库内 `cargo_type` 的危险品属性 | 能否由货类推导 |
|---|---|---|
| 化工 | 烧碱 / 硫酸 / 液体化工品 —— **全部** `is_dangerous = true` | ✅ 可推（true）|
| 建材 / 金属 / 农资 / 集装箱 / 其他 | 成员**全部**为 false | ✅ 可推（false）|
| **能源** | 成品油 = true，动力煤 / 焦炭 = false | ❌ **不可推** |

⇒ 规则应当是"**货类内部属性一致才可由货类推导；不一致必须追问货种**"，
而这个"一致"必须**问数据库**，不能在我脑子里写死一张"哪些类一致"的表：

```sql
SELECT count(DISTINCT is_dangerous) AS kinds, bool_and(is_dangerous) AS uniform
  FROM cargo_type WHERE category = ?;      -- kinds = 1 ⇒ 可推导；> 1 ⇒ 追问
```

**为什么必须查库**：若硬编码"化工可推、能源不可推"，那么**货种表一变**（新增一个
"液化天然气"到能源、或某类里加一个危险品），代码就会**继续用旧常识算钱**——
而且不会报错，只会算错金额。这与 C-31「语料是费率的唯一事实来源」是同一条纪律：
**权威源在数据里，不在代码里。**

## 落地的三处

1. **契约**：`quote_fee` 增加 `cargo_category`（7 类枚举），与 `cargo_name`（21 种）二选一；
   在 `notes` 里点名"能源类内部危险品属性不一致，只说'能源'时应追问货种"。
2. **服务层**：只给货类时调用 `cargoCategoryDangerous(category)`；
   返回 `null`（库内不一致）⇒ 走**追问**（`MISSING_PARAM_PREFIX + "货种"`），
   **绝不默认不加收**（默认不加收 = 少收 30%，默认加收 = 多收，两个方向都是错的钱）。
3. **金标准生成脚本**：只给货类的测算题也**查库推危险品属性**；
   查出来不一致就直接判"题面有错"并抛错——**评测集不许出现答不出的测算题**
   （这正是 `L1-006` 一度被拦下的原因：它问的是能源类的**费率**，
   而费率与危险品无关，故该检查只对 `quote` 类题生效）。

## 教训（可迁移）

1. **"术语粒度不足以确定答案"时，正确动作是追问，不是取默认值。**
   追问的代价是一次交互；默认值的代价是一笔**看起来合理的错钱**。
2. **"哪些情况能自动推导"这类判断，往往能从数据里查出来**——查了就同时得到
   "可推导的规则"和"不可推导的例证"，比拍脑袋写死一张表更可靠。
3. **校验失败先分清是"实现错"还是"能力缺"**：这次的红不是代码写错，
   而是**接口设计漏了用户的一种自然表达**。修契约比改测试更对。

## 锚点

- 契约：`backend/src/main/resources/structured/tool-contracts.json`（`quote_fee.parameters.cargo_category` 及其 `description` / `notes`）
- 推导规则：`backend/src/main/java/com/canalmind/structured/StructuredQueryService.java` 的 `quoteFee(...)`
- 查库接口：`StructuredDataLookup.cargoCategoryDangerous(String)`（含"为什么必须查库"的注释）
  与实现 `StructuredQueryRepository.cargoCategoryDangerous(...)`
- 测试：`StructuredQueryServiceTest` 的
  `categoryLevelDangerousIsDerivedFromDb`（化工 → 320×1.30 = 416.00）与
  `ambiguousCategoryAsksForCargoName`（能源 → 追问，且**不得给出金额**）
